# F2·F3 — 모의투자·질문식 매매 기능 명세

> **기능 단일 원본** · 2026-08-11 · 기준: `docs/영웅키움_기획_통합문서_v2.md` v2.6 §10
>
> F2 모의투자와 F3 질문식 기록의 화면, 데이터, 경계, 완료 기준은 이 파일에서 관리한다. 제품 목표·법무·전역 레드라인은 통합문서를 따르며, 이 기능을 바꿀 때는 이 파일을 먼저 수정하고 전역 문서에는 요약과 링크만 둔다.

## 1. 범위와 소유권

| 영역 | 소유 위치 | 책임 |
|---|---|---|
| 종목 탐색·상세·주문·보유 | `web/features/f2-trade/` | F2 화면과 거래 흐름 |
| 질문식 기록 폼 | `web/features/f3-reason/` | F2가 import하는 F3 공개 컴포넌트 |
| 시세 프록시 | `web/app/api/quote/` | 키움 시세 호출과 폴백 캐시 |
| 거래·행동 상태 | `web/shared/store/` | 거래 기록, 질문식 기록, 탐색·주문 이벤트 |
| 종목·픽스처 | `web/shared/data/` | 51종 유니버스와 재현 가능한 데모 데이터 |

- F2는 F3 폼을 복제하지 않고 공개 컴포넌트만 import한다.
- 기능 폴더는 `shared/`를 import만 한다. 공용 계약 변경은 `web/shared/AGENTS.md`를 따른다.
- 외부 시세를 클라이언트에서 직접 호출하지 않는다. `app/api/quote`만 사용한다.

## 2. 확정 전제

- 국내 우량주 **51종**만 제공한다. 목록과 섹터 기준은 `docs/모의투자_종목유니버스_데이터셋_설계.md`가 소유한다.
- 구성원은 각자 가상 **100만원**을 운용한다. 공동 지갑이 아니다.
- 설계는 시장가+지정가이지만 데모는 **시장가 즉시 체결**이다. 지정가는 안내 UI만 둘 수 있다.
- 실제 수수료·세금 수준을 안내하되 데모 계산은 픽스처 계약을 따른다.
- 동일 종목 매도 후 30분 재매수 제한은 [잠정]이며, 데모에서는 안내 문구를 우선한다.
- 질문식 기록은 주문 흐름에 내장하며 건너뛸 수 없다. 답변은 주문 허용 여부를 판정하는 시험이 아니다.

## 3. 전체 사용자 흐름

```text
종목 탐색
  → 종목 상세
  → 매수 또는 매도
  → 금액·수량 확인
  → F3 질문식 기록
  → 주문 확인
  → 시장가 즉시 체결
  → 거래·기록·행동 이벤트 저장
  → 완료 안내
```

### 3.1 종목 탐색·상세

- 검색과 업종 칩으로 51종 안에서만 탐색한다.
- 종목 상세에는 현재가, 간단 차트, 내 보유·수익률, 매수·매도 버튼을 둔다.
- 아이 눈높이 설명은 “이 회사는 무슨 일을 해?”와 “최근 무슨 일이 있었어?” 범위의 승인된 사실만 사용한다.
- 종목 상세 체류시간과 조회 종목 수를 행동 이벤트로 저장한다. 이 값은 F9 스코어링과 F10의 승인된 선제 신호에 사용될 수 있다.

### 3.2 매수 흐름

1. 금액 또는 수량을 선택한다.
2. 잔액과 예상 주문 금액을 확인한다.
3. 매수 근거를 선택한다.
4. 확신도를 4단계 탭에서 선택한다.
5. 예상 보유기간을 선택한다.
6. 주문 내용을 확인하고 체결한다.
7. 완료 화면에서 선택적으로 한 줄 메모를 남긴다.

### 3.3 매도 흐름

1. 매도 수량을 선택한다.
2. 매도 근거를 선택한다.
3. 주문 내용을 확인하고 체결한다.
4. 완료 화면에서 선택적으로 한 줄 메모를 남긴다.

매도 화면은 손익을 과장하거나 사용자의 선택을 평가하지 않는다. 수익률은 정량값 그대로 표시하고 “잘했다/못했다” 같은 문구를 쓰지 않는다.

## 4. F3 질문식 기록

### 4.1 매수 근거 — 필수, 택1

| 화면 문구 | 코드 |
|---|---|
| 뉴스에서 봤어 | `buy_news` |
| 차트가 좋아 보여 | `buy_chart` |
| 친구·가족이 추천했어 | `buy_social` |
| 이 회사나 제품을 잘 알아 | `buy_familiar` |
| 그냥 느낌이 좋아 | `buy_intuition` |

- 모든 선택지는 같은 크기와 시각적 비중으로 표시한다.
- 선택지에 정답·우열을 암시하지 않는다.

### 4.2 확신도 — 매수 시 필수, 택1

| 화면 문구 | 저장값 |
|---|---:|
| 잘 모르겠어 | 25 |
| 조금 | 50 |
| 꽤 | 75 |
| 완전 | 100 |

- 슬라이더가 아니라 **4단계 탭**을 사용한다.
- “정답은 없어!” 캡션을 항상 함께 표시한다.
- 높은 값이 좋은 점수라는 표현을 하지 않는다. F9는 확신도 크기보다 투자 행동과의 관계를 관찰한다.

### 4.3 예상 보유기간 — 매수 시 필수, 택1

| 화면 문구 | 코드 |
|---|---|
| 이번 주만 | `plan_short` |
| 시즌 끝까지 | `plan_season` |
| 모르겠어 | `plan_unknown` |

예상 보유기간은 F9 속도 축과 계획–행동 일치 분석의 입력이다. 목표가 입력은 현재 범위에 포함하지 않는다.

### 4.4 매도 근거 — 필수, 택1

| 화면 문구 | 코드 |
|---|---|
| 목표한 만큼 올랐어 | `sell_target_hit` |
| 더 떨어질까 봐 걱정돼 | `sell_fear_drop` |
| 다른 종목이 더 좋아 보여 | `sell_rebalance` |
| 그냥 불안해 | `sell_anxiety` |
| 기타 | `sell_other` |

### 4.5 한 줄 메모 — 선택

- 매수·매도 완료 화면에서만 선택적으로 입력한다.
- 최대 길이는 50자다.
- 메모가 없으면 빈 영역을 렌더링하지 않는다.

## 5. 데이터 계약

### 5.1 매수 기록

```ts
type BuyRecord = {
  orderId: string;
  userId: string;
  stockId: string;
  amountKrw: number;
  quantity: number;
  orderType: "market" | "limit";
  limitPrice: number | null;
  reasonCode:
    | "buy_news"
    | "buy_chart"
    | "buy_social"
    | "buy_familiar"
    | "buy_intuition";
  confidence: 25 | 50 | 75 | 100;
  holdingPlan: "plan_short" | "plan_season" | "plan_unknown";
  memo: string | null;
  status: "filled" | "cancelled";
  createdAt: string;
};
```

### 5.2 매도 기록

```ts
type SellRecord = {
  orderId: string;
  userId: string;
  stockId: string;
  quantity: number;
  linkedBuyOrderId: string | null;
  reasonCode:
    | "sell_target_hit"
    | "sell_fear_drop"
    | "sell_rebalance"
    | "sell_anxiety"
    | "sell_other";
  realizedPnlPct: number;
  heldDays: number;
  memo: string | null;
  createdAt: string;
};
```

### 5.3 행동 이벤트

| 이벤트 | 최소 데이터 | 사용처 |
|---|---|---|
| `stock_detail_viewed` | 사용자, 종목, 체류시간 | F9 탐색 깊이 |
| `order_confirmation_cancelled` | 사용자, 종목, 매수/매도, 시각 | F10 `switch` 신호 |
| `order_screen_dwell` | 사용자, 종목, 체류시간 | F10 `dwell` 신호 |
| `trade_filled` | 거래 기록, 실현손익 | F9 스코어링·F10 `lossRevisit` 기준 |
| `order_abandoned` | 이탈 단계 | 질문식 기록 이탈률 |

- F10은 위 이벤트 중 `switch`, `dwell`, `lossRevisit` 판정에 승인된 필드만 사용한다.
- 챗봇 대화는 F9 스코어링 입력이 아니다.
- 수집 항목은 온보딩에서 고지한다.

## 6. 엣지 케이스

- 같은 종목을 추가 매수해도 질문식 기록은 주문마다 새로 저장한다.
- 부분 매도는 체결 단위로 기록하고 가능하면 기준 매수 주문을 연결한다.
- 지정가 주문을 취소해도 작성된 질문식 기록은 `cancelled` 상태로 보존할 수 있다.
- 시즌 종료 자동 청산에는 질문식 폼을 다시 띄우지 않는다.
- 잔액 또는 부모가 정한 단일종목 한도를 초과한 주문은 주문 단계에서 차단하고 이유를 설명한다.
- 시세 API 실패·장외 시간에는 마지막 캐시 또는 픽스처를 사용한다.

## 7. 금지 사항

- 질문 답변에 따라 주문을 허용·차단하지 않는다.
- 확신도를 실력 점수·등급처럼 표시하지 않는다.
- 특정 근거 선택지를 색·크기·순서로 우대하지 않는다.
- 목표가·손절가 입력이나 수익률 전망을 새로 추가하지 않는다.
- 기능 폴더에서 공용 타입·스토어·UI 사본을 만들지 않는다.
- 클라이언트에서 키움 API를 직접 호출하거나 API 키를 노출하지 않는다.

## 8. 완료 기준

- 골든 패스 ②의 `탐색 → 상세 → 매수/매도 → F3 기록 → 체결` 흐름이 픽스처로 동작한다.
- 매수 기록에는 근거·확신도·예상 보유기간이 모두 저장되고, 매도 기록에는 매도 근거가 저장된다.
- 거래·탐색·주문 이벤트가 `shared/store` 계약으로 기록된다.
- 완료 문구는 “기록 완료! 키웅이가 기억해둘게”이며 체결 순간에만 컨페티를 사용한다.
- 관련 테스트와 `web/`의 `npm run build`가 통과한다.
