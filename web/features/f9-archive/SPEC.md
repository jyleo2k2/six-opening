# F9 — 가족 아카이브 기능 명세

> **기능 단일 원본** · 2026-08-12 16:50 · 기준: `docs/영웅키움_기획_통합문서_v2.md` v2.9 §11
>
> F9의 스코어링 입력·출력, 화면, LLM 경계, 완료 기준은 이 파일에서 관리한다. 제품 목표·법무·전역 레드라인은 통합문서를 따르며, 이 기능을 바꿀 때는 이 파일을 먼저 수정하고 전역 문서에는 요약과 링크만 둔다.

## 1. 목적과 범위

> ⚠ **2026-08-12 체계 교체.** 기존 **성향 5축 + 친화도 스코어**는 폐기했다. 5축 게이지·친화도 ML·유형 라벨 매트릭스(8~12종) 관련 결정은 모두 무효다.

F9는 가족의 기록을 두 축으로 보여 준다.

- **① 거래 데이터**: 종목별 차트 위에 부모와 자녀의 매수·매도 지점을 함께 표시한다. 점을 누르면 그때 입력한 거래이유가 그대로 뜬다. 구현은 F11이 소유한다.
- **② 투자성향 분석**: 판단 근거와 포트폴리오 폭 2축으로 **4가지 투자성향 유형**을 분류한다. 우열이 없는 스타일이다.
- **③ 거래내역 피드**: 부모·자녀 거래가 한 줄로 흐르고 서로 코멘트를 남긴다. 구현은 F11이 소유한다.
- **수익률 리포트**: 정량값을 그대로 표시하며 LLM이 해석하거나 전망하지 않는다.
- **가족 비교**: 양측 동의를 전제로 서로 다른 유형을 중립적으로 비교한다.

## 2. 소유권과 의존 관계

| 영역 | 소유 위치 | 책임 |
|---|---|---|
| 아카이브 UI·F9 프롬프트 | `web/features/f9-archive/` | 리포트·가족 비교·시즌 기록 |
| 스코어링 엔진 | `web/shared/engine/` | 2축 수치·4유형 계산 |
| 가족 매매 차트 | `web/features/f11-feed/SPEC.md` | 차트 마커·거래이유 연결 |
| 거래·행동 원본 | `web/shared/store/` | F2·F3 기록과 포트폴리오 스냅샷 |
| LLM 클라이언트·필터 | `web/shared/llm/` | Luna 호출과 공통 출력 필터 |
| 시드·픽스처 | `web/shared/data/` | 2주치 누적 행동과 3주차 데모 상태 |

- F9는 `shared/engine`이 만든 JSON을 읽고 표시한다. 기능 폴더에서 스코어를 다시 계산하지 않는다.
- 공용 계약 변경은 `web/shared/AGENTS.md`를 따른다.
- F10 챗봇 대화와 선제 발화 로그는 유형 산출에 넣지 않는다.
- **산출된 유형은 F10의 개입 방식을 결정하는 입력값으로 전달된다** (통합문서 §12 B-1).

## 3. 입력 데이터

### 3.1 허용 입력

- F2 거래 로그: 종목, 수량, 시각, 보유기간, 실현손익
- F2 탐색 이벤트: 상세 체류시간, 조회 종목·업종 수
- F2 포트폴리오 스냅샷: 종목·업종 비중, 현금, 평가손익
- F3 질문식 기록: 매수·매도 근거, 확신도, 예상 보유기간

### 3.2 금지 입력

- F10 대화 원문과 질문 횟수
- 가족 구성원의 비동의 원문 기록
- 모델이 추정하거나 생성한 수치
- 외부에서 임의로 보강한 투자 평가·주가 전망

## 4. 행동 데이터 2축과 4유형

두 축을 산출한 뒤 사분면으로 유형을 정한다. 축 값의 높고 낮음은 **실력이나 등급이 아니다.**

> 두 축 모두 **주관적 설문이 아니라 실제 기록에서 기계적으로 산출**한다. 아이에게 성향 검사를 시키지 않는다.

| 축 | 측정 대상 | 판정 기준 |
|---|---|---|
| **판단 근거** (가로) | 매수 전 **뉴스 · 기업정보 · 차트** 3개 탭의 열람 수 | 0~1개 = **직관형** / 2개 이상 = **근거형** |
| **포트폴리오 폭** (세로) | 해당 시즌에 **거래한 기업 개수** | 3개 이하 = **집중러** / 4개 이상 = **분산러** |

**기준이 두 개의 숫자뿐이라 부모가 결과를 납득하기 쉽고 "왜 이렇게 나왔는지"를 그 자리에서 설명할 수 있다.** 임계값(1/2개, 3/4개)은 개요 확정값이며 [가정]이 아니다.

### 4.1 유형 정의

|  | **집중러** (3개 이하) | **분산러** (4개 이상) |
|---|---|---|
| **직관형** (탭 0~1개) | **직관형 집중러** — 마음에 든 회사 한둘에 몰아넣는다. 결정이 빠르지만 고른 이유의 기록이 얇고, 그 종목이 흔들리면 전체가 흔들린다 | **직관형 분산러** — 여러 종목에 조금씩 담되 각각을 깊이 보지 않는다. 왜 샀는지 설명하기 어려운 종목이 섞인다 |
| **근거형** (탭 2개 이상) | **근거형 집중러** — 찾아볼 건 다 찾아보고 확신이 선 소수에 집중한다. 근거는 촘촘하지만 한쪽으로 쏠린다 | **근거형 분산러** — 찾아보고 나서 여러 종목에 나눠 담는다. 관심이 흩어질 수 있다 |

- **분기마다 다시 산출**하며 유형이 이동하는 것 자체가 성장 기록이다. 고정 낙인으로 표현하지 않는다.
- "이번 분기 민지는 직관형 집중러!"처럼 **기간을 반드시 표시**한다.
- 데이터가 적으면 유형을 단정하지 않고 "아직 관찰 초기"라고 표시한다.
- 어느 사분면도 더 낫지 않다. 아이 화면에 "정답은 없어!" 캡션을 병기한다.
- 임계값은 개요에서 확정됐다(탭 1/2개, 기업 3/4개). 임의로 바꾸지 않는다.

### 4.2 엔진 출력 계약

```ts
type BehaviorProfileSnapshot = {
  userId: string;
  periodStart: string;
  periodEnd: string;
  sampleSize: number;
  axes: {
    /** 매수 전 열람한 탭 수 (뉴스·기업정보·차트 중) 0~3 */
    viewedTabs: number;
    /** 시즌에 거래한 기업 개수 */
    tradedCompanies: number;
  };
  profileType:
    | "intuitive_focused"
    | "intuitive_diversified"
    | "evidence_focused"
    | "evidence_diversified"
    | null;
  reasonDistribution: Record<string, number>;
  confidencePattern: {
    average: number;
    actionAlignment: number;
  };
  observationState: "initial" | "ready";
};
```

실제 타입 이름은 `web/shared/types/`가 소유한다. 위 계약의 의미를 바꿀 때는 엔진 테스트와 F9 렌더링을 함께 갱신한다.

## 5. 폐기된 항목

| 폐기 | 대체 |
|---|---|
| 성향 5축(집중–분산·속도·신중함·손실 대응·탐험심) | 판단 근거 · 포트폴리오 폭 2축 |
| 결정 속도 축 (v2.8) | **포트폴리오 폭으로 교체 (v2.9)** |
| 유형 라벨 매트릭스 8~12종 | 4유형 사분면 |
| 친화도 스코어(ML) | 없음 — 성장은 **유형 이동 궤적**으로 본다 |

친화도 스코어를 폐기하면서 "아이에게 수치를 노출하지 않는다"는 제약도 함께 사라졌다. 다만 **4유형을 우열·성적으로 표현하지 않는다**는 원칙은 그대로 승계한다.

## 6. 화면 구성

### 6.1 가족 매매 차트

- 종목별 차트 위 부모·자녀 매수·매도 지점. 점을 누르면 거래이유가 뜬다.
- 렌더링과 마스킹 규칙은 `web/features/f11-feed/SPEC.md` §6이 소유한다.

### 6.2 투자성향 유형 카드

- 2×2 사분면 위 현재 위치와 유형 이름
- 두 축의 산출 근거 요약
- 근거 태깅 분포와 확신도 패턴
- Luna가 만든 관찰 서술 2~3문장
- “정답은 없어요!” 캡션
- 데이터 부족 시 “아직 관찰 초기” 상태

### 6.3 수익률 리포트

- 보유 종목, 평가손익, 수익률 추이
- 정량값을 그대로 표시한다.
- LLM 서술과 미래 전망을 붙이지 않는다.

### 6.4 가족 비교

- 부모와 자녀의 유형을 같은 사분면 위에 나란히 표시한다.
- “민지는 빠르게, 엄마는 오래 재고 정해요. 스타일이 달라요.”처럼 중립적으로 설명한다.
- 승패·우열·닮음 점수로 표현하지 않는다.
- 양측 공개 동의가 없으면 상대 기록을 표시하지 않는다.

### 6.5 시즌 기록

- 분기별 유형 이동 궤적
- 수익률 결산
- 시즌이 반복될수록 이전 시즌 카드를 누적한다.

## 7. LLM 경계

F9는 `gpt-5.6-luna`를 **서술 생성에만** 사용한다.

```text
F2·F3 원본 기록
  → shared/engine 룰·통계 계산
  → BehaviorProfileSnapshot JSON
  → Luna 관찰 서술 1회
  → shared/llm/filter
  → F9 화면
```

- 모델 입력에는 엔진 산출 JSON과 필요한 라벨 설명만 전달한다.
- 원시 거래 로그, 가족 대화, 수익률 전망을 모델에 전달하지 않는다.
- 유형 라벨과 모든 수치는 엔진이 계산한다. 모델이 바꾸거나 새로 만들 수 없다.
- 서술은 관찰 톤으로 2~3문장, 잘한 점·아쉬운 점 각 1~2개 이내다.
- 종목 추천, 매매 시점, 목표가, 수익률 전망, 훈계를 생성하지 않는다.
- 출력은 반드시 `web/shared/llm/filter`를 통과한다. 실패하면 고정 폴백을 표시한다.

## 8. 데모 상태

- 시즌 3주차 시점으로 시작한다.
- 시드 2주치 거래·질문식 기록·탐색 이벤트를 제공한다.
- 시연 중 새 거래를 합산해 엔진을 다시 계산하고 축 또는 분포가 화면에서 갱신되어야 한다.
- 민지와 엄마 계정 전환 시 각자의 기록만 표시한다.

## 9. 금지 사항

- 성향 축을 점수·실력·등급으로 표현하지 않는다.
- 데이터가 적은 사용자의 유형을 단정하지 않는다.
- 4유형을 우열·성적·점수로 표현하지 않는다.
- 수익률 리포트에 LLM 해석·예측을 붙이지 않는다.
- 가족 데이터를 동의 없이 비교하지 않는다.
- 기능 폴더에서 엔진 계산이나 공용 타입을 복제하지 않는다.

## 10. 완료 기준

- 골든 패스 ⑥에서 민지의 탭 열람 수·거래 기업 수, 분기 유형, 근거 분포가 시드로 렌더링된다.
- 시연 중 F2·F3 기록이 추가되면 엔진 산출과 F9 화면이 갱신된다.
- 엄마 전환 후 엄마 리포트와 중립적인 가족 비교가 표시된다.
- Luna 서술이 엔진 JSON과 일치하고 공통 필터를 통과한다.
- 수익률 값은 모델을 거치지 않고 표시된다.
- 엔진 지표별 테스트와 `web/`의 `npm run build`가 통과한다.
