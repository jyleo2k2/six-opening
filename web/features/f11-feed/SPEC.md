# F11 — 가족 거래 피드 기능 명세

> **기능 단일 원본** · 2026-08-12 · 기준: `docs/영웅키움_기획_통합문서_v2.md` v2.7 §11.4 · §10 차트
>
> 부모와 자녀가 서로의 거래 기록을 보고 코멘트로 대화하는 화면과, 종목 차트의 가족 매매 지점 표시를 이 파일에서 관리한다. 제품 목표·법무·전역 레드라인은 통합문서를 따른다.

## 1. 제품 계약

기존 아카이브(F9)는 주간·시즌 단위 리포트라 **거래가 일어난 그 순간의 대화**를 담지 못한다. **리포트는 회고이고 피드는 대화다.**

질문식 매매(F3)가 이미 근거·확신도·예상 보유기간을 필수로 받고 있으므로 **새로 입력받는 데이터가 없다.** 피드는 기존 데이터의 새 표면이다.

## 2. 소유권과 파일 책임

코드는 2026-08-13에 `mock-stock/`에서 `web/`으로 이관했고 `mock-stock/`은 삭제했다.

| 위치 | 책임 |
|---|---|
| `web/features/f11-feed/FeedScreen.tsx` | 피드 목록·카드·코멘트 UI |
| `web/shared/store/use-family-feed-store.ts` | 열람 계정·가족 거래·코멘트 상태 |
| `web/shared/store/use-investment-store.ts` | 본인 거래 (⚠ §7.2 참조 — 화면 연결 때 교체 예정) |
| `web/shared/engine/comment-filter.ts` | 부모→자녀 코멘트 게이트 (순수 함수) |
| `web/shared/engine/trade-markers.ts` | 차트 매매 지점 좌표·라벨 계산 (순수 함수) |
| `web/shared/types/trade.ts` | `Trade`·`TradeComment`·`FamilyMember` 계약 |

> ⚠ **아직 라우트에 연결되지 않았다.** `/feed` 라우트와 차트 마커 렌더는 F11 화면 작업에서 붙인다. 화면 정본이 `web/public/ui/app.html`(iframe)이므로 피드는 F10 챗봇과 같은 React 오버레이 방식으로 얹는다.

## 3. 피드 카드

| 요소 | 내용 |
|---|---|
| 헤더 | 누가 · 종목 · 언제 |
| 구분 | 매수/매도. **수량·단가는 본인 카드에만** |
| 본문 | 고른 이유 · 확신도 · 한 줄 생각 |
| 코멘트 | 목록 + 입력 |
| 액션 | 해당 종목 차트로 이동 |

정렬은 최신순이다. 본인 거래(`use-investment-store`)와 가족 거래(`use-family-feed-store`)를 합쳐 보여준다.

## 4. 코멘트 계약

```ts
type TradeComment = {
  id: string;
  tradeId: string;
  author: FamilyMember;   // "child" | "parent"
  body: string;
  createdAt: string;
};
```

- 텍스트만, **최대 200자**. 이미지·링크 없음
- 삭제는 작성자 본인만. **수정 없음** — 기록의 정직성
- **코멘트는 성향 스코어링·친화도 피처에 반영하지 않는다**

### 4.1 부모→자녀 코멘트 게이트

`gateComment({ body, author, target })`가 **부모→자녀 방향에서만** 검사한다. 자녀→부모는 검사하지 않는다.

| 차단 사유 | 예 |
|---|---|
| `recommendation` | "이거 지금 사라", "손절해야지", "사는게 좋아" |
| `timing` | "내일 팔아", "곧 오를거야" |
| `scolding` | "그러니까 내가 뭐랬어", "왜 샀어", "답답하네" |
| `grading` | "이번엔 못했네", "완전 틀렸어" |
| `empty` · `too_long` | 공백 · 200자 초과 |

차단 시 저장하지 않고 **대안을 제시하는 안내 문구**를 보여준다. 예: *"혼내는 말투는 아이가 다음 기록을 솔직하게 쓰지 않게 만들어요. 무엇이 궁금한지로 바꿔 볼까요?"*

> **왜 필터인가.** 통합문서 §21은 AI의 훈계를 금지하는데, 사람이 하는 훈계를 방치하면 "안전한 투자 경험"이 챗봇 안에서만 성립한다. 아이가 야단맞는 곳이 되면 다음 거래부터 근거 태깅을 방어적으로 쓰고, 그 순간 F9 성향 분석 데이터가 함께 망가진다. **필터는 예의가 아니라 데이터 무결성 장치다.**

**검사기에 LLM을 쓰지 않는다** — 검사기도 환각하면 게이트가 아니다. 정규식 룰과 테스트로 고정한다.

## 5. 열람 경계

- 같은 가족 팀 구성원끼리만. 리그의 다른 가족에게는 보이지 않는다
- **거래 기록만 공유한다.** 챗봇 대화 원문 · 행동 데이터(체류·스와이프) · 친화도 수치는 피드에 올리지 않는다
- **상호 열람.** 자녀도 부모 기록을 본다. 단방향이면 감시가 되고, 감시로 인식되는 순간 근거 태깅이 방어적으로 바뀐다
- **타인 카드의 수량·금액은 표시하지 않는다** — 자산 규모 비노출 (§8 실잔액 미연동과 같은 이유)

> **F10 챗봇과의 경계.** 챗봇은 계속 **본인 데이터만** 조회한다. 피드는 사용자가 직접 보는 화면이지 챗봇의 조회 범위가 아니다. "민지가 뭐 샀어?"를 챗봇에게 물으면 계속 거절한다 — 그 답은 이 화면에 있다.

## 6. 차트 가족 매매 지점 (F2 화면에 얹는다)

| 항목 | 규칙 |
|---|---|
| 대상 | 같은 종목의 가족 전원 **체결** 지점. 미체결 예약주문은 제외 (실시간 따라하기 방지) |
| 마커 | 매수 ▲ / 매도 ▼. 자녀 `fill-magenta` / 부모 `fill-navy` |
| 라벨 | `{이름} {매수/매도}` + **본인 마커에만** 수량 |
| 축 | 차트 값과 체결가를 **모두 포함**해 잡는다 (`chartBounds`) — 체결가가 범위 밖이면 마커가 잘린다 |
| 탭 | `/feed?trade={id}`로 이동하고 해당 카드를 강조 |

> **왜 단가는 안 가리나.** 마커의 y 위치가 곧 체결가다. 숨길 수 없고 숨길 이유도 없다. 가리는 것은 **수량·금액**이며 이유는 자산 규모 노출 방지다. 비교 대상은 판단이지 금액이 아니다.

## 7. 현재 구현과 남은 작업

### 7.1 구현 완료 — 2026-08-12

- `/feed` 라우트, 최신순 피드, 민지↔엄마 열람 계정 전환
- 본인·가족 거래 병합 표시, 타인 카드 수량·금액 마스킹
- 코멘트 목록·입력, 부모→자녀 게이트 5종 차단 + 안내 문구
- 종목 차트 가족 매매 지점 마커, 탭 시 피드 카드로 이동
- 엄마 시드 거래 3건 + 대화 시드 2건 (자녀 계정에서 피드가 비지 않게)

### 7.2 남은 작업

| 우선순위 | 항목 | 완료 조건 |
|---:|---|---|
| 0 | **화면 재연결** | `mock-stock` 삭제로 `/feed` 라우트와 차트 마커 렌더가 사라졌다. `FeedScreen`을 React 오버레이로 얹고, 본인 거래 소스를 `use-investment-store`에서 app.html의 `localStorage` 키 `kw_proto_v1` 어댑터로 바꾼다 — 지금은 저장소가 둘로 갈려 있다 |
| 1 | 실제 세션·가족 권한 | 지금은 클라이언트 상태의 열람 전환이다. 서버 세션이 생기면 같은 팀 구성원만 조회하도록 막고 타 가족 접근을 테스트한다 |
| 2 | 코멘트 서버 저장 | 현재 `localStorage`. 저장소가 생기면 작성자 본인만 삭제 가능하도록 서버에서 검증한다 |
| 3 | 피드 알림 정책 | 코멘트 즉시 푸시 여부 미정 — 일간 푸시 금지 원칙(§21)과 충돌 소지 |
| 4 | 게이트 강도 조정 | 차단 후 재작성 유도 vs 경고 후 통과 — 통합문서 §22 미결정 |
| 5 | 마커 밀집 처리 | 같은 종목 체결이 많아지면 x축이 균등 분할이라 시간 간격이 왜곡된다. 실제 거래일 축으로 교체 필요 |

## 8. 완료 기준

- `/feed`에서 부모·자녀 거래가 최신순으로 보이고 타인 카드에 수량·금액이 없다
- 부모 계정으로 훈계·추천 코멘트를 쓰면 차단되고 안내가 뜬다
- 자녀 계정의 같은 문구는 통과한다
- 종목 차트에 가족 매매 지점이 뜨고 탭하면 해당 피드 카드로 간다
- `web`의 `npm test`와 `npm run build`가 통과한다
