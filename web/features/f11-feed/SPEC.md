# F11 — 가족 거래 피드 기능 명세

> **기능 단일 원본** · 2026-08-12 · 기준: `docs/영웅키움_기획_통합문서_v2.md` v2.7 §11.4 · §10 차트
>
> 부모와 자녀가 서로의 거래 기록을 보고 코멘트로 대화하는 화면과, 종목 차트의 가족 매매 지점 표시를 이 파일에서 관리한다. 제품 목표·법무·전역 레드라인은 통합문서를 따른다.

## 1. 제품 계약

기존 아카이브(F9)는 주간·시즌 단위 리포트라 **거래가 일어난 그 순간의 대화**를 담지 못한다. **리포트는 회고이고 피드는 대화다.**

질문식 매매(F3)가 이미 근거·예상 보유기간을 필수로 받고 있으므로 **새로 입력받는 데이터가 없다.** 피드는 기존 데이터의 새 표면이다.

## 2. 소유권과 파일 책임

코드는 2026-08-13에 `mock-stock/`에서 `web/`으로 이관했고 `mock-stock/`은 삭제했다.

| `web/shared/engine/comment-filter.ts` | 부모→자녀 코멘트 게이트 (순수 함수) |
| `web/shared/engine/trade-markers.ts` | 차트 매매 지점 봉·라벨 계산과 `ChartTrade` 계약 (순수 함수) |
| `web/app/api/trades/route.ts` | 종목별 가족 체결 조회. 남의 수량을 지우는 지점 (§6.1) |

### 왜 라우트가 아니라 오버레이인가

화면 정본은 iframe 안의 `web/public/ui/app.html`이다. `/feed` 라우트를 따로 만들면 iframe 밖으로 나가버려 앱이 두 개로 보인다. F10 챗봇과 같은 오버레이로 얹는다.

### 본인 거래의 단일 저장소

app.html이 자체 `localStorage` 키 **`kw_proto_v1`**에 잔고·매수·매도를 저장한다. iframe이 같은 오리진이라 부모 React가 그 키를 직접 읽는다. **별도의 투자 스토어를 두지 않는다** — 저장소가 둘로 갈리면 피드와 화면이 어긋난다.

`prototype-trades.ts`가 처리하는 변환:

| app.html | `Trade` |
|---|---|
| `records` / `sellRecords` | `side: "buy"` / `"sell"` |
| `user_id: "child_minji"` / `"parent_mom"` | `member` |
| `amount_krw ÷ qty` | `price` |
| `reason_code`·`sell_reason_code` | `reason` (한글 라벨) |
| `order_status: "pending"` | **제외** — 미체결 지정가는 피드에 올리지 않는다 (§6) |

### 피드 → 차트 이동

`postMessage({ type: "kiwoom:open-stock", symbol })`을 app.html이 받아 해당 종목 상세로 전환한다. origin을 검증하며 F10의 `kiwoom:chat-context`와 같은 방식이다.

| 요소 | 내용 |

| 헤더 | 누가 · 종목 · 언제 |

## 4. 코멘트 계약

```ts
type TradeComment = {
  id: string;
  tradeId: string;
  author: FamilyMember;   // "child" | "parent"
  body: string;
  createdAt: string;
};
```

- 텍스트만, **최대 200자**. 이미지·링크 없음
- 삭제는 작성자 본인만. **수정 없음** — 기록의 정직성
- **코멘트는 성향 스코어링·친화도 피처에 반영하지 않는다**

### 4.1 부모→자녀 코멘트 게이트

`gateComment({ body, author, target })`가 **부모→자녀 방향에서만** 검사한다. 자녀→부모는 검사하지 않는다.

| 차단 사유 | 예 |
|---|---|
| `recommendation` | "이거 지금 사라", "손절해야지", "사는게 좋아" |
| `timing` | "내일 팔아", "곧 오를거야" |
| `scolding` | "그러니까 내가 뭐랬어", "왜 샀어", "답답하네" |
| `grading` | "이번엔 못했네", "완전 틀렸어" |
| `empty` · `too_long` | 공백 · 200자 초과 |

차단 시 저장하지 않고 **대안을 제시하는 안내 문구**를 보여준다. 예: *"혼내는 말투는 아이가 다음 기록을 솔직하게 쓰지 않게 만들어요. 무엇이 궁금한지로 바꿔 볼까요?"*

> **왜 필터인가.** 통합문서 §21은 AI의 훈계를 금지하는데, 사람이 하는 훈계를 방치하면 "안전한 투자 경험"이 챗봇 안에서만 성립한다. 아이가 야단맞는 곳이 되면 다음 거래부터 근거 태깅을 방어적으로 쓰고, 그 순간 F9 성향 분석 데이터가 함께 망가진다. **필터는 예의가 아니라 데이터 무결성 장치다.**

**검사기에 LLM을 쓰지 않는다** — 검사기도 환각하면 게이트가 아니다. 정규식 룰과 테스트로 고정한다.

## 5. 열람 경계

- 같은 가족 팀 구성원끼리만. 리그의 다른 가족에게는 보이지 않는다
- **거래 기록만 공유한다.** 챗봇 대화 원문 · 행동 데이터(체류·스와이프) · 친화도 수치는 피드에 올리지 않는다
- **상호 열람.** 자녀도 부모 기록을 본다. 단방향이면 감시가 되고, 감시로 인식되는 순간 근거 태깅이 방어적으로 바뀐다
- **타인 카드의 수량·금액은 표시하지 않는다** — 자산 규모 비노출 (§8 실잔액 미연동과 같은 이유)

> **F10 챗봇과의 경계.** 챗봇은 계속 **본인 데이터만** 조회한다. 피드는 사용자가 직접 보는 화면이지 챗봇의 조회 범위가 아니다. "민지가 뭐 샀어?"를 챗봇에게 물으면 계속 거절한다 — 그 답은 이 화면에 있다.

## 6. 차트 가족 매매 지점 (F2 화면에 얹는다)

| 항목 | 규칙 |
|---|---|
| 대상 | 같은 종목의 **같은 가족 전원** 체결 지점. `transactions` 에는 체결만 들어가므로 미체결 예약주문은 애초에 없다 (실시간 따라하기 방지) |
| 출처 | **Supabase `transactions` 하나뿐이다.** 차트는 `GET /api/trades?symbol=` 만 읽는다 |
| 마커 | 둥근 뱃지(22×22, `rx=6`) 안에 흰 글자 **B**(매수) / **S**(매도). 말풍선 꼬리가 뱃지 변에 붙어 체결가를 가리킨다 |
| 색 | 자녀 `--color-trade-child` / 부모 `--color-trade-parent`. **등락색(`up`·`down`)을 쓰지 않는다** |
| 캡션 | **없다.** 글자가 매수·매도를, 색이 사람을 나타낸다 |
| 라벨 | `{이름} {매수/매도}` + **본인 마커에만** 수량. 이름은 `profiles.name` 을 그대로 쓴다. 화면에는 안 쓰고 SVG `<title>` 로만 남긴다 |
| x축 | 체결 시각 **이하의 마지막 봉**에 붙인다. 첫 봉보다 이른 체결은 차트 범위 밖이라 버린다 |
| y축 | 체결가를 `priceToCoordinate` 로 옮긴 자리. 봉 위아래로 밀지 않는다 |
| 탭 | **없다.** 마커는 표시만 한다 |
| 수량 마스킹 | **서버가 한다.** `GET /api/trades` 가 세션 사용자 본인 체결에만 `quantity` 를 담고 나머지는 `null` 로 지운다 |

### 6.1 데이터 계약 — `GET /api/trades?symbol={6자리}`

세션(`kw_uid`)이 없으면 401, 종목 코드가 6자리 숫자가 아니면 400이다.

```
transactions
  ├ stocks!inner    stock_code = symbol
  └ profiles!inner  family_tag = 내 family_tag   (family_tag 이 없으면 본인 체결만)
```

응답은 `{ trades: ChartTrade[] }` 이고 `created_at` 오름차순이다.

| 필드 | 출처 | 비고 |
|---|---|---|
| `id` | `transactions.id` | |
| `name` | `profiles.name` | 마커 라벨에 그대로 쓴다 |
| `member` | `profiles.parent_child` | 마커 색을 정한다. `null` 이면 `child` |
| `side` | `transactions.side` | `B`/`S` 글자를 정한다 |
| `price` | `transactions.trade_price` | 마커의 y |
| `quantity` | `transactions.trade_quantity` | **본인 체결만.** 남의 것은 `null` |
| `tradedAt` | `transactions.created_at` | 붙일 봉을 정한다 |

> **왜 마스킹을 서버로 옮겼나.** 예전에는 차트 URL 의 `viewer` 쿼리로 열람 계정을 받아 클라이언트가 가렸다. 그런데 app.html 이 그 쿼리를 붙이지 않아 **실제로는 아무에게도 수량이 안 붙었고**, 붙였더라도 남의 수량이 응답에는 실려 오므로 가리는 시늉일 뿐이었다. 세션은 서버가 이미 아니까 서버가 지운다. `viewer` 쿼리는 없앤다.

> **왜 단가는 안 가리나.** 마커의 y 위치가 곧 체결가다. 숨길 수 없고 숨길 이유도 없다. 가리는 것은 **수량·금액**이며 이유는 자산 규모 노출 방지다. 비교 대상은 판단이지 금액이 아니다.

> **왜 코드 시드와 `localStorage` 를 끊었나.** 2026-08-13 이전에는 본인 거래를 app.html 의 `localStorage`, 엄마 거래를 `shared/store/family-trade-seed` 에서 읽어 합쳤다. 저장소가 셋으로 갈려 있어 같은 체결이 화면마다 다르게 보일 수 있었다. 차트 마커는 `transactions` 한 곳만 본다. 시드는 피드(F11 화면)와 성향 분석(F9)이 계속 쓰므로 파일은 남긴다.

> **빈 차트는 정상이다.** `transactions` 에 그 종목 체결이 없으면 마커가 하나도 없다. 시드로 채우지 않는다.

> **왜 마커를 눌러도 아무 일이 없나.** 거래 내역이 아카이브 화면의 피드 형식으로 옮겨가는 중이라 이동 목적지가 아직 없다(2026-08-13 결정). 목적지가 정해지기 전에 이동을 붙이면 곧 다시 뜯어야 한다. UI 가 자리를 잡으면 §7.2 에서 다시 판단한다.

> **왜 캡션을 안 다나.** 시안 원본에는 `자녀 매수 · 10/14` 캡션이 있었지만, 한 종목에 체결이 쌓이면 글자가 겹쳐 차트를 덮는다. 글자로 매수·매도를, 색으로 사람을 구분하면 캡션 없이도 읽힌다.

> **왜 등락색을 안 쓰나.** `--color-up`(빨강)·`--color-down`(파랑)은 캔들이 이미 쓰고 있다. 마커에 같은 색을 쓰면 보는 사람이 "빨간 마커 = 오른 날"로 읽는다.

### 좌표는 라이브러리에서 받고 그리기는 SVG 로 한다

2026-08-13 에 차트가 app.html 안 SVG 에서 `lightweight-charts` 로 바뀌었다. `trade-markers.ts` 가 픽셀 좌표(`x`·`y`·삼각형 `points`)와 `chartBounds` 를 직접 계산하던 이유가 사라졌으므로 걷어냈다. 엔진은 **무엇을 언제 어떤 라벨로** 찍을지만 정한다.

라이브러리 기본 마커(`createSeriesMarkers`)는 모양이 원·사각·화살표뿐이라 시안의 "삼각 포인터 + 둥근 뱃지 + 흰 B/S" 를 못 그린다. 대신 좌표 변환만 빌린다.

```
timeScale().timeToCoordinate(체결 봉 시각)  →  x
series.priceToCoordinate(체결가)            →  y
```

받은 좌표에 SVG 를 차트 위에 얹는다. 시안 마크업을 그대로 쓸 수 있고, 나중에 탭·툴팁을 붙일 때도 DOM 이벤트로 끝난다. 스크롤·줌·리사이즈 때는 `subscribeVisibleLogicalRangeChange` 와 `ResizeObserver` 로 좌표를 다시 잡고, 화면 밖으로 나간 체결은 좌표가 `null` 이라 그리지 않는다.

**마커는 받은 x 를 그대로 쓴다.** 예전에는 뱃지가 가격축 숫자를 덮지 않도록 x 를 `[뱃지폭/2, 페인폭-뱃지폭/2]` 로 잘라 붙였는데, 그러면 차트를 드래그해 체결일이 오른쪽 끝을 지날 때 뱃지가 그 자리에 눌러앉아 **거래일이 아닌 날짜를 가리켰다.** 마커의 존재 이유가 "언제 샀고 언제 팔았나" 이므로 날짜가 어긋나는 쪽이 축을 덮는 쪽보다 나쁘다. 대신 SVG 자체의 폭을 `chart.paneSize().width` 로 맞춰 가격축 앞에서 잘리게 한다 — 클램프 없이도 축을 덮지 않는다.

차트는 app.html 안의 iframe(`/tradingview-chart`)이고 마커 원본은 `GET /api/trades` 로 받는다. 세션 쿠키(`kw_uid`)는 같은 오리진이라 iframe 요청에도 그대로 실린다.

| 1 | **로그인 붙이기** | 지금은 `DEMO_USER_ID` 환경변수로 세션을 대신한다(`app/api/supabase.ts`). app.html 에 로그인이 붙어 `kw_uid` 쿠키가 진짜로 발급되면 마커·피드가 사람별로 갈린다. **그 전까지 서버는 모두를 같은 한 사람으로 본다** |
| 2 | **가족 구성원 늘리기** | `profiles` 에 부모 계정이 생기고 `family_tag` 가 같아야 §6.1 질의가 실제로 두 사람을 돌려준다. 현재는 한 명뿐이라 사실상 본인 체결만 보인다 |
| 2 | **디자인시스템 문서에 토큰 등재** | `--color-trade-child`·`--color-trade-parent` 를 `app/globals.css` 에는 넣었지만 `docs/디자인시스템.md` 에는 아직 없다. 그 문서를 다른 세션이 claim 중이라 못 넣었다 |
| 3 | 마커 겹침 | 같은 봉·비슷한 체결가의 마커가 서로를 가린다. 주봉에서는 한 주 체결이 모두 같은 x 에 쌓인다. "언제 샀나"만 보면 되는 단계라 미뤄 둔다 |
| 3 | 피드도 같은 출처로 | 마커는 `transactions` 로 옮겼지만 피드 화면은 아직 `localStorage` + 시드다. 저장소가 갈려 있으므로 순서를 정해 옮긴다 |
| 4 | 코멘트 서버 저장 | 현재 `localStorage`. 저장소가 생기면 작성자 본인만 삭제 가능하도록 서버에서 검증한다 |
| 5 | 피드 알림 정책 | 코멘트 즉시 푸시 여부 미정 — 일간 푸시 금지 원칙(§21)과 충돌 소지 |
| 6 | 게이트 강도 조정 | 차단 후 재작성 유도 vs 경고 후 통과 — 통합문서 §22 미결정 |

## 8. 완료 기준

- "가족 기록" 버튼으로 피드가 열리고 부모·자녀 거래가 최신순으로 보이며 타인 카드에 수량·금액이 없다
- 부모 계정으로 훈계·추천 코멘트를 쓰면 차단되고 안내가 뜬다
- 자녀 계정의 같은 문구는 통과한다
- "차트에서 이 지점 보기"를 누르면 iframe이 해당 종목 상세로 이동한다
- (§7.2 우선순위 0) 종목 차트에 가족 매매 지점이 뜨고 탭하면 해당 피드 카드로 간다
- `web`의 `npm test`와 `npm run build`가 통과한다
