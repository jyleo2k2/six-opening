# 영웅 키움 — 질문식 매매 구현 스펙 v1

> **모의투자 구현 담당 공유용** · 2026-08-11 · 기준: 기획 통합 문서 v2.2 §10
> 이 문서 하나로 매수·매도 플로우의 화면, 카피, 선택지 코드값, 판정 로직, 저장 스키마를 구현할 수 있어야 한다.
> 카피(문구)는 확정안이며, 워딩 수정 시 기획과 협의.

## 0. 인터랙션 원칙 (확정)

| # | 원칙 |
|---|---|
| 1 | 매수 이유 · 보유 계획 · 매도 이유 · 조건부 질문 = **버튼식** (택1) |
| 2 | 확신도 = **슬라이더 바** (0~100 연속형. 아이 화면엔 숫자 비노출 — 말과 표정 중심) |
| 3 | 매도 시 **'사던 날의 나' 카드 필수 노출** (스킵 불가 화면) |
| 4 | **계획과 다르게 매도할 때만** 조건부 미니 질문 노출 (계획 일치 시 질문 생략) |
| 5 | 질문은 게이트가 아니다 — 어떤 답이든 주문 진행. 오답 처리·훈계·점수 노출 없음 |
| 6 | 타이핑 없음 (한 줄 메모만 선택 입력) |

핵심 컨셉: **"판단(매수 기록) → 행동(보유·매도) → 회고(사던 날의 나)"가 연결되는 투자 학습 루프.** 정답을 맞히게 하는 게 아니라, 매수 당시 생각을 기록하고 매도할 때 다시 만나게 한다.

## 1. 전체 플로우

```
[매수]
종목 상세 ─[사볼래!(매수)]→ ①금액·가격 → ②Q1 이유(버튼)
  → ③Q2 확신도(슬라이더) → ④Q3 보유 계획(버튼)
  → (계획='목표 가격'이면 ④-1 목표가 설정) → ⑤확인·주문 → 완료(+메모 선택)

[매도]
보유 카드 ─[팔래(매도)]→ ①수량 → ②'사던 날의 나' 카드(필수)
  → ③Q4 매도 이유(버튼) → ④판정: 계획 일치?
       ├─ 일치   → 질문 없이 진행
       ├─ 불일치 → Q5 조건부 미니 질문(버튼 5)
       └─ 판정 불가(계획='모르겠어') → 질문 생략
  → ⑤확인·주문 → 완료(회고 기록 저장, +메모 선택)
```

## 2. 매수 플로우 — 화면별 스펙

### BUY-0. 진입 (종목 상세)

- CTA 버튼: `사볼래! (매수)` — 용어는 숨기지 않고 **번역 병기** 원칙
- 종목 상세는 어린이 친화 모드: 호가창 없음. 현재가 + 간단 차트 + "이 회사는 ○○를 만들어요" 한 줄

### BUY-1. 얼마나 살까?

| 요소 | 스펙 |
|---|---|
| 잔액 표시 | `💰 내 지갑: 820,000원` |
| 금액 입력 | 칩 버튼 `[1만원] [3만원] [5만원] [직접 입력]` — 직접 입력은 숫자 패드 |
| 수량 환산 | 실시간 자동 표시: "삼성전자 약 2주를 살 수 있어" (아이에게 수량 계산 시키지 않기) |
| 가격 방식 | 토글 `[지금 가격에 바로 사기(시장가)]` / `[내가 정한 가격 되면 사기(지정가)]` — 데모는 시장가만 활성, 지정가는 UI만 |
| 검증 | 잔액 초과 시 진행 불가 + "지갑보다 많이 살 수는 없어!" / 최소 수량 미달 시 진행 불가 + 안내. **단일종목 한도 검증은 없다 [확정 2026-08-13]** |

### BUY-2. Q1 "왜 이 회사가 좋아 보였어?" (버튼 택1, 필수)

키웅이 말풍선: **"왜 이 회사가 좋아 보였어? 정답은 없어, 솔직한 게 최고야!"**

| 버튼 (아이 화면) | `reason_code` | 내부 태그 |
|---|---|---|
| 📰 뉴스에서 봐서 | `buy_news` | 정보형·자기 |
| 📈 그래프가 좋아 보여서 | `buy_chart` | 정보형·자기 |
| 🛒 내가 아는 회사·써본 거라서 | `buy_familiar` | 정보형(경험)·자기 |
| 🏆 인기 순위에서 봐서 | `buy_ranking` | 소셜형·군중 |
| 🗣 친구·가족이 말해줘서 | `buy_social` | 소셜형·타인 |
| 🤷 그냥 느낌이 좋아서 | `buy_intuition` | 직관형·무근거 |

- 6개 버튼 **2열 × 3행**, 전부 동일 색·크기 (우열 표현 금지)
- **순서 로테이션**: 세션마다 6개 버튼 순서 셔플 (위치 편향 상쇄) — 셔플 시드는 세션 ID

### BUY-3. Q2 "얼마나 자신 있어?" (슬라이더, 필수)

키웅이 말풍선: **"정답은 없어! 지금 네 마음에 가까운 곳으로 움직여봐."**

```
잘 모르겠어                              정말 자신 있어!
 😶 ━━━━━━━●━━━━━━━━━━━━━━━━ 🔥
        현재 선택: "조금 자신 있어"
```

| 슬라이더 값 | 아이에게 보이는 문구 | 키웅이/썸 표정 | `confidence_band` |
|---|---|---|---|
| 0~24 | 아직 잘 모르겠어 | 😶 | `confidence_low` |
| 25~49 | 조금 자신 있어 | 🙂 | `confidence_mid_low` |
| 50~74 | 꽤 자신 있어 | 😎 | `confidence_mid_high` |
| 75~100 | 정말 자신 있어! | 🔥 | `confidence_high` |

**구현 규칙:**

- **아이 화면에 숫자(0~100) 비노출** — 문구·표정만 갱신. (숫자를 보이면 "100 = 좋은 답"으로 오인 → 데이터 오염)
- 저장은 **원시값 `confidence_raw` (0~100 정수)** + 파생 `confidence_band` 둘 다
- 초기 핸들 위치: **50 고정** (중앙 시작 — 초기값 편향 최소화). 핸들을 한 번도 안 움직여도 진행 가능하되, `slider_touched: false` 플래그 저장 (무응답 구분용)
- 드래그 중 표정·문구 실시간 변경 (구간 경계에서 전환)

### BUY-4. Q3 "언제까지 가질 생각이야?" (버튼 택1, 필수)

| 버튼 | `plan_code` | 태그 |
|---|---|---|
| 📅 이번 주만 | `plan_short` | 기간 계획 |
| 🏁 시즌 끝까지 | `plan_season` | 기간 계획 |
| 🎯 내가 정한 목표 가격이 되면 | `plan_target` | 조건 계획 |
| 🤷 아직 모르겠어 | `plan_none` | 무계획 |

**BUY-4-1. (조건부) 목표가 설정** — `plan_target` 선택 시에만:

- 칩 버튼 `[+5%] [+10%] [+20%] [직접 입력]` → 환산가 표시: "지금 71,000원 → 목표 78,100원"
- 저장: `plan_target_price` (원 단위). 하락 목표(손절가)는 v1 스코프 제외

### BUY-5. 확인 → 완료

- 주문 요약: 종목 · 금액(수량) · 가격 방식
- **내 답 한 문장 조립** (1차 회고 장치): `"뉴스를 보고 · 꽤 자신 있게 · 시즌 끝까지"`
- CTA: `주문 넣기!` → 체결 → 완료 화면: 🎉 **"기록 완료! 키웅이가 기억해둘게"** (컨페티)
- 완료 화면에 **한 줄 메모 (선택)**: "하고 싶은 말이 있으면 남겨둬 (나중에 다시 보여줄게)" — 최대 50자

## 3. 매도 플로우 — 화면별 스펙

### SELL-1. 얼마나 팔까?

- 칩 버튼 `[전부] [절반] [직접 입력]` + 보유 수량·평가손익 표시

### SELL-2. ⭐ '사던 날의 나' 카드 (필수 노출 — 스킵 불가, [다음] 버튼으로만 진행)

키웅이 말풍선: **"잠깐! 사던 날의 너는 이렇게 생각했어."**

```
┌──────────────────────────────────┐
│  3주 전의 나                       │
│  "뉴스를 보고,                     │
│   꽤 자신 있게,                    │
│   시즌 끝까지 가지려고 샀어."        │   ← 카드의 중심 (크게)
│  ✍️ "월드투어 시작한대"  (메모 있을 때만) │
│  ──────────────────────────       │
│  현재                              │
│  수익률      +5.2%                 │   ← 보조 정보 (작게)
│  보유 기간    3주                   │
│  남은 시즌    5주                   │
└──────────────────────────────────┘
```

**레이아웃 규칙 (중요):**

- **당시 생각이 카드의 중심** (큰 글씨), 수익률은 보조 정보 (작은 글씨)
- 수익률에 **빨강·파랑 강조 금지** — 중립 색(잉크색) 사용. 손익을 강조하면 아이가 회고 대신 손익에만 집중함
- 당시 계획과 현재 상황을 **나란히** 배치 (계획 대비 어디까지 왔는지 스스로 비교하게)
- 이 카드는 **평가하지 않는다** — "잘했다/못했다" 문구 절대 금지

### SELL-3. Q4 "왜 팔고 싶어?" (버튼 택1, 필수)

| 버튼 | `sell_reason_code` | 태그 |
|---|---|---|
| 🎯 목표한 만큼 와서 | `sell_target_hit` | 계획 실행형 |
| 🏁 정한 날짜가 돼서 | `sell_plan_time` | 계획 실행형 |
| 🔄 더 좋아 보이는 회사를 찾아서 | `sell_rebalance` | 정보·재배분형 |
| 😟 더 떨어질까 봐 | `sell_fear_drop` | 감정·손실회피형 |
| 😰 그냥 불안해서 | `sell_anxiety` | 감정형 |
| 💰 다른 데 쓸 돈이 필요해서 | `sell_liquidity` | 유동성(중립) |

- 로테이션: 상위 5개 셔플, `sell_liquidity`는 **항상 마지막 고정** (중립 배출구)
- `sell_liquidity`는 성향·친화도 분석에서 제외 (진짜 사유의 오염 방지용 버튼)

### SELL-4. 계획 일치 판정 → 분기

**판정 함수 (연결된 매수 기록의 `plan_code` 기준):**

| 매수 당시 계획 | `plan_match = true` 조건 | 비고 |
|---|---|---|
| `plan_short` (이번 주만) | 매수일로부터 `SHORT_TERM_DAYS`(기본 7일) 이내 매도 | 파라미터로 조정 가능 |
| `plan_season` (시즌 끝까지) | 시즌 종료 주간(결산 주) 매도 **또는** 시즌 종료 자동 청산 | 자동 청산도 일치 처리 |
| `plan_target` (목표 가격) | 매도 시점 현재가 ≥ `plan_target_price` | |
| `plan_none` (모르겠어) | **판정하지 않음** (`plan_match = null`) | 질문 없음 — 중립 통과 |

```pseudo
function judgePlanMatch(buyRecord, sellContext):
  switch buyRecord.plan_code:
    case plan_short:  return daysBetween(buyRecord.ts, now) <= SHORT_TERM_DAYS
    case plan_season: return sellContext.isSettlementWeek or sellContext.isAutoLiquidation
    case plan_target: return sellContext.currentPrice >= buyRecord.plan_target_price
    case plan_none:   return null   // 판정 안 함
```

**분기 A — 일치 (`true`):** 조건부 질문 없이 SELL-5로 진행 (`plan_match: true`만 기록)

**분기 B — 불일치 (`false`) → Q5 조건부 미니 질문:**

키웅이: **"처음에는 ○○(계획 문구 삽입)하려고 했었네. 계획이 바뀌는 건 괜찮아! 무엇이 달라졌어?"**

| 버튼 | `change_reason_code` | 구분하는 것 |
|---|---|---|
| 📰 새로운 소식을 알게 됐어 | `change_new_info` | 새 정보 유입 |
| 🏢 회사에 대한 생각이 바뀌었어 | `change_view_shift` | 기업 판단 변화 |
| 📉 가격이 움직여서 불안해졌어 | `change_price_emotion` | 가격·감정 반응 |
| 🔄 다른 회사가 더 좋아 보였어 | `change_alternative` | 대안 발견 |
| 🙋 처음 계획이 나와 맞지 않았어 | `change_plan_revision` | 자기 계획 수정 |

**분기 C — 판정 불가 (`null`):** 질문 없이 SELL-5로 직행

### SELL-5. 확인 → 완료

- 주문 요약 + 완료 화면. 매도 회고 기록(아래 스키마) 저장
- 한 줄 메모(선택) + 재매수 제한 안내: "이 회사는 30분 뒤에 다시 살 수 있어" [잠정]

## 5. 엣지 케이스 규칙

| 케이스 | 규칙 |
|---|---|
| **같은 종목 추가 매수** | 매수 질문(Q1~Q3)은 **주문마다 반복** (기록은 주문 단위). 부담 경감: 동일 종목 재매수 시 "지난번엔 '뉴스를 봐서'라고 했어. 이번엔?" 프리텍스트로 이전 답 표시(선택은 새로 함) |
| **매도 시 회고 카드의 기준 매수** | 해당 종목의 **가장 최근 매수 기록** 기준 (`linked_buy_order_id`). 매수가 여러 번이면 카드에 "이 회사를 3번 샀어" 뱃지 병기 |
| **부분 매도** | 회고 카드·Q4·판정 동일하게 진행. 잔여 보유분은 원래 매수 기록 유지 (다음 매도 때 또 소환) |
| **부분 매도 반복** | 같은 `linked_buy_order_id`로 2번째 매도부터는 회고 카드 표시하되 조건부 질문은 **첫 매도에서만** (반복 피로 방지) |
| **시즌 종료 자동 청산** | `plan_season`은 일치 처리, 그 외 계획은 판정 없이 청산. 질문 플로우 미노출 |
| **`plan_none` 매도** | 판정·조건부 질문 전부 생략 (중립) |
| **지정가 주문 미체결 취소** | 질문 기록은 저장 유지 (`order_status: cancelled`) — 취소도 행동 데이터 |
| **회고 카드에 메모 없음** | 메모 줄 자체를 렌더링하지 않음 (빈 칸 노출 금지) |

## 6. 스코어 반영 규칙 (분석 파트 참고 — 구현은 로그 저장까지만)

**⚠️ 확신도는 '높을수록 좋은 값'이 아니다.** 친화도에 반영되는 건 확신도의 **크기가 아니라 확신-행동 정합성**:

- 확신도 20인데 자산 50% 투자 → 확신-행동 **불일치** 신호
- 확신도 80이어도 적절히 분산 → 자신감 높지만 위험 조절 가능 신호
- 모든 종목에 항상 95~100 → 자기평가 **분화 부족** 신호
- 종목별로 30·60·80처럼 다르게 응답 → **판단을 구분하기 시작** (성장 신호)

confidence_raw로 가능한 분석: 확신도×투자금액 관계 / 확신도×수익률 관계 / 확신도×계획 준수 관계 / 종목별 분화 / 시즌 경과에 따른 과잉·현실화 조정.

| 데이터 | 성향 5축 (스타일) | 친화도 (성장 방향) |
|---|---|---|
| reason_code 분포 | 리포트 서술 | ① 근거 성숙도 (직관→소셜→정보 이동) |
| confidence_raw | 신중함 축 (확신×금액 정합) | ③ 확신도 분화 (분산 증가) |
| plan_code + 실보유 | 속도 축 | ② 계획 보유율·계획-행동 일치율 |
| sell_reason_code | 손실 대응·탐험심 축 | — |
| change_reason_code | — | ④ 계획 변경의 질 (`change_new_info` 비중↑ = 성장) |
| retro/memo 이벤트 | — | ⑤ 자발 신호 |
