# 와이어프레임 브리프 — 현재 클릭 가능한 프로토타입

> 갱신: 2026-08-14 · 기준: `web/public/ui/app.html`과 `/`의 React 오버레이
>
> 이 문서는 새 화면 제안서가 아니라 현재 구현을 다시 그릴 수 있는 AS-IS 브리프다. 기능 계약은 각 `web/features/*/SPEC.md`를 따른다.

## 서비스 한 줄

자녀와 부모가 각자 가상 지갑으로 모의투자하고, 거래 이유와 행동 기록을 성장 아카이브와 가족 대화로 되돌려보는 모바일 데모다.

## 1. 캔버스와 런타임

- 바깥 기기 프레임: 450×920
- 실제 앱 콘텐츠: 402×874, 프레임 안 좌측 24px·상단 23px
- 상태바: 402×59
- 작은 브라우저: 450×920 전체를 비율 축소
- 메인 앱: `/ui/app.html?runtime=1` iframe
- iframe 밖 오버레이: F10 키웅이, F11 가족 기록
- 메인 하단 탭: 홈 / 모의투자 / 아카이브 / 랭킹 4개
- 메인 계정 전환 스위치: 없음

컬러·타이포·공용 컴포넌트는 `docs/디자인시스템.md`를 따른다. 정적 화면은 현재 인라인 색상·그라디언트를 사용한다.

## 2. 전역 화면 구조

```text
홈
├─ 내 계좌 보기 → 포트폴리오
├─ 모의투자 하러 가기 → 종목 탐색
├─ 아카이브 탭 → 성장 아카이브
└─ 랭킹 탭 → 랭킹

종목 탐색 → 종목 상세
             ├─ 차트 → TradingView 차트
             ├─ 뉴스 → 뉴스 상세
             ├─ 매수 → 매수 3단계
             └─ 매도 → 매도 3단계

전역 버튼
├─ 키웅이 → F10 오버레이
└─ 가족 기록 → F11 오버레이 → 종목 상세
```

## 3. 메인 화면

### 3.1 홈

상단부터 아래 순서로 배치한다.

1. `영웅 키움` 타이틀과 `시즌 3`
2. 사용자 카드
   - 이니셜 아바타
   - 이름 `김찬영`
   - 마스킹된 모의투자 계좌 번호
   - 전체 자산과 손익
   - `시작할 때 10,000,000원`
   - 쓸 수 있는 돈 / 가진 회사
   - `내 계좌 보기`
3. 시즌 진행: 3주차 / 4주, 75% 바
4. 부모 계정일 때만 보이도록 작성된 스쿨락 카드
5. pill 형태 `모의투자 하러 가기` CTA
6. 하단 4탭

메인 계정이 기본 `child`로 고정되고 전환 UI가 없어 부모 전용 스쿨락 카드는 일반 사용자 흐름에서 열 수 없다.

### 3.2 종목 탐색

- 제목: `어떤 회사를 살까?`
- 회사명 검색 입력과 지우기
- 가로 스크롤 섹터 칩 13개
- 51개 화이트리스트 종목을 가로 스와이프 카드로 표시
- 카드: 카테고리, 회사명, 한 줄 설명, 현재가, 등락, 스파크라인
- 카드를 누르면 종목 상세로 이동
- 빈 검색 결과 안내
- 하단 4탭 유지

### 3.3 종목 상세

- 뒤로가기, 종목명, 관심 종목 하트
- 현재가와 등락
- 보유 수량·평가 정보
- 탭형 정보 영역과 관련 상세 진입
- 차트 보기 → 내부 `/tradingview-chart` iframe
- 뉴스 보기 → 뉴스 상세
- 하단 매수 / 매도 진입

상세 탭 체류는 매수 전 정보 확인 근거로 사용한다. 유효 체류 기준은 탭당 10초 이상이다.

### 3.4 차트

- `lightweight-charts` 캔들 차트
- 서버 체결이 있으면 가족 B·S 마커 표시
- 자녀와 부모는 별도 마커 색 사용
- 마커는 표시 전용이며 클릭되지 않음
- 데이터가 없으면 빈 마커가 정상

### 3.5 뉴스 상세

- 선택 종목 관련 뉴스 표시
- 열람 시작·종료 체류 이벤트 기록
- 뒤로가기로 종목 상세 복귀

## 4. 주문 화면

### 4.1 매수 3단계

#### 1단계 — 주문값

- 시장가 / 지정가
- 금액 / 주 수 입력
- 주문 가능 최대치
- 지정가일 때 가격 입력
- 자녀 스쿨락 시간에는 주문 차단 안내

#### 2단계 — 이유

6개 중 하나를 필수 선택한다.

- 뉴스를 봤어
- 차트를 봤어
- 잘 아는 회사야
- 순위에서 봤어
- 주변에서 들었어
- 그냥 느낌이야

한 줄 메모는 선택이며 최대 50자다.

#### 3단계 — 보유 계획·완료

- 단기로 볼래
- 시즌 동안 볼래
- 목표 가격까지 볼래: 현재가 대비 +5% / +10% / +20%
- 아직 모르겠어

시장은 즉시 로컬 체결 후 컨페티 완료 화면을 보인다. 지정가는 현금을 예약한 pending 상태만 만든다. 확신도 선택 화면은 없다.

### 4.2 매도 3단계

#### 1단계 — 주문값

- 시장가 / 지정가
- 금액 / 주 수 입력
- 현재 보유 최대치

#### 2단계 — 이유

- 목표에 도달했어
- 계획한 시간이 됐어
- 비중을 바꾸고 싶어
- 더 떨어질까 걱정돼
- 그냥 불안해
- 돈이 필요해

#### 3단계 — 계획 비교·완료

처음 계획과 같은지 기록한다. 다르면 새 정보, 생각 변화, 가격 감정, 다른 대안, 계획 수정 중 하나를 고른다. 시장가는 즉시 반영하며 지정가는 pending이다.

## 5. 포트폴리오와 랭킹

### 5.1 포트폴리오

- 전체 자산, 손익, 현금
- 보유 종목별 수량·평가금액·손익
- 보유가 없을 때 빈 상태
- 종목 선택 시 상세로 이동

### 5.2 랭킹

- 네이비 상단 히어로 영역
- 이번 주 / 시즌 전체 토글
- 1~3위 시상대
- 가족 리그 순위 목록
- 하단 4탭

## 6. 성장 아카이브

상단 탭은 성향 / 수익률 / 가족 비교 / 시즌 기록 4개다. 첫 진입 때 자녀·부모 프로필을 `/api/profile`로 계산하고 서술을 요청한다.

### 6.1 성향

- 이번 시즌 캐릭터 카드
- `정답은 없어!` 배지
- 5개 능력치 SVG 오각형, 10점 만점
- 매수 이유 분포
- 키웅이 시즌 서술

현재 엔진 응답과 UI 필드명이 달라 캐릭터 이모지와 별 레벨이 비어 보일 수 있다.

### 6.2 수익률

- 전체 자산과 손익·수익률
- 시작금 10,000,000원
- 보유 종목별 평가와 현금
- 미보유 빈 상태

### 6.3 가족 비교

- `양쪽이 공개에 동의했어요` 고정 문구
- 자녀·부모 캐릭터 카드
- 5개 능력치 숫자 병치
- 중립 비교 문장

동의 문구는 실제 동의 상태를 조회하지 않는다.

### 6.4 시즌 기록

- 현재 시즌의 매수·매도·메모·상세 확인 횟수
- `4주차에 열려` 잠금 카드
- 과거 시즌 목록이나 시즌 간 변화 그래프는 없음

## 7. 전역 React 오버레이

### 7.1 F10 키웅이

- iframe 밖 플로팅 버튼
- 화면 맥락을 전달받는 챗봇 오버레이
- 종목 추천·매매 시점·목표가·수익률 전망은 거절
- 허용된 화면 이동은 사용자가 버튼을 눌렀을 때만 실행

세부 발화·안전 게이트는 F10 SPEC이 단일 원본이다.

### 7.2 F11 가족 기록

- `가족 기록` 고정 버튼으로 전체 오버레이 열기
- `민지로 보기` / `엄마로 보기`: 피드의 본인 판정만 변경
- 로컬 체결과 가족 시드를 최신순 카드로 표시
- 본인 카드만 수량·주당 단가 노출
- 코멘트 입력과 부모→자녀 표현 게이트
- `차트에서 이 지점 보기` 버튼은 현재 종목 상세로 이동
- 좋아요와 서버 코멘트 UI는 없음

F11의 하단 React 3탭은 메인 4탭과 다른 컴포넌트다.

## 8. 현재 브리프에서 제외하는 흐름

아래는 코드 파일이나 제품 구상에 일부 흔적이 있어도 현재 사용자가 도달할 수 없다.

- 첫 진입 튜토리얼: `tutorial.js`가 `app.html`에 연결되지 않음
- 메인 부모↔자녀 계정 전환
- 온보딩·가족 초대·법정대리인 동의
- 지정가 자동 체결
- 과거 시즌 비교와 시즌 결산 카드
- 피드 좋아요·서버 코멘트·코멘트 삭제
- 차트 마커 클릭·피드 카드 딥링크

## 9. AS-IS 산출물 목록

현재 구현을 화면 산출물로 정리할 때 필요한 상태는 다음과 같다.

1. 홈
2. 종목 탐색
3. 종목 상세
4. 차트
5. 뉴스 상세
6. 매수 1·2·3단계와 완료
7. 매도 1·2·3단계와 완료
8. 포트폴리오
9. 랭킹
10. 아카이브 4탭
11. F10 닫힘·열림·거절 상태
12. F11 자녀 기준·부모 기준·코멘트 차단 상태

빈 상태가 실제로 존재하는 화면은 빈 상태도 별도 산출물로 포함한다. 미구현 흐름을 현재 화면처럼 그리지 않는다.
