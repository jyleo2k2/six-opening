# 모의투자 종목 유니버스 데이터셋 설계

## 1. 기준과 범위

- [사실] 이 문서는 사용자가 확정한 13개 섹터, 51개 종목을 모의투자 유니버스로 사용한다.
- [사실] 이 목록은 투자 추천이 아니라 데모에서 탐색·설명·모의주문에 사용할 고정 대상 목록이다.
- [확정] ETF, ETN, 레버리지·인버스 상품, 파생상품, 공매도·신용·미수 대상은 이 데이터셋에 포함하지 않는다.
- [가정] 한 회사에 여러 상장 종목이 있으면, 별도 결정 전까지 대표 보통주 1개만 포함한다.

기존의 “50종 [잠정]” 표기는 이 목록의 실제 합계인 **51종 [확정]**으로 대체한다. ETF는 별도 2단계 검토 대상이다.

## 3. 데이터는 세 층으로 분리한다

종목의 정체성, 시세, 데모 행동 데이터를 한 파일에 섞지 않는다. 화면과 챗봇은 필요한 층만 가져간다.

```text
종목 마스터(stock master) ──┬→ 탐색·종목 상세·챗봇의 회사 설명
                             ├→ 시세 API 요청의 종목코드
                             └→ 주문·보유·로그의 종목 식별자

시세 스냅샷(quote cache) ────→ 현재가·등락·차트 표시
데모 시드(seed) ────────────→ 초기 보유·거래 로그·시연 시나리오
```

### A. 종목 마스터: 버전 관리하는 정적 데이터

권장 위치는 `web/shared/data/stocks.ts`다. 51개가 작고 변경 빈도가 낮으므로, MVP에서는 DB보다 타입이 있는 정적 배열이 적합하다.

```ts
export type StockMaster = {
  id: string;                 // 내부 불변 식별자: "KRX:005930" 형식
  symbol: string;             // 시세 API에 넘길 거래소 종목코드
  name: string;               // 화면 표시명
  searchAliases: string[];    // 띄어쓰기·약칭·영문 표기 검색용
  sector: SectorKey;          // 아래 13개 키 중 하나
  companySummary: string;     // 아이 눈높이의 한 줄 사실 설명
  market: "KOSPI" | "KOSDAQ";
  isActive: boolean;          // 상장폐지·거래정지 등 운영 제외 처리
  displayOrder: number;       // 섹터 안의 고정 노출 순서
};
```

`id`는 주문, 보유, 검색 이벤트, F3 근거 기록, F9 성향 계산에서 공통으로 사용한다. 회사명은 바뀔 수 있으므로 식별자로 사용하지 않는다.

### B. 시세 스냅샷: API 응답과 캐시 데이터

시세는 마스터와 분리해 `app/api/quote/[symbol]`을 통해서만 가져온다. 클라이언트가 외부 시세 API를 직접 호출하지 않는다.

```ts
export type QuoteSnapshot = {
  symbol: string;
  price: number;
  change: number;
  changeRate: number;
  asOf: string;               // 조회·기준 시각 ISO 문자열
  source: "kiwoom" | "fixture";
};
```

API 장애나 발표 시연에는 마지막 정상 응답 또는 `fixtures` 데이터를 사용한다. 과거 차트 데이터도 종목 마스터와 별개로 관리한다.

### C. 데모 시드: 시연용 거래·보유 데이터

`web/shared/data/seed` 또는 `fixtures`에 둔다. `stockId`로 마스터를 참조하고, 회사명·섹터·시세를 중복 저장하지 않는다.

```ts
type DemoTrade = {
  stockId: string;
  side: "buy" | "sell";
  quantity: number;
  unitPrice: number;
  executedAt: string;
  reasonTag: string;
  confidence: 25 | 50 | 75 | 100;
};
```

## 4. 섹터와 검색 표준

섹터 값은 UI 라벨과 분리된 고정 키를 사용한다. 그러면 디자인 문구가 바뀌어도 데이터·통계·필터가 깨지지 않는다.

```ts
type SectorKey =
  | "game"
  | "logistics"
  | "semiconductor"
  | "defense"
  | "food"
  | "energy"
  | "entertainment"
  | "retail"
  | "finance"
  | "automotive"
  | "shipbuilding"
  | "airline"
  | "cosmetics";
```

검색은 `name`과 `searchAliases`를 공백·대소문자 없이 비교한다. 예를 들어 `JYP Ent.`는 `JYP`, `JYP엔터`, `JYP Ent`를 별칭으로 두되, 화면의 공식 표시는 원본 표기 하나로 고정한다.

## 5. 입력·검증 절차

1. **원본 목록 고정**: 이 문서의 섹터·종목·합계 51개를 변경 기준으로 삼는다.
2. **종목코드 검증**: 각 회사의 대표 보통주인지, 거래소 종목코드·시장구분이 맞는지 신뢰할 수 있는 거래소·증권사 데이터로 확인한다.
3. **이름·별칭 정규화**: 공식 표시명, 검색 별칭, 브랜드명과 법인명 차이를 검토한다.
4. **한 줄 설명 작성**: 회사가 하는 일을 사실 중심의 쉬운 문장으로 작성한다. 매수 근거·성장 전망·수익률 표현은 넣지 않는다.
5. **중복 검사**: `id`, `symbol`, `name`, `displayOrder`가 중복되지 않는지 검사한다.
6. **연동 검사**: 51개 모두 검색 결과·종목 상세·시세 fixture를 만들 수 있는지 확인한다.

종목코드와 시장구분은 시점에 따라 변경될 수 있어 이 문서에 추정값으로 적지 않는다. 검증을 마친 값만 `stocks.ts`에 입력한다.

## 6. 완료 기준

- 13개 섹터와 51개 종목이 마스터 데이터에 각각 한 번씩 존재한다.
- 모든 종목에 검증된 `id`, `symbol`, `market`, 한 줄 사실 설명, 검색 별칭이 있다.
- 검색 결과와 주문·보유·거래 로그가 `stockId` 하나로 연결된다.
- fixture 시세가 없어도 종목 탐색과 회사 설명은 동작한다.
- 챗봇은 마스터의 `companySummary` 같은 사실 데이터만 인용하며, 종목 추천·매매 시점·목표가·수익률 전망을 생성하지 않는다.
