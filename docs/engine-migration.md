# 테스트 후 게임 엔진 교체

> 작성일: 2026-08-05
> 전제: Phase 1 재미 검증이 끝난 뒤의 이야기. 검증 전 엔진 교체는 인프라 비용 선지불이라 금지.

## 1. 교체 비용의 구조 — 왜 "큰 노력이 안 드는가"

지금 아키텍처는 룰과 화면이 완전히 분리되어 있다.

```
game/src/    (룰 엔진, 순수 TS)   ← 유일한 룰 소스. 시뮬레이터·테스트·UI가 공유
game/ui/src/ (렌더링, React DOM)  ← 엔진을 import해서 그리기만 함
```

`game/ui`는 엔진의 함수 8개(`createGame`, `startTurn`, `playCard`, `legalPlays`,
`marketPhase`, `resolveTimeout`, `assets`, `holdingsValue`)만 호출한다.
엔진 교체란 실제로는 **이 8개 호출을 새 렌더러에서 다시 하는 것**이고, 룰·밸런스·봇·시뮬레이터는 전부 그대로 남는다.

| 갈아탈 곳 | 룰 엔진 | UI | 총비용 감 |
|---|---|---|---|
| TS 계열 (Phaser, PixiJS, Cocos Creator) | **그대로 import** | 재작성 (~수일) | 낮음 |
| C#/GDScript 계열 (Unity, Godot) | **포팅 + 이후 이중 유지보수** | 재작성 | 높음. 포팅 자체보다 "밸런스 패치마다 두 벌 수정"이 진짜 비용 |

따라서 원칙: **언어 경계를 넘지 않는 한 교체는 싸다.** 넘는 순간 룰 소스가 둘이 되고, 11절 검증 루프(셀프플레이 시뮬)가 흔들린다.

## 2. 교체를 고려할 트리거

- 카드 연출(날아가기·파티클·시장 충격 임팩트)이 CSS/Framer Motion 한계에 닿음 → **PixiJS 이펙트 레이어** 부분 채용 (교체 아님)
- 모바일 앱스토어 출시 결정 (Phase 3) → Cocos Creator 또는 Capacitor 웹뷰 포장 검토
- 실시간 PvP + 네이티브 성능 요구 → 그때 Unity/Godot, 룰 서버는 TS 유지(서버 권위) 전제

## 3. AI 친화성 비교 (2026-08 기준)

"AI 친화적" = 코딩 에이전트가 잘 다루는가. 기준: 학습 데이터 양, 텍스트 기반 워크플로(에이전트가 파일만 만져서 작업 가능한가), 헤드리스 실행·테스트 용이성.

| 엔진 | 언어 | AI 친화성 | 근거 |
|---|---|---|---|
| **React DOM (현재)** | TS | ★★★★★ | 학습 데이터 최다. 전부 텍스트 파일, 헤드리스 테스트(Playwright·vitest) 완비. 에이전트가 화면을 스크린샷으로 검증 가능 |
| **Phaser** | TS | ★★★★☆ | 코드만으로 씬 구성(에디터 없음), 문서·예제 방대. 다만 캔버스 내부 상태는 스크린샷 픽셀 검증으로만 확인 |
| **PixiJS** | TS | ★★★★☆ | 순수 코드 렌더러라 에이전트 작업 쉬움. 게임 프레임워크가 아니라 직접 짜야 할 게 많음 |
| **Godot** | GDScript | ★★★☆☆ | .tscn/.gd가 텍스트라 diff·패치 가능, 헤드리스 CLI 있음. 학습 데이터는 Unity보다 적으나 증가 중 |
| **Cocos Creator** | TS | ★★☆☆☆ | 언어는 TS지만 에디터 중심 워크플로(.scene 바이너리성 메타)라 에이전트가 화면을 못 만짐. 중국어 자료 비중 높음 |
| **Unity** | C# | ★★☆☆☆ | 학습 데이터는 많지만 씬·프리팹이 YAML 뭉치라 에이전트가 에디터 없이 다루기 어려움. 헤드리스 테스트 무거움 |

결론: **AI 에이전트와 페어로 개발하는 동안은 지금 스택(React DOM, 필요시 +PixiJS)이 최적.**
엔진을 옮겨도 Phaser까지가 에이전트 생산성을 유지하는 마지노선이다.

## 4. 권장 경로

```
Phase 1 (지금)   React DOM            ← 재미 검증, 에이전트 생산성 최대
Phase 2          + Framer Motion      ← 카드 연출. 부족하면 이펙트만 PixiJS 레이어
Phase 3 (모바일) Capacitor 포장 우선  ← 웹 코드 그대로 앱스토어. 성능 미달일 때만 Cocos/Unity 검토
```

어느 경로든 불변 조건: `game/src`가 유일한 룰 소스, `npm test` + `npm run sim`이 매 빌드 통과.
