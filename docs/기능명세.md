## 2. 실제 런타임 구조

```text
Next.js /
└─ web/app/page.tsx
   └─ ConnectedPrototype
      ├─ iframe: /ui/app.html?runtime=1
      │  ├─ 홈·탐색·상세·뉴스·매수·매도·포트폴리오·랭킹·아카이브
      │  └─ iframe: /tradingview-chart (종목 차트 화면에서만)

      └─ F11 FeedScreen
```

### 2.1 사용자 라우트

## 5. 주문·기록 흐름

### 5.1 매수

1. 시장가 또는 지정가와 금액/수량을 고른다.
2. 6개 매수 이유 중 하나를 고르고 메모를 선택 입력한다.
3. 4개 보유 계획 중 하나를 고른 뒤 주문한다.
4. 정규장 시장가는 즉시 체결한다. 장외 시장가는 현금을 예약한 `scheduled` 기록을 만들고 다음 거래일의 확인된 일봉 시가로 체결한다. 지정가는 현금을 예약한 pending 기록만 만든다.

현재 매수 이유는 뉴스·차트·익숙함·랭킹·주변 의견·직감 6개다. 계획은 단기·시즌·목표가·미정 4개다. **확신도 입력은 없다.** 목표가는 사용자가 스스로 적는 보유 계획이며 AI 추천 목표가가 아니다.

### 5.2 매도

1. 시장가 또는 지정가와 금액/수량을 고른다.
2. 6개 매도 이유 중 하나를 고른다.
3. 기존 계획 준수 여부를 기록하고, 계획과 다르면 5개 변경 이유 중 하나를 고른다.
4. 정규장 시장가는 즉시 반영한다. 장외 시장가는 수량을 예약한 `scheduled` 기록을 만들고 다음 거래일의 확인된 일봉 시가로 체결한다. 지정가는 pending 기록을 만든다.

장외 시장가 예약은 주문 접수와 실제 체결을 분리한다. 휴일·거래정지·시가 데이터 미확인 때는 예약을 유지하고, 같은 주문을 중복 체결하지 않는다. 금액 매수는 예약 금액 전부를 시가 기준 소수 수량으로 바꾸며, 수량 매수는 시가 상승으로 예약 금액을 넘으면 거절하고 현금을 돌려준다. 매도 예약과 지정가 매도는 보유 수량에서 사용 가능 수량만 잠그며 취소 시 자산 총액이 변하지 않는다. 지정가 주문은 자동 체결되지 않는다.

## 6. 저장과 서버 동기화

### 6.1 브라우저 즉시 상태

`app.html`은 `kw_proto_v1`에 다음 값만 저장한다.

- 계정별 현금·보유
- 매수·매도 기록
- 행동 이벤트와 배지
- 시퀀스와 관심 종목

현재 화면, 선택 계정, 작성 중 주문, 스쿨락 개발 설정은 영속화하지 않는다.

### 6.2 서버 연결

| 흐름 | 현재 동작 |
|---|---|
| `/api/account` | DB 사용자를 찾는 데만 사용. 서버 잔고·보유로 화면을 초기화하지 않음 |
| `/api/trade` | DB 사용자와 현재 역할이 맞는 시장가 체결만 best-effort 전송. 실패해도 로컬 체결을 되돌리지 않음 |
| `/api/tab-view` | 매수 전 10초 이상 본 탭 수를 집계 전송 |
| `/api/profile` | 브라우저 계정 상태·행동을 보내 자녀/부모 스냅샷과 서술을 계산 |
| `/api/auth/login`, `/api/auth/switch` | 구현돼 있으나 현재 프론트가 호출하지 않음 |

즉, 현재 데모의 체감 원본은 브라우저 상태이고 서버는 일부 기능에만 연결되어 있다.

## 7. F9 계산과 표시

아카이브 탭은 **성향·수익률 두 개**이고, 성향 탭에서 카드 모아보기·카드 상세·가족 성향 비교 오버레이 셋이 열린다.

계산 엔진은 **이관 중이라 두 벌**이다. 화면이 지금 쓰는 것은 구버전 `shared/engine/archive-profile.js`이며, 앞으로 갈 정본은 `shared/engine/behavior-profile.ts`다. 새 산식을 한쪽에만 넣지 않는다.

| 경로 | 무엇을 주나 |
|---|---|
| `shared/engine/archive-profile.js` | 화면이 `localStorage["kw_proto_v1"]`로 직접 계산하는 다섯 축(0~100)·캐릭터·정확 레벨 |
| `GET /api/profile/behavior` | 로그인 세션의 `stock_tab_views`·`transactions` 집계로 **캐릭터 카드만** 다시 정한다 |
| `GET /api/profile/season-cards` | 로그인 세션의 Supabase 매수를 KST 주 단위로 묶은 지난 주차 카드 |
| `POST /api/profile` | 브라우저 상태+시드로 누적 스냅샷·주간 카드·선택적 Luna 서술 |
| `GET /api/family` | 실제 가족 구성원과 누적 성향 (가족 비교 오버레이) |

- 유효 정보 확인: 매수 전 10초 이상 본 서로 다른 탭 수
- 집중/분산: 보유 섹터 수와 현금 비중
- 정확: 구버전은 체결 후 **5거래일**, 신버전 정본은 **2거래일** 종가 비교
- 매수 표본이 3건 미만이면 분석 데이터가 부족한 상태로 본다.

현재 UI는 엔진의 `level` 대신 존재하지 않는 `starGrade`를 읽어 별 표시가 비고, 캐릭터 데이터에 없는 `emoji`를 읽어 이모지가 비어 있다. 가족 비교의 동의 문구는 실제 동의 데이터가 아닌 고정 문구다. 상세 계산은 F9 SPEC을 따른다.

## 8. F11 피드와 차트 마커

- 피드: `GET /api/family`가 세션 사용자와 같은 `family_tag`의 구성원·Supabase 체결을 최신순으로 준다. 로컬 시드 피드와 `kiwoom-family-feed` 저장소는 제거됐다
- 차트 마커: `/api/trades`가 돌려주는 Supabase 거래만 사용
- 코멘트·좋아요: `/api/comments`·`/api/likes`를 통해 DB에 저장한다. 좋아요는 가족 전체 개수와 본인 선택 상태를 유지하고, 코멘트는 본인 것만 삭제할 수 있다
- 타인 카드의 수량·체결가는 서버 응답 단계에서 `null`로 마스킹한다
- 부모→자녀 코멘트의 추천·타이밍·훈계·채점 표현은 서버가 저장 전에 차단한다
- 같은 피드가 F11 React 오버레이와 아카이브 수익률 탭 두 곳에 있으며 **둘 다 같은 API를 쓴다**
- `종목 자세히 보기`: 종목 상세로 이동

피드와 차트가 이제 같은 거래 원본(Supabase `transactions`)을 본다. 상세 계약은 F11 SPEC을 따른다.

## 9. 현재 도달 가능한 골든 패스

1. `/` 홈에서 가족 순위와 자녀 자산을 본다.
2. 모의투자 탭에서 종목을 탐색하고 상세 탭을 10초 이상 확인한다.
3. 상세에서 키웅이를 열어 허용 질문을 묻는다.
4. 정규장에는 매수 화면에서 시장가·금액, 이유, 보유 계획을 선택해 즉시 체결한다. 장외에는 같은 주문이 다음 거래일 시가 예약으로 접수되는지 확인한다.
5. 포트폴리오와 아카이브에서 새 로컬 거래가 반영됐는지 본다.
6. 가족 기록을 열어 자신의 거래와 가족 시드를 확인하고 코멘트를 남긴다.
7. 종목 이동 버튼으로 해당 종목 상세가 열리는지 확인한다.

메인 부모 전환, 튜토리얼, 지정가 자동 체결, 실제 시간외 거래, 피드 좋아요, 서버 코멘트 동기화는 이 골든 패스에 넣지 않는다.

## 10. 문서화된 현재 제약

1. 정적 `app.html`이 주요 UI와 상태를 함께 소유해 기능 폴더 경계와 다르다.
2. 로컬 체결 성공과 서버 저장 성공이 원자적으로 묶여 있지 않다.
3. 메인 부모 계정 전환 UI가 없어 부모 단독 화면을 사용자 흐름으로 열 수 없다.
4. 이름, F9 표시 필드, F11 이동 문구가 코드 내부에서도 서로 어긋난다.
5. F11 시장가 매도 금액 표시에는 확인된 결함이 있다.
6. 저장소 안에서 거래·계정·반응 API가 기대하는 전체 Supabase 스키마 마이그레이션을 확인할 수 없다.
