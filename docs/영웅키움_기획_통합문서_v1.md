## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 서비스명 | **영웅 키움** — 키움증권이 투자자를 '영웅'이라 부르는 데서 착안. 미래의 영웅(자녀)을 '키운다'는 중의적 의미 |
| 한 줄 소개 | **성장 발자취가 남는 가족 단위 모의투자 플랫폼** (어린이 눈높이) |
| 형태 | 신규 앱이 아니라 **기존 키움 MTS 내 신규 메뉴로 이식.** 메뉴 진입 시 전용 화면 세트로 전환 |
| 궁극적 목표 | 키움증권에 계좌 있는 부모의 자녀를 잠재고객으로 보고, ① 미성년 계좌 개설을 유도하고 ② 투자 습관을 길러주며 ③ 잠재고객을 키움증권의 **장기고객으로 전환**한다 |
| 사용자가 얻는 것 | 어린 자녀의 투자 습관 형성, 주식 투자에 대한 친숙함·익숙함 |

## 2. 문제 정의 & 페인포인트

### 사용자 페인포인트

> **부모는 자녀가 비교적 안전한 환경에서 주식 투자를 경험해보고, 투자 습관을 기르게 해주고 싶은데 — 마땅한 플랫폼이 없다.**

- 기존 MTS·모의투자는 성인 기준의 용어·화면·정보량이라 아이가 쓸 수 없다
- 부모가 직접 가르치자니 방법론이 없고, 교육 콘텐츠와 실제 '해보는 경험'이 연결된 도구가 없다

### 문제 정의의 레이어 분리

| 층위 | 주체 | 내용 |
|---|---|---|
| 사업 배경 | 키움 | 초중등 자녀 세대는 미래 잠재고객이나, 이들과의 접점·브랜드 경험이 없음 |
| 🔴 사용자 페인 | 부모 | 자녀에게 안전한 투자 경험을 시켜줄 플랫폼이 없다 |
| 서비스 목표 | — | 자녀가 안전한 환경에서 투자 습관을 기르고 주식·키움에 친숙해진다 |
| 비즈니스 목표 | 키움 | 미성년 계좌 개설·활성화 → 가족 단위 이용 → 장기고객 전환 |

## 3. 타겟 & 페르소나

| 구분 | 대상 |
|---|---|
| 핵심 타겟 | **키움증권 계좌를 개설한 초·중등 자녀의 부모** 중, 자녀에게 주식투자 경험을 시켜주고 싶은 부모 — 그리고 그 자녀들 |
| 사용 주체 | 자녀(모의투자 플레이어) + 부모(함께 참여하는 가족 구성원이자 법정대리인) |

### 페르소나

**① 부모 (43세)**
키움증권 계좌 보유, 종종 주식 매매를 한다. 자녀가 안전한 플랫폼에서 미리 주식 투자를 경험해보고, 주식·투자에 친숙해지고 투자 습관과 경제 관념을 갖게 해주고 싶다.

**② 자녀 (2014년생, 13세, 초6)**
부모와 함께 체험해보는 것을 좋아한다. 아직 경제·투자·주식이 뭔지 잘 모르고 어려워한다.

## 4. Why 키움 (사업 배경)

- 현재의 초중등 세대는 키움의 **미래 잠재고객** — 그러나 접점이 없다
- 어릴 때부터 키움 모의투자 플랫폼에 노출되면 주식 투자와 키움증권 브랜드에 친근함을 형성
- 성인이 되어 본격적인 매매 유저로 성장할 때, **첫 투자 경험과 성장 기록이 전부 키움 안에 있는 상태**가 됨 → 장기고객 전환의 토대
- 미성년자 비대면 계좌 개설 인프라를 키움이 이미 보유(→ §12) → **기존 자산 위에 얹는 서비스**로 실현 가능성이 높음

## 5. 서비스 구조 개요

```
키움 MTS
 └─ [영웅 키움] 메뉴 (신규)
     ├─ 튜토리얼 모드  ← 계좌 없이도 개방
     ├─ 시즌 모의투자  ← 참가 조건: 자녀 명의 미성년 계좌 (§6)
     │    ├─ 가족 팀 (부모+자녀, 개인별 가상 지갑)
     │    ├─ 질문식 매매 · 화이트리스트 50종목
     │    └─ 리그 단위 가족 경쟁 (수익률 기준)
     ├─ 성장 아카이브  ← AI 분석 리포트 + 친화도 스코어 누적
     └─ 플로팅 챗봇   ← 전 화면 상시 대기
```

- **한 가족 = 한 팀**, 가족별 경쟁
- **분기별 연 4회**, 회당 **약 4주** 시즌제 (근거는 §7)
- 시즌이 반복될수록 아카이브에 가족·자녀의 성장 기록이 쌓인다 — 서비스명 '영웅 키움'의 핵심 정체성

## 6. 참가 조건 & KPI 퍼널

### 참가 조건 (확정)

> **키움증권 계좌를 보유한 부모 중, 미성년 자녀 계좌를 신규 개설했거나 이미 보유한 가족만 시즌 참가 가능.**

### 2단 퍼널 설계

| 단계 | 요구 조건 | 목적 |
|---|---|---|
| 튜토리얼·구경 모드 | 없음 (부모 로그인만) | 체험 전 이탈 방지 — "재밌어 보여서 계좌를 만든다"는 순서를 만든다 |
| 시즌 정식 참가 | **자녀 명의 미성년 계좌** | 계좌 개설이 자연스러운 전환 이벤트가 됨 → 전환율 측정 가능 |

### KPI 이원화 (확정)

| KPI | 정의 | 계측 지점 |
|---|---|---|
| **① 신규 미성년 계좌 개설 수** | 서비스 참가를 위해 새로 개설된 자녀 계좌 | 온보딩 내 개설 플로우 완료 시 |
| **② 기존 미성년 계좌 활성화율** | 이미 개설돼 있던(방치 상태 포함) 자녀 계좌의 첫 서비스 연결 | 기존 계좌 첫 팀 연결 시 |

> 이원화 이유: 이미 계좌를 만들어둔 가족은 '개설 수'에 잡히지 않지만, 방치 계좌를 깨우는 것 역시 키움 입장에서 동등하게 가치 있는 성과다.

보조 지표: 시즌 재참여율, 친화도 스코어 변화(§10), 튜토리얼→정식 참가 전환율.

## 7. 시즌 운영 설계

### 왜 분기별 연 4회인가

- 상장기업의 **실적 발표(어닝시즌)가 분기 주기** → 시즌을 분기에 맞추면 매 시즌 "실적이 주가를 움직이는" 실제 시장 이벤트를 한 번씩 경험하게 된다
- 학기·방학 리듬과 자연스럽게 맞음
- 회차가 끊겨야 "리셋 후 재도전"의 신규 진입 시점이 생김 → 시즌마다 신규 가족 유입 가능
- 아카이브 관점에서 **분기 단위의 비교 가능한 성장 기록** 단위가 생김

### 왜 회당 4주인가

- 하루 이틀이면 '찍기'가 되고, 한 학기짜리면 아이의 집중력이 유지되지 않음
- 4주는 최소 한 번의 등락 사이클을 견디며 **"기다리는 경험"**을 하게 되는 길이
- 용돈 주기(월 단위)와 일치 — 아이의 돈 감각 단위와 맞음

### 시즌 캘린더

```
[모집·연습 1주] → [본 경쟁 4주] → [결산 1주]  × 연 4회
```
- 본 경쟁 4주를 어닝시즌에 걸치도록 배치
- 시즌 오프 기간에도 튜토리얼·연습 모드는 상시 개방

### 시드 & 경쟁 규칙 (확정)

| 항목 | 내용 |
|---|---|
| 시드 | **구성원 1인당 동일 가상 금액 지급** — [제안] 100만원 (아이 돈 감각을 위해 용돈 스케일) |
| 지갑 구조 | **개인별 가상 지갑** — 부모·자녀 각자 운용. 가족 공동 통장 아님 |
| 가족 성적 | **구성원 수익률 평균** — 전원 시드가 같으므로 가족 총자산 수익률과 수학적으로 동일 |
| 실잔액 연동 | **하지 않음** — 자산 격차 노출·프라이버시·구현 복잡도 문제. 현실감은 금액이 아니라 실시간 시세·체결 경험에서 나온다 |
| 시즌 종료 시 | 가상 자산 전액 리셋. 남는 것은 아카이브의 기록 |

**개인별 지갑이어야 하는 결정적 이유:** 공동 통장이면 사실상 부모가 주도하게 되고, 자녀 행동 데이터가 부모와 섞여 **질문식 매매 분석과 친화도 ML 스코어 산출이 불가능**해진다. 데이터 기능 두 개가 이 구조를 강제한다.

### 공정성 설계

- 비교는 금액이 아니라 **수익률** — 5인 가족(총 500만)과 3인 가족(총 300만)이 공정하게 경쟁
- 통계적 특성: 인원이 많을수록 평균 수익률이 중간으로 수렴(극단값이 어려움) → 완화 장치:
  - **[제안] 참가 인원 상한: 부모 1 + 자녀 1 필수, 최대 4인**
  - 시상 다각화(§8 STEP 3)로 대가족도 가져갈 상을 보장
- **리그 분할**: [제안] 30~50가족 단위 리그로 묶어 "우리 리그 4위" 같은 체감 가능한 경쟁 단위 제공 (전체 순위는 대부분의 가족에게 무의미)

## 8. 전체 프로세스 (STEP 0~3)

### STEP 0. 진입 & 가족 팀 결성 (모집 주간)

1. 부모가 키움 MTS 로그인 → **[영웅 키움]** 메뉴 진입 (부모 계좌 보유는 로그인으로 자동 충족)
2. **[가족 팀 만들기]** → 시스템이 부모 명의에 연결된 미성년 자녀 계좌 존재 여부 조회
   - 자녀 계좌 **있음** → 바로 연결 *(KPI ② 활성화 카운트)*
   - 자녀 계좌 **없음** → 키움 기존 미성년 비대면 개설 플로우로 안내, 완료 후 복귀 *(KPI ① 신규 개설 카운트)*
3. 자녀는 자기 기기의 MTS에서 자녀 계정으로 로그인 → 부모가 발급한 **가족 초대 코드**로 팀 합류
   - 자녀의 서비스 가입·개인정보 수집 동의는 **부모 화면 안에서 법정대리인 동의로 처리** (§12)
4. 계좌 없이도 튜토리얼·구경 모드 개방 (2단 퍼널)

### STEP 1. 시즌 개막 — 시드 지급

- 시즌 시작일, 구성원 1인당 가상 시드 일괄 지급 (개인별 지갑)
- 이전 시즌 자산 전액 리셋 — 공정성 + 신규 진입 보장

### STEP 2. 매매 진행 (본 경쟁 4주)

**자녀 화면 기준 주문 플로우:**

1. **종목 탐색** — 화이트리스트 50종목만 노출, 종목명 옆 "이 회사는 ○○를 만들어요" 한 줄 설명
2. **질문식 매매** — 주문 직전 객관식 2~3문항 (§9). 정답 없음, 기록만
3. **주문 입력** — 금액 단위 입력 지원("10만원어치" → 수량 자동 계산), 지정가/시장가 선택
4. **체결** — 실시간 시세 기반 체결 시뮬레이션. **실제 장 운영시간(09:00~15:30)에만 체결** — "시장에는 문 여는 시간이 있다"는 것 자체가 교육. 장외 시간엔 예약주문 접수
5. 전 과정에서 플로팅 챗봇 상시 대기 (§11)

**진행 중 피드백:**

- **주간 중간순위** — 매주 월요일 갱신 알림. *일간이 아닌 이유: 일 단위 등락에 일희일비하는 단타 습관을 유도하지 않기 위해*
- **가족 내부 비교 화면** — "아빠 +3.2% vs 나 +5.1%" → 가족 대화 트리거
- 리그 단위 순위 제공

### STEP 3. 시즌 결산 (결산 주간)

1. 마지막 거래일 종가로 수익률 확정 → 가족 성적 산출
2. **시상 다각화** — 수익률 1등만 상 받는 구조 금지:
   - 🏆 가족 종합 (리그별 수익률 1위)
   - 🧒 개인 부문 (자녀 중 최고 수익률)
   - 🧭 행동 부문 [제안]: 분산투자상(몰빵 없이 운용) / 진득이상(평균 보유기간 최장) / 질문왕(챗봇에 좋은 질문 최다)
3. **보상은 비금전** — 뱃지·칭호·아카이브 트로피 (미성년 대상 금전·실물 보상은 사행성 리스크, §12)
4. **AI 아카이브 리포트 발행** + 친화도 스코어 갱신 (§10)
5. 다음 시즌 예고 + "지난 시즌의 나" 회고 카드 → 재참여 루프

## 9. 핵심기능 ① 모의투자

### 튜토리얼 모드

- 매수·매도·시장가·현재가·차트 등 **기본 버튼·용어를 화면 위에서 직접 설명**
- 계좌 없이 개방 (전환 퍼널의 입구)

### 화이트리스트 50종목

- 비교적 안전한 우량주로 구성된 **국내 기업 50개** (선별 완료)
- 미수·신용·레버리지·파생 등 위험 거래는 구조적으로 존재하지 않음 — "안전한 환경"의 실체

### 질문식 매매 — 이 서비스의 데이터 심장

주문가·수량만 입력하는 게 아니라, 주문 과정에 **간단한 객관식 질문**이 함께 나온다.

예시 문항 [제안]:
- "왜 사고 싶어요?" — 뉴스를 봐서 / 써본 물건·아는 회사라서 / 가족이 추천해서 / 느낌이 좋아서
- "얼마나 가지고 있을 생각이에요?" — 이번 주만 / 시즌 끝까지 / 모르겠어요

설계 원칙:
- **정답 없음, 평가 없음** — 아이의 의사결정 과정을 스스로 인식하게 하는 것이 목적
- 응답은 전부 기록됨 → AI 분석(§10)의 구조화된 원료. **다른 팀이 가질 수 없는 데이터 자산**
- 문항은 2~3개로 짧게 — 주문 흐름을 막는 순간 아이는 떠난다

## 10. 핵심기능 ② 성장 아카이브 & 친화도 ML 스코어

### 아카이브

- 시즌 종료 시 해당 회차 자녀의 투자 내용을 **AI가 분석** — 질문식 매매 응답 + 매매 로그(+수익률 등) 활용
- 시즌 반복 참여 → 데이터가 누적 → **가족과 자녀의 성장 아카이브**로 발전
- 서비스명의 유래: 키움은 투자자를 '영웅'이라 부른다 — 이 아카이브가 미래의 영웅을 '키운' 기록

### 친화도 ML 스코어 (명칭 미정)

주식투자에 대한 친화도·관심도를 머신러닝으로 산출하고, **서비스 이용 전후로 스코어가 상승하는 것을 보여주는 것**이 목표.

**라벨(정답) 설계 — 두 가지 안:**

| | A안 (권장): 재참여 예측 모델 | B안: 설문 라벨 회귀 |
|---|---|---|
| 라벨 | 다음 시즌 재참여 / 접속 지속 여부 | 시즌 시작·종료 시 아이·부모 리커트 설문 |
| 스코어 정의 | 투자 활동을 지속할 확률 | 행동 로그로 설문 점수를 예측 |
| 강점 | 라벨이 데이터 안에 실재, 논리가 깔끔 | "친화도"라는 개념과 직접 대응 |
| 약점 | — | 프로젝트 기간 내 실제 응답 수집 불가 |

**피처 설계 원칙 — 순환 논리 금지:**
- 사용량 지표(접속 횟수·매매 횟수) 위주로 구성하면 "많이 쓰면 오르는 점수"가 되어 전후 상승이 동어반복이 됨
- 스코어의 무게는 **질적 지표**에: 질문식 매매에서 근거 있는 선택 비율, 분산투자 여부, 평균 보유 기간, 스스로 챗봇에 한 질문 수 등

**정직성 원칙:**
- 실사용자 데이터가 없으므로 발표의 전후 상승 그래프는 **가상(시뮬레이션) 데이터임을 명시** — "측정 체계를 이렇게 설계했고, 가상 시나리오에서 이렇게 나타난다"로 프레이밍
- 노출 이원화 [제안]: 아이에게는 숫자 대신 레벨·뱃지(점수 낙인 방지), 부모 리포트에만 상세 수치

## 11. 핵심기능 ③ 행동패턴 기반 플로팅 챗봇

### 트리거 — 챗봇이 먼저 말을 건다

- 주식이 낯선 아이들은 "뭘 모르는지도 모른다" → 질문을 기다리지 않고 **행동패턴 감지로 선제 개입**
- 규칙 예: **한 화면에서 5분 이상 정지** 등 사전 정의된 룰 감지 → 플로팅 버튼이 말풍선으로 *"고민이 있나요?"*
- 채팅 진입 후: "금리 인상이 뭐야?" "삼성전자 관련 뉴스 있어?" 등 자유 질문 → 어린이 눈높이 답변

### 절대 금지 규칙 (레드라인이자 규제 방어 장치)

> **주가 예측·매매 판단 답변 절대 금지.**

- "삼성전자 오를까?" "하이닉스 팔까?" 류 질문 → 예측·판단 대신:
  > *"그 부분은 내가 대답할 수 없어. 다만 삼성전자의 최근 소식을 알려줄게!"* → 최근 시황을 어린이 눈높이로 설명
- 이 규칙은 UX 원칙인 동시에, 챗봇이 매매 판단을 제공할 경우 발생하는 **투자권유·투자자문 소지를 차단하는 규제 방어 장치**

## 12. 법적·규제 검토

> 발표 프레임: **"저희는 규제를 우회하지 않았습니다. 법정대리인 동의가 필요하다는 사실이 저희 온보딩의 출발점입니다 — 부모가 시작하고, 부모가 동의하고, 부모가 초대합니다."**

### ① 미성년자 계좌 개설 (민법상 법정대리)

- 미성년자는 본인이 증권계좌를 개설할 수 없고 **법정대리인이 대리 개설**
- **키움증권은 2023년 4월부터 영웅문S#에서 미성년자 비대면 계좌개설을 이미 지원** — 부모가 정부24 발급 가족관계증명서·기본증명서의 발급번호 진위확인으로 앱 안에서 개설 완료 (출처: 머니투데이 2023-04-20 보도)
- → 우리 온보딩의 "계좌 없음 → 개설 안내"는 **키움의 기존 비대면 개설 플로우에 연결만 하면 됨.** 신규 인프라 불필요 = 실현 가능성 근거

### ② 만 14세 미만 아동 개인정보 (개인정보보호법 제22조의2)

- 만 14세 미만 아동의 개인정보 처리에는 **법정대리인 동의 + 동의 여부 확인 의무**
- 우리 구조의 대응: **자녀가 스스로 가입하는 경로가 애초에 없다**
  - 부모가 먼저 팀을 만들고 초대 코드를 발급하는 구조 → 자녀의 가입·개인정보 수집 동의를 **부모 MTS 화면 안에서 처리** (법정대리인 동의가 UX에 내장)
  - 부모는 이미 키움 실명확인 고객 → "동의자가 진짜 법정대리인인가" 확인 문제까지 해결
- 만 14세 이상 미성년자는 개인정보 동의는 본인 가능하나 계좌는 어차피 법정대리인 개설 → **전 연령 부모 개시 플로우로 통일**

### ③ 추가 대응 사항

| 이슈 | 대응 |
|---|---|
| 행동 데이터 수집 (친화도 스코어·챗봇 트리거) | 아동 행동 프로파일링이라 민감 → 수집 항목을 동의서에 명시, 부모가 자녀 리포트에서 수집 내용을 확인 가능하게 투명화 |
| 아동 대상 알림 | 마케팅 수신 동의 별도, 아동에게는 서비스 필수 알림(시즌 일정 등)만 보수적으로 |
| 챗봇 | 주가 예측·매매 판단 금지 규칙(§11) = 투자권유·자문 소지 차단 |
| 시즌 보상 | 미성년 대상 금전·실물 보상은 사행성 리스크 → **비금전 보상 원칙** (뱃지·칭호·트로피) |
| 모의투자 자체 | 실거래가 아니므로 금융거래 규제 부담 낮음. 단, 실거래로 오인되지 않도록 화면에 '모의투자' 명시 |

## 13. UI/UX 원칙

- 기존 키움 MTS와 유사한 UI 골격 — 단, 어린 자녀가 쓴다는 전제에서 **더 쉽고, 귀엽고, 예쁜 아이 친화적 스타일**
- 일반 주식투자 화면 대비 **간결한 문구·간단한 화면 구성** (정보량 다이어트)
- 금액 단위 입력 지원 — 아이에게 "8만2천원 × 3주" 계산을 시키지 않는다
- 참고 리소스: [nextlevelbuilder/ui-ux-pro-max-skill](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) (kid-친화 UI 가이드)
