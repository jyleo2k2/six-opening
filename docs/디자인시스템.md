# 디자인 시스템 — 현재 구현 기준

> 갱신: 2026-08-16 · 기준: PR #294까지 병합된 `main`의 `web/app/globals.css`, `web/features/f0-home/`, `web/features/f10-chatbot/`
>
> 이 문서는 **지금 화면이 실제로 무엇을 쓰는지**를 적는다. 새 React UI가 따라야 할 토큰과 규칙은 §2·§4에 있고, 옮겨 온 화면이 그 규칙을 아직 안 따르는 사실은 §1·§8에 그대로 적는다.

## 1. UI 표면이 두 개다 — 다만 경계가 바뀌었다

**화면 해체(PR #254)로 `app.html`은 더 이상 사용자 화면을 그리지 않는다.** 예전 이 문서가 적었던 "메인 앱 = iframe 정적 HTML"은 폐기다. 지금 갈리는 것은 HTML과 React가 아니라 **같은 React 안의 두 스타일 계약**이다.

| 표면 | 소유 | 스타일 방식 | 실측 |
|---|---|---|---|
| 옮겨 온 앱 화면 | `web/features/f0-home/` — 홈·탐색·상세·차트·뉴스·주문·계좌·랭킹·아카이브 | **프로토타입 인라인 스타일 그대로.** CSS 선언 문자열을 `lib/css-style.ts`의 `styleFromCss`가 객체로 바꿔 넣는다 | `className` 5곳 vs 인라인 hex 399곳 |
| F10 챗봇 UI | `web/features/f10-chatbot/` | `globals.css`의 Tailwind `@theme` 토큰 | `className` 65곳 |

- **인라인 스타일은 실수가 아니라 이관 방식이다.** 선언이 화면당 수십 개라 손으로 객체로 옮기면 값이 조용히 어긋난다. 그래서 문자열을 원본 그대로 옮기고 변환은 `styleFromCss` 한 곳에서만 한다. 토큰화는 이관과 분리된 별도 작업이다.
- 그러므로 **옮겨 온 화면을 고칠 때 "토큰을 쓰라"고 요구하지 않는다.** 주변 시각 언어를 유지한다. 새로 만드는 React UI(F10 계열, 앞으로의 공용 조각)는 §2 토큰을 쓴다.
- `web/public/ui/app.html`은 조립 생성물이고 iframe 안에서 살아만 있다. 스타일 판단의 근거로 삼지 않는다.
- `web/design-system/`은 claude.ai/design에서 받아 온 **반입 원본**이다. 빌드에 들어가지 않고 손으로 고치지 않는다. 반입값이 이 문서와 어긋나면 이 문서를 먼저 갱신한다.

## 2. React 테마 토큰

`web/app/globals.css`의 실제 `@theme` 계약이다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `navy` | `#001E5A` | 헤더, 핵심 정보, 보조 CTA |
| `magenta` | `#D70082` | 주 CTA, 선택 상태 |
| `gray` | `#BEBEBE` | 구분선, 비활성 |
| `bg` | `#F6F7FA` | React 화면 배경 |
| `ink` | `#1A2233` | 본문 텍스트 |
| `up` | `#E8322E` | 상승·수익 |
| `down` | `#1668DC` | 하락·손실 |
| `trade-child` | `#0F8A68` | 차트의 자녀 체결 마커 |
| `trade-parent` | `#16233F` | 차트의 부모 체결 마커 |
| `shadow-card` | `0 8px 24px rgb(0 30 90 / 0.08)` | React 카드 그림자 |

흰색은 Tailwind 기본 `white`를 쓴다. 국내 증권앱 관례에 맞춰 상승은 빨강, 하락은 파랑이다. 체결 마커는 등락으로 오독하지 않도록 `trade-child`·`trade-parent`를 쓴다.

`globals.css`에는 토큰 외에 `.prototype-chat-overlay`(챗봇 오버레이의 고정 위치·클리핑 대상)만 있다. 플로팅 버튼 좌표는 `f10-chatbot/lib/floating-avatar.ts`가 인라인으로 주므로 CSS에 적지 않는다 — 적으면 인라인에 밀려 죽은 규칙이 된다.

## 3. 폰 프레임 기하 — 원본은 하나다

| 값 | 크기 | 소유 |
|---|---|---|
| 바깥 iPhone 프레임 | 450 × 920 | `f10-chatbot/lib/bottom-sheet.ts`의 `PROTOTYPE_PHONE` |
| 실제 콘텐츠 영역 | 402 × 874 (좌 24 · 상 23) | `f0-home/lib/phone-frame.ts`의 `PHONE_SCREEN` |
| 화면 라운드 | 40px | 같음 |
| 상태바 높이 | 59px (화면 `padding-top`) | `stock-chrome.tsx`·`ArchiveScreen.tsx` 등 각 화면 |

- 작은 창에서는 450×920 기준으로 **줄이기만** 한다(`phoneFrameScale`, 키우지 않는다).
- **배율을 새로 계산하지 않는다.** 챗봇 시트가 쓰는 `getPrototypeScreenRect` 값을 프레임도 그대로 쓴다. 두 기하가 갈리면 화면을 오갈 때 폰이 튀고 시트가 프레임 밖으로 나온다.
- 프레임 이미지는 `PhoneFrame.tsx`가 그리고 상태바는 `dark`/`light` 두 벌(`/ui/assets/statusbar.svg`·`statusbar-w.svg`)이다.
- 챗봇처럼 iframe **밖**에 있는 오버레이는 스태킹 컨텍스트가 갈려 z-index로 순서를 못 정한다. 그래서 `phoneScreenClipPath`로 화면 사각형에 가두고, 그 위에 프레임 이미지를 한 겹 더 깐다(`phoneFrameRect`).
- 하단 탭은 **홈 / 모의투자 / 아카이브 / 랭킹** 4개이며 `BottomNav.tsx`가 소유한다. 각각 `/`·`/explore`·`/archive`·`/ranking`으로 가고, 이동은 직접 하지 않고 `onLeave(path)`로 올린다.
- 전역 부모↔자녀 스위처는 없다.

### 애니메이션

`f0-home/phone-frame.css`가 폰 프레임 안의 keyframes를 소유한다. Pretendard 400~900 로컬 `@font-face`도 여기 있다.

| 이름 | 쓰임 |
|---|---|
| `popItem` | 홈의 목표 아이템 튀어오르기 |
| `sheetUp` | 보유 시트 올라오기 |
| `kwPop` · `kwRise` · `kwFall` | 체결 완료 화면의 마스코트 등장 · 풍선 · 색종이 |

가로 흔들림은 요소가 `--kwx` 커스텀 속성으로 넘긴다.

## 4. 형태와 타이포그래피

### 새로 만드는 React UI

- 카드: 16px 라운드, 흰 배경, `shadow-card`
- 버튼: 최소 높이 48px, 12px 라운드
- 주 버튼: magenta 배경 + 흰 글자
- 보조 버튼: 흰 배경 + navy 테두리·글자
- 칩형 버튼: 필요한 기능에서 999px 라운드 사용
- 화면 헤더: 최소 높이 78px, navy 배경, 흰 글자

### 글꼴과 숫자

- 글꼴: Pretendard → Segoe UI → Malgun Gothic → sans-serif (`globals.css` `body`)
- Pretendard 400·500·600·700·800·900 로컬 에셋을 `phone-frame.css`가 로드한다.
- 가격·수익률·수량은 가능하면 `tabular-nums`를 사용한다.

**옮겨 온 화면은 위 크기 체계를 따르지 않는다.** 화면별 인라인 수치를 그대로 들고 왔으므로, 이 체계를 전 화면에 적용했다고 설명하지 않는다.

## 5. 말투와 금융 표현

- 자녀 대상 문구는 해요체와 짧은 문장을 쓴다.
- 훈계·채점·정답처럼 들리는 표현을 피한다.
- 종목 추천, 매매 시점, AI 생성 목표가, 손절가, 수익률 전망은 금지한다.
- 사용자가 직접 세우는 보유 계획의 목표가는 허용하되 AI 조언처럼 표현하지 않는다.
- 상승·하락에는 색만 의존하지 말고 텍스트나 ▲▼ 기호를 함께 쓴다.
- 유형·캐릭터는 기간성 관찰로 표현하고 고정 낙인이나 실력 등급으로 부르지 않는다.

현재 매매 기록 화면에는 확신도 선택 UI가 없다. 관련 캡션이나 `ConfidenceSelector`를 구현 완료 기능으로 문서화하지 않는다.

## 6. 그래픽과 차트

- 키웅이: F10 플로팅 버튼과 챗봇 화면의 캐릭터. 플로팅 아바타는 `f10-chatbot/assets/floating/`의 hero 5종·villain 5종을 유휴 시간마다 교체한다.
- 영웅이: 현재 앱 공용 컴포넌트 계약이 아님
- 체결 완료 화면: `OrderScreen` 3단계가 마스코트 + 풍선 5개 + 색종이 14조각을 띄운다(§3 keyframes).
- TradingView 차트: 자녀/부모의 B·S SVG 체결 마커를 표시. 표시 전용이며 클릭 상호작용이 없다.
- F9 아카이브: 5개 능력치를 SVG 레이더(오각형)로 표시한다 — `ArchiveScreen.tsx`. "금지" 또는 "미구현"으로 설명하지 않는다.
- **판정 보류는 빈 값이 아니라 명시 상태다.** 엔진이 유형을 못 정하면 축은 중립 5, 유형은 `관찰 중`이고 캐릭터 그림 자리는 비운다 — 자리는 남겨 오각형이 움직이지 않게 한다(PR #294).

## 7. 공용 React 컴포넌트는 현재 없다

`web/shared/ui/`는 **비어 있다**(`.gitkeep`뿐). 유일한 소비자였던 F11 `FeedScreen`이 삭제되면서 함께 비었다. 예전 이 문서가 적었던 `Button`·`Card`·`TabBar`·`ScreenHeader`·`PhoneShell` 5종은 **더 이상 존재하지 않는다.**

지금 React UI는 기능 폴더가 각자 소유한다.

| 조각 | 소유 |
|---|---|
| 폰 프레임 · 하단 탭 | `f0-home/PhoneFrame.tsx` · `BottomNav.tsx` |
| 바텀 시트 기하·닫힘 문턱 | `f10-chatbot/lib/bottom-sheet.ts` (`f0-home/lib/sheet-drag.ts`가 같은 규칙을 쓴다) |
| 플로팅 버튼 | `f10-chatbot/lib/floating-avatar.ts` |

공용 승격은 **두 번째 실제 소비자가 생겼을 때** 타입·구현·테스트와 함께 검토한다. `Chip`·`PriceText`·`ProgressBar`·`CoachAvatar`·`SpeechBubble`·`ChatComposer`·`ConfidenceSelector`·`ConfettiBurst`를 공용 계약으로 문서화하지 않는다.

## 8. 현재 정합성 부채

1. **옮겨 온 화면 9개가 토큰 대신 인라인 hex 399곳을 쓴다**(§1). 토큰화는 이관과 분리된 별도 작업이며 아직 착수하지 않았다.
2. 한 폰 안에 스타일 계약이 둘이라(인라인 vs Tailwind) 챗봇과 화면의 색·크기가 어긋날 수 있다. 어긋나면 이 문서의 토큰이 기준이다.
3. `web/design-system/README.md`는 `foundations/`·`components/` 폴더 구조를 적어 두었지만 실제로는 `prototype/모의투자-화면-프로토타입.html` 한 장뿐이다.
4. 화면 사각형 실측이 아직 iframe `#kw-screen`에 묶여 있어 `app.html`을 뗄 수 없다(`docs/기술스택.md` §화면 구성).

`starGrade`·`emoji` 빈 값, F11 `TabBar`의 `/` 링크, 5축 표기는 **모두 해소됐다** — 실행 경로의 React 코드에는 남아 있지 않고 `web/design-system/`의 반입 원본 HTML에만 있다.
