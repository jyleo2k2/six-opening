# MVP 완성 조건 + 작업 백로그

> 이 문서는 자율 루프의 작업 지시서다. 매 사이클: **다음 미완료 태스크 1개 → 구현 → 검증 명령 실행 → 통과하면 체크 + 진행 로그 기록.**
> 설계 근거는 `docs/game-design.md`. 수치·룰 충돌 시 그쪽이 원본.

## 완성의 정의

**루프가 만들 수 있는 것**: 재미의 전제조건이 전부 갖춰진, 사람이 평가만 하면 되는 게임.
**루프가 만들 수 없는 것**: 재미 그 자체, 연출 감성, 아이의 실제 반응 → 아래 "사람 게이트" 참고.

### Tier 1 — 플레이 가능한 완성 (여기까지가 MVP)

T1~T8 전부 체크 + `game`의 `npm test`·`npm run sim`, `game/ui`의 `npm run e2e` 그린.

### Tier 2 — 리텐션 완성

T9~T10. Tier 1 사람 게이트 통과 후에만 착수.

### 사람 게이트 (루프가 판단하지 않는다)

- 카드 내는 맛이 있는가 / 한 판 더 하고 싶은가
- 연출·비주얼 퀄리티
- 초등 고학년이 1분 안에 첫 턴을 스스로 진행하는가 (실측)

루프는 이 지점에 도달하면 **멈추고 사용자에게 보고**한다. 추측으로 통과 처리하지 않는다.

## 불변 조건 (매 태스크마다 지켜야 함)

1. **룰은 `game/src`에만.** `game/ui`는 엔진을 import만 하고 룰을 재구현하지 않는다.
2. **회귀 그린**: 작업 후 `game`에서 `npm test`, `game/ui`에서 `npm run e2e`가 통과해야 태스크 완료.
   - e2e는 dev 서버가 먼저 떠 있어야 한다: `game/ui`에서 `npm run dev` 실행 후 별도 셸에서 e2e.
   - **함정**: 이 환경의 Vite는 IPv6(`::1`)에만 바인딩돼 `127.0.0.1` 접속이 거부된다. e2e 기본 URL이 `127.0.0.1`이므로 `$env:E2E_URL = "http://localhost:5178/"` 를 지정하고 실행할 것.
3. **교육 메시지 3종 유지**: 분산>몰빵, 정직>불법, 시그널활용>무시. `npm run sim`에서 역전되면 그 변경은 되돌린다.
4. **설계 문서 동기화**: 룰·수치가 바뀌면 `docs/game-design.md`의 해당 절과 11절 스냅샷을 갱신한다.
5. **범위 엄수**: 백로그에 없는 기능을 추가하지 않는다. 필요하다고 판단되면 백로그에 제안으로 적고 사용자 확인을 기다린다.

## Tier 1

### [x] T1. 엔진 이벤트 로그 (선행 필수 — API 변경) — 2026-08-05 완료

**왜 먼저**: 다른 모든 피드백 시스템이 여기 의존. 나중에 하면 UI를 다시 뜯어야 함.

현재 엔진은 상태만 바꾸고 "무슨 일이 일어났는지"를 알려주지 않는다. `playCard`와 `marketPhase`가 발생한 사건 목록을 반환하게 한다.

최소한 아래 사건을 구분해서 낼 것:
- 손절 예약 발동 (지킨 금액 포함)
- 섹터 이벤트 피격 (플레이어별 손익, 보유 분산도 포함 — "분산 덕분에 덜 맞음" 계산 가능해야)
- 공매도 청산 (손익)
- 금감원 조사 적발 (몰수액)
- 생활비 강제 매도
- 월드 이벤트 발동
- 승리 조건 충족

**검증**: `game`에서 `npm test` — 사건 종류별 유닛 테스트 추가, 기존 23개 그린 유지. 동일 시드 `npm run sim` 결과가 이전과 동일해야 함(순수 관측 추가이므로 밸런스 불변).

### [x] T2. 판정 피드백 UI — 2026-08-05 완료

T1의 이벤트 로그를 화면에 띄운다. 플레이어가 "내가 왜 잘했는지" 알아야 재미도 교육도 성립.

| 상황 | 메시지 예 |
|---|---|
| 쇼크 맞았는데 분산 상태 | "분산 덕분에 -25% 대신 -6%" |
| 손절 예약 발동 | "손절 발동! 8만 지켰다" |
| 공매도 → 같은 섹터 쇼크 | "콤보! 공매도 +12만" |
| 내가 낸 쇼크에 내가 더 맞음 | "앗, 내 반도체도 같이 맞았다" |
| 내부자거래 적발 | 크게 연출 (자산 몰수) |

**검증**: `game/ui`에서 `npm run e2e` — 분산 보유 상태에서 섹터 쇼크를 맞는 시나리오를 고정 시드로 재현하고 해당 문구 노출을 확인.

### [x] T3. 매치 종료 정산 — 2026-08-05 완료

현재 종료 화면은 자산만 표시. "한 판 더"의 고리를 만든다.

- 등급: **수익률 기반** 별 1~3 (절대 금액 아님 — 실력 지표로 유지)
- 획득 골드 (누적 저장, localStorage)
- 이번 판에 처음 낸 카드 = "새로 배운 카드" 목록 (도감의 씨앗, 부모 리포트 원료)
- 다음 등급까지 남은 골드 표시

**검증**: `npm run e2e` — 승리/패배 각각에서 등급·골드·신규카드 요소 존재 확인. 재시작 후 골드 누적 유지 확인.

### [x] T4. 멀리건 (첫 손패 1회 교체) — 2026-08-05 완료

운으로 지면 아이가 접는다. 매치 시작 시 손패 중 원하는 장수를 버리고 같은 수만큼 새로 뽑는 1회 기회.

**검증**: `game`에서 유닛 테스트 (교체 후 손패 수 동일, 버린 카드는 덱으로 복귀 후 셔플). `npm run e2e`로 UI 흐름 1회.

### [ ] T5. AI 난이도 3티어

봇 7종을 난이도로 묶는다. 매치 시작 시 선택.
- 쉬움 / 보통(greedy) / 어려움(signal 또는 shark)

**검증**: `npm run sim`에 티어 매치업 추가 — 고정 기준 봇 대비 승률이 쉬움 > 보통 > 어려움 순으로 단조 감소.

### [ ] T6. 온보딩 (첫 판 튜토리얼)

현재 첫 화면에 카드·종목·에너지·뉴스가 한꺼번에 등장. 검증 루프 목표는 "1분 설명으로 첫 턴 스스로 진행".
- 첫 판은 고정 시드 + 단계별 힌트 (카드 선택 → 종목 선택 → 턴 종료)
- 첫 판 손패는 매수/매도/관망 위주로 제한

**검증**: `npm run e2e` — 튜토리얼 흐름을 끝까지 따라가 1턴 완료. 2회차부터는 튜토리얼이 뜨지 않음.

### [ ] T7. 밸런스 재조정

`docs/game-design.md` 11절 스냅샷의 미달 항목 해결.

목표: 파산 ≥5% (어그로 매치업 기준) / 목표달성 ≥15% (상위 플레이 기준) / 턴종료 ≤75%
동시에 교육 3종·선공후공 5%p·터틀 <35%·평균 라운드 10~15 유지.

**검증**: `npm run sim` 리포트가 위 조건 전부 만족. 결과를 11절 스냅샷에 반영.

### [ ] T8. 카드 기여 지표 재정의

현재 "카드를 낸 플레이어의 승률"은 선택 편향이 있다 (배당 86% = 이기는 판에서만 내는 카드). 인과에 가까운 지표로 교체.

권장: 카드를 덱에서 뺀 덱 vs 넣은 덱의 승률 차(덱 단위 A/B), 또는 동일 시드에서 해당 카드만 무효화한 대조군 비교.

**검증**: `npm run sim` 리포트에 새 지표 출력. 명백한 지배 카드(신규 지표 55% 초과)가 없거나, 있으면 조정 후 재측정.

### T1 산출물 요약 (T2가 쓸 것)

`game/src/types.ts`의 `GameEvent` discriminated union — 엔진은 숫자·식별자만 내보내고 **한국어 문구는 만들지 않는다**(UI 책임).

| 타입 | 주요 필드 |
|---|---|
| `stopLossTriggered` | `stockId`, `shares`, `saleProceeds`, `savedAmount`(지킨 금액) |
| `sectorHit` | `sector`, `pct`, `source`(카드발/월드이벤트발), `impacts[]` — 플레이어별 `pnlAmount` + `exposureRatio`(0~1, 분산도) |
| `shortClosed` | `entryPrice`, `exitPrice`, `amount`, `pnl` |
| `insiderCaught` | `fineAmount`(몰수액) |
| `forcedSale` | `stockId`, `shares`, `proceeds` |
| `worldEventTriggered` | `eventId`, `headline`, `effects` |
| `gameOver` | `winner`, `reason` |

`game/ui/src/useMatch.ts`는 아직 반환값을 버리고 있다 — T2에서 수집·전달하도록 연결해야 한다.
