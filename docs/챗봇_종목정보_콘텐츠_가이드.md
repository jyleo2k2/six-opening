# 키웅이 종목 정보 콘텐츠 가이드

## 1. 목적과 원칙

이 문서는 모의투자 유니버스의 51개 종목을 두고, F10 키웅이가 초등학생~중학생 사용자에게 제공해야 할 정보 범위를 정한다.

- [사실] 대상 종목과 섹터는 [모의투자 종목 유니버스 데이터셋 설계](모의투자_종목유니버스_데이터셋_설계.md)의 13개 섹터·51개 종목을 따른다.
- [확정] 키웅이는 **“어떤 회사를 사야 하는가”**가 아니라 **“그 회사와 산업이 무엇을 하는가”**를 설명한다.
- [확정] 종목 추천, 매수·매도 시점, 목표가·손절가, 가격·수익률 전망, 다른 종목과의 우열 판단, 훈계는 제공하지 않는다.
- [확정] 화면에 없는 최신 수치·실적·뉴스·회사 사실을 만들어 내지 않는다. 최신 사실은 검증된 데이터 원본과 기준일이 있을 때만 설명한다.

## 2. 모든 종목에 공통으로 제공할 정보

각 종목에는 아래 5개 정보 카드를 준비한다. 한 번의 챗봇 답변은 사용자 질문에 필요한 카드만 골라, 최대 3문장으로 설명한다.

| 카드 | 아이에게 설명할 내용 | 데이터 기준 |
|---|---|---|
| 회사 한 줄 소개 | “이 회사는 무엇을 만들어 주거나, 어떤 서비스를 하는 회사야?” | `companySummary` |
| 산업 속 역할 | 같은 섹터 안에서 어떤 일을 맡는지 | `sector` + 검증된 설명 |
| 일상 연결 | 사용자가 마주칠 수 있는 제품·서비스·장면 | 검증된 대표 사례 |
| 돈의 흐름 | 아주 단순한 방식으로, 회사가 대가를 받는 구조 | 사업모델 설명 |
| 화면 읽기 | 현재가·등락·보유 수량·예상 금액 같은 화면 숫자의 뜻 | 화면 컨텍스트·API 값 |

### 답변 예시 형식

```text
질문: “이 회사는 뭐 하는 회사야?”
답변: “이 회사는 [제품/서비스]를 [고객]에게 제공하는 회사야.
그래서 [산업] 안에서 [역할]을 맡고 있어.
화면의 숫자는 이 회사의 주식이 지금 거래되는 모습을 보여 주는 거지, 앞으로의 결과를 약속하는 건 아니야.”
```

`[제품/서비스]`, `[고객]`, `[산업]`, `[역할]`에는 검증된 사실만 넣는다. 이 형식은 투자 판단을 유도하지 않고 회사·산업 이해에 초점을 둔다.

## 3. 연령별 깊이

| 대상 | 설명 방식 | 예시 질문 |
|---|---|---|
| 초등학생 | 친숙한 일상 장면, 쉬운 명사, 짧은 문장 | “이 회사는 뭘 만들어?”, “내가 어디서 만나?” |
| 중학생 | 산업의 연결, 비용·고객·경쟁의 기본 구조, 화면 수치의 의미 | “어떻게 돈을 벌어?”, “이 산업은 왜 여러 회사가 필요해?” |

두 연령 모두 회사의 미래를 단정하지 않는다. “오를까?”, “지금 사도 돼?” 같은 질문에는 고정 거절문과 함께 회사 설명·화면 확인 기준으로 되돌린다.

## 5. 종목 상세 화면에서 가능한 질문

키웅이는 종목 상세에서 아래 질문을 우선 지원한다.

1. **회사 이해**: “이 회사는 무엇을 해?”, “어떤 제품이나 서비스를 제공해?”
2. **산업 이해**: “이 섹터는 어떤 일을 해?”, “같은 섹터 회사들은 무엇이 달라?”
3. **생활 연결**: “내가 이 회사를 어디에서 만날 수 있어?”
4. **화면 이해**: “시장가가 뭐야?”, “현재가와 등락은 무슨 뜻이야?”, “10주면 얼마야?”
5. **모의투자 사용법**: “주문 전에 무엇을 확인해?”, “이유와 확신도는 왜 기록해?”

### 답하지 않는 질문과 전환 방식

| 요청 | 처리 | 대신 안내할 내용 |
|---|---|---|
| “어느 종목을 사야 해?” | 고정 거절 | 회사 설명, 업종, 화면에서 확인할 수 있는 사실 |
| “이 종목 오를까?” | 고정 거절 | 가격은 변할 수 있으며, 회사가 하는 일과 화면 수치의 뜻 |
| “지금 팔까?” | 고정 거절 | 주문 수량·예상 금액·기록한 이유를 다시 확인하는 방법 |
| “목표가는 얼마야?” | 고정 거절 | 목표가를 제시하지 않으며, 모의주문 규칙과 현재 화면 정보 |
| “어떤 회사가 더 좋아?” | 우열 판단 거절 | 두 회사가 하는 일·산업 역할의 사실 비교 |

## 6. 콘텐츠 데이터 구조

종목 마스터의 `companySummary`만으로는 질문 폭을 충분히 다루기 어렵다. 챗봇 전용 사실 콘텐츠를 `stockId` 기준으로 별도 관리한다.

```ts
type StockEducationContent = {
  stockId: string;
  companySummary: string;      // 회사 한 줄 소개
  sectorSummary: string;       // 섹터가 하는 일
  everydayExamples: string[];  // 일상 연결 사례
  businessFlow: string[];      // “만들기 → 전달하기 → 서비스” 같은 순서
  childQuestions: string[];    // 추천 질문 칩
  middleSchoolNotes: string[]; // 중학생용 추가 설명
  factSources: Array<{
    label: string;
    checkedAt: string;
  }>;
};
```

### 작성 규칙

- 사실 하나마다 검증 원본과 확인일을 남긴다.
- 한 카드에는 하나의 개념만 넣고, 어려운 용어는 같은 답변 안에서 풀어 쓴다.
- 회사의 제품·브랜드·사업은 변경될 수 있으므로 정기적으로 재검토한다.
- 실적, 주가, 계약, 시장점유율처럼 시점에 민감한 정보는 기준일 없이는 챗봇 지식에 넣지 않는다.
- 방산·금융·화장품처럼 오해 위험이 있는 분야는 안전·의료·수익 보장을 암시하지 않는 중립 표현을 사용한다.

## 7. 완료 기준

- 51개 종목 모두에 회사 한 줄 소개와 섹터 설명이 있다.
- 섹터별로 최소 3개의 초등학생용 추천 질문과 2개의 중학생용 추가 질문이 있다.
- 모든 설명은 사실 원본과 확인일을 가진다.
- 추천·시점·목표가·전망 표현이 콘텐츠와 챗봇 출력 필터 어느 곳에도 없다.
- 종목 상세 화면, 챗봇 추천 질문, F3 기록 화면이 같은 `stockId`를 사용한다.
