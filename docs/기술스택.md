## 개발 병렬 작업 하네스

- 앱과 같은 런타임인 Node.js의 무의존성 스크립트 `scripts/git-session-manager.mjs`를 사용한다. 병렬 작업 관리 때문에 Python 서비스나 별도 데이터베이스를 추가하지 않는다.
- 루트 `main` worktree는 관제 전용으로 유지하고, 기능 작업은 레포와 나란한 `{레포폴더명}-worktrees/{사용AI}/{작업자}/{한글-작업명}` 아래의 전용 worktree에서 수행한다(현재 경로는 `C:/dev/six-opening-worktrees/`). 경로는 `git-session-manager.mjs start`가 만들어 주는 값을 그대로 쓴다.
- 세션 관리기는 브랜치 신원, worktree 경로, 예상 수정 범위 claim, 활성 로컬 세션, 열린 GitHub PR의 수정 파일 겹침을 검사한다. 상태는 공용 Git 디렉터리의 로컬 JSON에 저장하며 저장소에는 커밋하지 않는다.
- Claude는 편집 전 훅, 모든 Git 사용자는 저장소의 pre-commit·pre-push 훅, GitHub PR은 `session-policy` 워크플로로 같은 핵심 규칙을 검증한다.
- Next.js 산출물인 `web/.next`와 `web/node_modules`는 worktree끼리 공유하지 않는다. 각 worktree에서 `npm ci`를 실행하고 개발 서버 포트는 세션 관리기가 안내한 값을 사용한다.
- 이 하네스는 개발 도구이며 Next.js 번들·Vercel 배포·F10 런타임에는 포함되지 않는다.

### 구현 규칙

- SDK: **`openai`** 서버 전용, **Responses API**를 쓴다. API 키는 `OPENAI_API_KEY`만 사용한다.
- 모델 ID는 `shared/llm`의 단일 상수 `gpt-5.6-luna`로 둔다. 별도 프로바이더 추상화는 만들지 않는다. **별칭 `gpt-5.6`은 sol로 라우팅되므로 쓰지 않는다.**
- F10은 서버에서 `client.responses.create({ stream: true })`를 호출하고 `response.output_text.delta` 이벤트만 읽는다. 원시 델타 전체를 최대 4,000자로 서버 버퍼에 먼저 모은 뒤, 생성이 끝난 전체 텍스트를 최대 3문장·출처·권한·수치·금지 표현 기준으로 공통 검증한다. 통과한 완성 답변만 단일 `text` SSE 이벤트로 보내며 차단 시 고정 응답으로 대체한다.
- F9은 `client.responses.create`(비스트리밍)로 서술만 생성하고 공통 출력 필터를 거친다.
- **출력 검사는 2단이다 [개정 2026-08-14].** 1단은 `shared/llm/filter`의 결정적 룰이고, 2단은 `f10-chatbot/lib/output-judge`의 Luna 판정이다. 2단은 `source === "model"`인 답변에만 돌리므로 고정 응답·사전·FAQ·Tool 경로에는 호출이 없다. 판정 실패·시간 초과는 닫힌 실패로 처리해 고정 응답으로 대체한다. 2단이 환각해도 1단이 잡던 표현은 그대로 차단되므로 안전 하한선은 내려가지 않는다.
- 2단 도입 근거는 실측이다. 같은 의미를 다른 표현으로 쓴 추천·전망 문장을 1단 룰은 0/12 차단했고, 룰을 8개 확장해도 표현을 바꾼 5문장은 0/5 차단이었다. Luna 판정은 12/12·5/5를 차단하고 정상 설명 8건은 0건 오탐했다. 단건 지연 약 1.5초는 SPEC §5.2의 최소 2초 답변 준비 카드 안에 들어간다.
- 수치 검증은 **단위가 붙은 주장값만** 대조한다(`123원`·`12%`·`10주`). `1주당`처럼 단위 뒤에 조사가 붙는 관용구와 단위 없는 설명용 숫자는 화면 수치 주장이 아니므로 통과시킨다. 허용 목록은 화면 맥락값과 **사용자가 같은 질문에 적은 숫자**로 구성한다.
- F9·F10 대화의 `reasoning.effort`는 **`low`** — 무대 지연을 줄이되 3문장·거절 지시 준수는 유지한다. `max_output_tokens`는 reasoning 토큰까지 포함하므로 800으로 두고, 3문장 상한은 서버 라우트가 자른다. 지연이 더 문제면 `none`으로 내린다.
- F10 대화는 텍스트 입력만 제공한다. 음성 파이프라인은 범위 밖이다(Luna는 Realtime 미지원).

### 어린이 뉴스 역할 파이프라인 프로토타입 [팀 확정 2026-08-12]

역할 파이프라인 구현은 `web/features/f2-trade/prototypes/child-news-role-pipeline/`에 격리돼 있고, 저장 계약은 `web/features/f2-trade/lib/news/contracts.ts`와 `supabase/migrations/`의 `news_*` 테이블이다. `ready_for_storage` 결과는 Supabase에 저장되며 `GET /api/news`가 서비스 화면에 물린다. **일일 자동 수집 스케줄은 아직 없다** — 현재 자동화된 워크플로는 `candles.yml`(장마감 캔들 적재)뿐이고 뉴스 수집은 수동 실행이다.

- 범위는 `오늘 국내 시황` 또는 `선정 51개 기업의 직접적인 중요 사건` 두 가지다. 채용·행사·사회공헌·사내 혁신·일반 홍보와 선정 기업이 고객·제공 채널로만 등장하는 기사는 제외한다.
- 원문은 문장 단위 근거 id로 나눈다. 관련성 선별자가 포함한 문장만 편집자에게 전달해 코스닥 동향·개발자 강연 같은 주변 사실이 문안으로 되돌아오는 경로를 끊는다.
- 편집자는 선별자가 표시한 어려운 용어를 모두 `replaced` 또는 `explained`로 처리한다. 결정적 게이트는 근거 id, 중심 문장 위치, 원문에 없는 숫자, 공통 금지 표현, 긍정·부정 라벨, 용어 처리 누락을 검사한다.
- 독립 출고 검수자는 선별자의 설명이나 편집자의 자체 점수를 받지 않고 원문 전체와 실제 노출문만 본다. 검수 LLM은 의미 교차검증 역할이며, 게시 여부는 서버가 모든 boolean·issue·역할 간 주체/사건 일치를 확인해 결정한다. 공통 정규식 출력 필터는 별도로 유지한다.
- 편집 문제만 한 번 `high`로 재작성한다. 독립 검수에서 범위·주체·중요성이 다르다고 판정하면 즉시 탈락한다. 파싱 오류·시간 초과·판단 불일치는 모두 닫힌 실패로 처리한다.
- `ready_for_storage` 결과만 DB 저장 단계로 넘긴다. 통과 기사가 목표 개수보다 적어도 일상 기사로 보충하지 않는다.

### F10 라우팅·툴·RAG 경계 [팀 확정 2026-08-11]

- **한 번 통과하는 파이프라인:** 요청·세션 검증 → 입력 안전 게이트 → 규칙 기반 질문 목적 라우팅 → (해석 실패면 후속 질문 재작성 후 재라우팅) → 선택적 읽기 전용 조회 → 용어 분류 또는 답변 생성 → 공통 출력 게이트 → 구조화 응답. 모델이 스스로 툴을 반복 선택하는 에이전트 루프는 만들지 않는다.
- **한 요청의 LLM 호출은 최대 4회다** [개정 2026-08-14]: 재작성 → 용어 분류 → 답변 생성 → 출력 2단 판정. 각 단계는 조건부이며 **용어 분류와 답변 생성은 서로 배타적**이다(분류에 성공하면 생성하지 않는다). 각 호출은 자체 타임아웃과 닫힌 실패 처리를 갖고, 어느 단계가 실패해도 승인된 고정 응답으로 내려간다.
- **툴로 만들 것:** 승인된 종목 사실 조회, 본인 거래·질문식 기록 조회, 본인 F9 JSON 조회, 본인 아카이브 조회. 모두 서버 전용·읽기 전용이며 입력·출력 스키마와 허용 필드를 고정한다.
- **툴로 만들지 않을 것:** 용어 사전, 사용법 FAQ, 추천·위기·개인정보 고정 응답, 선제 도움 고정 발화. 단순한 것은 TypeScript 데이터와 순수 함수로 처리한다.
- **사용자 경계:** 사용자·가족 식별자는 세션에서 서버가 주입한다. 모델과 클라이언트는 조회 대상을 지정하거나 다른 가족 구성원으로 바꿀 수 없다.
- **RAG:** “매수가 뭐야?” 수준은 사전으로 처리한다. 승인된 교육 문서가 사전 규모를 넘어 의미 검색이 필요할 때만 소규모 RAG를 추가한다. 공개 웹 검색은 MVP 답변 경로에 두지 않는다.
- **후속 행동:** 관련 화면 이동은 모델이 만든 URL이 아니라 허용 목록의 `uiAction`을 반환하고 사용자 탭 후 실행한다.
- **재검토 조건:** 한 요청에서 여러 툴의 반복 호출, 중단 후 재개, 사람 승인, 복잡한 재시도·분기가 실제 요구사항이 될 때만 LangGraph 도입을 재검토한다. 현재 Next.js 단일 TypeScript 서비스에 별도 Python 런타임이 필요하지 않으므로 PydanticAI는 사용하지 않는다.
- **선제 도움:** 유형은 `switch`·`dwell`·`lossRevisit` 3종으로 고정하고 LLM을 호출하지 않는다. 횟수·시간·손실률 임계값만 [가정]으로 검증한다.

## 구조 원칙

- **실행 가능한 앱은 `web/` 하나다** (배포·발표 대상). 루트 `mock-stock/`은 `web/`으로 이관한 뒤 삭제됐으므로 참조하지 않는다. `behavior-demo/`(Vite + Supabase)는 행동 수집 실험 코드이며 사용자 화면의 정본이 아니다.
- 전역 기획·디자인·기술 문서는 `docs/`, 기능 구현 명세는 코드 소유 폴더의 `SPEC.md`에 둔다.
- API 키(OpenAI, 키움·토스, Supabase)는 서버 코드에서만 — 클라이언트 번들 및 `NEXT_PUBLIC_*` 포함 금지
- LLM 프롬프트는 기능 폴더, SDK 호출·모델 상수·필터는 `shared/llm`에 둔다. F10 `app/api/chat`은 스트림 전송만 담당하며 컴포넌트에서 SDK를 직접 호출하지 않는다
- 행동 이벤트(탭 체류·화면 전환·주문 취소)는 `app.html`이 기록하고 `postMessage`로 React에 넘긴다. 규칙 판정은 `shared/engine`이 하며 LLM 호출만 서버를 경유한다
- **수치·스코어링 계산은 `shared/engine`에만 둔다.** 화면은 표시만 한다. 아카이브 엔진은 이관 중이라 두 벌이다 — 화면이 쓰는 구버전 `archive-profile.js`와 앞으로 갈 정본 `behavior-profile.ts`이며, 산식을 한쪽에만 넣지 않는다
- **`app.html`은 커밋된 파일이 정본이고 `web/ui-src/`는 그 분해본이다.** `web/scripts/ui-build.mjs`가 `split`·`build`·`verify`·`export`로 왕복시키며, `archive-profile.js`도 이 빌드가 `app.html` 안으로 복사한다. 한쪽만 고치면 `verify`가 깨진다
- **폴백 우선**: 실연동(키움 시세·LLM·Supabase)이 실패해도 데모가 죽지 않게 각 경로에 폴백을 둔다. 시세 픽스처의 실제 위치는 `web/app/api/quote/fixtures.ts`다(`shared/data/fixtures/`는 비어 있다)

## 서버 API (route.ts 21개 — 2026-08-14 실측)

`web/app/api/supabase.ts`가 모든 DB 접근의 단일 통로다. 세션 사용자는 서버가 쿠키에서 정하고 요청 본문이 지정할 수 없다.

| `auth/switch` | POST | 세션 계정 전환 | 아직 화면에서 호출하지 않음 |
