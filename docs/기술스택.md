- 작성: 2026-08-06 v0.1 → **2026-08-07 전면 개정** (게임 기획 교체: 1:1 카드게임 → 2~8인 히스토리 투자 시뮬)
- 대상: `docs/기획서.md` (2026-08-07) · 범위: ① 히스토리 투자 시뮬 ② 도감·뉴스 ③ 자녀 투자 제안서
- 스택·배포 형태·폴더 구조는 v0.1 결정을 승계한다 — 게임 장르가 바뀌어도 근거가 그대로 성립한다.
  미확정은 【T#】 — §10

## 0. 전제

| 항목 | 결정 |
|---|---|
| 영웅문 실제 임베드 | 하지 않는다. 시연 목적 — **"자녀용 영웅문" 셸을 우리가 만든다** |
| 자녀 실계좌 | 자녀는 조회·제안, 주문은 부모. 화면은 구현하되 데이터는 mock 어댑터 (§7) |
| 부모 | 시연에선 본 앱의 부모 뷰 |
| 게임 데이터 | **전부 가상** — 익명 회사·정적 데이터 팩. 시세 API를 쓰지 않는다 (§7) |

## 1. 결론 요약

| 레이어 | 선택 | 한 줄 이유 |
|---|---|---|
| 배포 형태 | 웹앱 (PWA) + Capacitor 래핑(선택) | QR 3초 진입 = 시연 최적. 8인 방은 관객 폰으로 즉석 합류 |
| 프론트 | Next.js (App Router) + TypeScript + Tailwind | 도감/뉴스 SSR + 제안서 공유링크 OG |
| 게임 렌더 | React DOM + Framer Motion (+ Lottie) | 시세판·순위 보드·채팅 = 문서형 UI. Canvas 불필요. 순위 풀스크린 연출은 Motion + Lottie 1개 |
| 상태관리 | Zustand (로컬) + TanStack Query (서버) | 규모에 맞게 |
| 게임 서버 | TypeScript + **Colyseus** | 2~8인 룸·페이즈 타이머·채팅 릴레이·재접속 내장 + **룰 엔진 공유**로 판정 이중구현 제거 |
| DB / Auth | Supabase (Postgres) | 초대코드 인증 + **명예의 전당 저장** |
| 증권 데이터 | `web/lib/brokerage` 어댑터 — mock | 제안서 트랙 전용. 게임은 무관(가상 데이터) |
| 배치 | Python (uv) | 뉴스 재작성 배치. **종가 스냅샷 파이프라인은 폐기** — 게임이 실시세를 안 쓴다 |
| 인프라 | Vercel(웹) + Fly.io/Railway(게임서버) + Supabase | 게임서버는 stateful WebSocket — 서버리스 불가 |
| 워크스페이스 | npm workspaces (`game`, `web`) | web이 룰 엔진을 소스로 직접 import |

## 2. 배포 형태 — 웹 (v0.1 결정 승계)

시연 우위가 비대칭이다: 웹이면 발표 화면은 브라우저, **관객은 QR 스캔 3초 만에 같은 방에 들어와
8인 플레이**가 된다 — 새 게임에서 이 장점이 카드게임 때보다 더 크다. Capacitor는 마지막에 래핑만.
푸시가 필요한 핵심 루프(제안서 승인 알림)도 v0.1 그대로.

## 3. 프로젝트 구조

```
six-opening/
├─ package.json             { "workspaces": ["game", "web"] }
│
├─ game/                    ── 게임 트랙 ──
│  ├─ src/                  룰 엔진 (순수 TS, SSOT) — web·server·sim이 공유
│  │  ├─ types.ts           섹터·종목·이벤트·상태·액션 계약
│  │  ├─ rules.ts           룰 상수 (시드 자금·티어·페이즈 시간) — 밸런스는 여기부터
│  │  ├─ rng.ts             결정적 난수 (시드 재현)
│  │  ├─ state.ts           createInitialState — 이벤트 5개 추첨·시세판·1턴 뉴스 배정
│  │  ├─ news.ts / info.ts  뉴스 배정 · 정보소 판정 (적중/빗나감·미끼 예보)
│  │  ├─ event.ts           이벤트 적용 — 섹터 방향 × 종목별 폭 추첨
│  │  ├─ settle.ts          총자산·순위 (동점 공동)
│  │  ├─ view.ts            viewFor(state, playerId) — 정보 비대칭 필터 (기획서 §9)
│  │  ├─ actions/           buy · sell · buyInfo · advancePhase → reduce() 단일 진입점
│  │  └─ index.ts           공개 API — web·server·sim은 여기만 import
│  ├─ data/                 2011~2020 데이터 팩: 종목 16(익명)·이벤트 13·뉴스 풀
│  ├─ server/               Colyseus GameRoom — 권위 판정·페이즈 타이머·채팅 릴레이
│  ├─ sim/                  봇 4전략 셀프플레이 시뮬레이터
│  └─ tests/                Vitest
│
├─ web/                     ── Next.js 자녀 영웅문 + 부모 뷰 (v0.1 구조 그대로) ──
│  ├─ app/(child)/game/     로비(방 생성·초대코드) · [roomId] 대전 화면
│  ├─ app/(child)/{home,stock,news,dex,proposal}/ · app/(parent)/ · app/(public)/
│  ├─ features/             game(시세판·채팅·순위 연출·useGameRoom) · portfolio · proposal · dex · news
│  ├─ components/ui/        도메인 모르는 표현 컴포넌트
│  └─ lib/brokerage/        증권 어댑터 — port + mock (placeOrder 금지)
│
├─ content/                 도감·뉴스 MDX (사람 검수 후 커밋)
├─ pipelines/               Python(uv) — news_digest만. close_snapshot 폐기
└─ docs/
```

경계 근거(v0.1 승계): `game/src`는 클라 즉시 반응과 서버 권위가 **같은 판정**을 돌리기 위한 SSOT.
`game/data` 분리는 밸런스 튜닝·연대 팩 확장이 데이터 교체만으로 되게 하기 위함 — **다른 연대
(2001~2010 등) 확장 = data 팩 추가, 엔진 수정 없음**.

> 모듈 해석 주의(승계): `game`은 확장자 없는 상대 import + `moduleResolution: Bundler`.
> 순수 node 단독 실행 불가 — tsx/vitest/번들러로 돌린다.

## 4. 게임 렌더링 — DOM (승계, 전제 갱신)

동시에 움직이는 요소가 카드 10장에서 **시세판 16행 + 순위 8행 + 채팅 스트림**으로 바뀌었지만
전부 문서형 UI라 결론은 동일하게 React DOM. 이벤트 연출(사건 배너 → 등락 → 풀스크린 순위)은
Framer Motion 시퀀스 + Lottie 1개. 턴별 자산 그래프는 SVG 스파크라인 직접 그리기 【T5: 차트
라이브러리 도입 여부 — 필요해질 때 재검토】.

저사양 실기기 측정 원칙 유지 (주력 기기 = 물려받은 저가 안드로이드 가정).

## 5. 게임 서버 — Colyseus (승계, 역할 확대)

카드게임 때는 "룰 공유" 하나가 이유였다면, 지금은 Colyseus의 룸·동시성 기능을 전부 쓴다:

- **2~8인 초대코드 방** (【T2】 해소 — 랜덤 매칭 없음, 방장이 시작)
- **페이즈 타이머 권위**: 준비 90s → 채팅 60s → 이벤트 연출 → 다음 턴. 클라는 남은 시간 표시만
- **채팅·이모티콘 릴레이**: 룰 엔진 밖 — 자산에 영향 없는 메시지는 서버가 중계만 한다
- **플레이어별 상태 필터**: broadcast 금지, `viewFor(state, playerId)` 결과를 개별 send —
  이벤트 큐·타인 뉴스·타인 정보 내용이 와이어에 실리지 않는다 (기획서 §9)
- 재접속: WebView 백그라운드 절단 대응 `allowReconnection` (승계)

## 6. 인증 · 개인정보 (승계)

만 14세 미만 = 법정대리인 동의 필수 → 부모가 프로필 생성·초대코드 발급, 자녀는 코드+닉네임만.
자녀에게서 이메일·전화번호를 수집하지 않는다. 게임 채팅도 닉네임만 노출한다.
Supabase Auth (부모 매직링크 / 자녀 초대코드 세션).

## 7. 데이터

```
[게임]     game/data 정적 팩 (익명 회사·이벤트·뉴스)  →  엔진  →  화면   ← 외부 API 없음
[제안서]   brokerage/mock 고정 스냅샷  →  화면                        ← 실연동은 어댑터 교체
[명예의 전당]  게임 종료 결과  →  Supabase 테이블 【T6: 스키마】
```

익명 회사 확정으로 **시세 API·KRX 라이선스·종가 파이프라인이 전부 범위에서 빠졌다.**
게임 진행 중 외부 호출 0회 — 장애·레이트리밋이 대전에 영향을 줄 수 없다.

## 8. 콘텐츠 정책

- 사람 검수 대상 = **편집 텍스트** (`content/` MDX + `game/data` 뉴스·사건 문구). 자동 발행 금지
- **실시간 유저 채팅은 검수 대상이 아니다** — 닉네임만·200자 제한·금칙어 필터 【T4】
- 뉴스 원문 크롤링·전재 금지 (재작성만). 앱이 실존 종목 추천 금지 — 게임 속 회사는 전부 가상
- 실제 재난을 다루는 사건 카피는 역사 한 줄 설명을 병기하고 희화화하지 않는다 (기획서 §8)
