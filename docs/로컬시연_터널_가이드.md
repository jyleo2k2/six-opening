# 로컬 시연 — Cloudflare 터널 가이드

> 작성: 2026-08-18 · 대상: 발표·시연에서 실기기(폰) 접속이 필요한 경우
>
> 실행 스크립트는 `scripts/local-demo.ps1` 하나다. 이 문서는 그 스크립트가 왜 그렇게 생겼는지와 실패했을 때 어디를 보는지를 적는다.

## 1. 한 줄 실행

PowerShell에서 저장소 루트에 선 채로:

```powershell
.\scripts\local-demo.ps1
```

빌드 → 서버 기동 → 시세 점검 → 터널 개통까지 한 번에 진행하고, 마지막에 `https://….trycloudflare.com` 공개 주소를 찍는다. 그 주소를 폰에서 열면 된다.

코드를 안 고쳤으면 빌드를 건너뛴다:

```powershell
.\scripts\local-demo.ps1 -SkipBuild
```

끝낼 때는 창을 닫거나 `Ctrl+C`. 남은 프로세스가 의심되면:

```powershell
.\scripts\local-demo.ps1 -Stop
```

### 옵션

| 옵션 | 용도 |
|---|---|
| `-SkipBuild` | 기존 `.next`를 그대로 쓴다 |
| `-NoTunnel` | 터널을 열지 않고 로컬 서버까지만 띄운다. 바깥에 노출하지 않고 빌드·시세만 확인할 때 |
| `-Port 3020` | 포트를 바꾼다 (기본 3010) |
| `-Provider kiwoom` | 첫 시세 제공자를 바꾼다 (기본 `toss`) |
| `-Quic` | QUIC으로 터널을 연결한다 (기본은 `http2` — §7 참고) |
| `-Stop` | 남은 서버·터널을 정리한다 |

### `.env`는 관제 저장소 루트에서 찾는다 [사실]

`.env`는 Git이 추적하지 않아 **관제 저장소 루트(`C:/dev/six-opening`)에만 있고 worktree에는 없다.** 스크립트는 worktree에서 실행돼도 `.git` 파일이 가리키는 관제 루트를 따라가 그 `.env`를 읽는다 — `web/shared/repo-root.ts`의 `controlRepositoryRoot`와 같은 규칙이다. 어느 파일을 읽었는지는 실행 로그의 `원본:` 줄에 찍힌다.

## 2. 왜 클라우드가 아니라 터널인가 [사실]

**시세 API 두 곳이 서로 다른 방식으로 IP를 본다.**

| 제공자 | 제약 | 근거 |
|---|---|---|
| 토스 | **사전 등록한 IP만 통과.** 미등록 IP는 자격증명이 맞아도 403 | 토스증권 WTS의 허용 IP 관리 (공개 가이드 기준, 공식 문서 미확인) |
| 키움 | **토큰을 발급받은 IP와 요청 IP가 같아야 한다** | 키움 REST API 에러코드 `8010` — "Token을 발급받은 IP와 서비스를 요청한 IP가 동일하지 않습니다" |

클라우드에 올리면 나가는 IP가 개발 머신과 달라져 둘 다 깨진다. 고정 IP를 얻으려면 Railway Pro($20/월, 단 IP가 3개라 키움 `8010` 위험), AWS Lightsail·EC2(고정 IP 1개, 설정 반나절 이상), 또는 NAT Gateway(월 $32+) 중 하나가 필요하다.

**터널은 이 문제를 우회한다.** 앱이 개발 머신에서 그대로 돌고 터널은 들어오는 트래픽만 중계하므로, 토스·키움으로 **나가는** 요청은 여전히 이미 등록된 IP에서 출발한다. 추가 비용 0원, 서버 설정 없음.

실측 확인 [사실 — 2026-08-18]: 이 스크립트로 띄운 프로덕션 서버에서 `GET /api/quote/005930`이 `source: "live"`, `provider: "toss"`를 반환했다(삼성전자 268,000원 / -2.37%). 같은 날 `cloudflared` quick tunnel도 서울 엣지(`icn06`)에 정상 등록됐다.

## 3. 준비 (한 번만)

```powershell
winget install --id Cloudflare.cloudflared
```

계정 가입은 필요 없다. 설치 경로는 보통 `C:\Program Files (x86)\cloudflared\cloudflared.exe`이며 스크립트가 자동으로 찾는다.

저장소 루트에 `.env`가 채워져 있어야 한다(`.env.example` 참고). 필요한 값은 `SUPABASE_URL`·`SUPABASE_SECRET_KEY`·`OPENAI_API_KEY`, 그리고 쓰는 제공자의 키다.

## 4. 스크립트가 하는 일

| 단계 | 내용 |
|---|---|
| 1 | 루트 `.env`를 **현재 프로세스 환경변수로 주입** (§6-1이 이유) |
| 2 | `QUOTE_PROVIDER=toss` · `QUOTE_PROVIDER_FALLBACK=kiwoom` 고정 |
| 3 | `DEMO_USER_ID`가 있으면 **제거** — 쿠키 없이 API를 여는 개발용 우회라 공개 주소에서 위험하다 |
| 4 | 포트(기본 3010) 점유 확인 |
| 5 | `next build` (`-SkipBuild`면 생략) |
| 6 | `next start -p 3010`을 백그라운드로 띄우고 포트가 열릴 때까지 대기 |
| 7 | `GET /api/quote/005930`으로 **실데이터인지 확인** |
| 8 | `cloudflared tunnel`을 `--protocol http2`로 개통하고 공개 주소 출력 |

포트 3010을 쓰는 이유는 세션 관리기가 배정하는 3100번대와 겹치지 않게 하기 위해서다. 바꾸려면 `-Port 3020`처럼 준다.

## 5. 확인 체크리스트

공개 주소를 폰에서 열고 순서대로 본다.

1. 로그인 화면이 뜬다
2. 계정으로 로그인하면 해당 역할의 홈이 그려진다 (`cksdud` 자녀 / `mom` / `dad`)
3. **탐색 탭에서 종목 카드 가격이 5초마다 움직인다** ← 실시간 시세가 살아 있다는 유일한 눈에 보이는 신호

3번이 안 움직이면 시세가 보관 캔들이나 픽스처로 떨어진 것이다. 스크립트 7단계가 이미 경고를 찍었을 테니 콘솔을 다시 보라.

## 6. 함정

### 6.1 프로덕션 모드는 `.env`를 안 읽는다 [사실]

`web/app/api/dev-env.ts`:

```js
if (loaded || process.env.NODE_ENV === "production") return;
```

`next start`는 `NODE_ENV=production`이고, 시세 제공자(`providers/toss.ts`·`kiwoom.ts`·`index.ts`)와 `app/api/supabase.ts`가 전부 이 함수를 거친다. 따라서 **`npm start`만 치면 키가 하나도 안 들어가 픽스처 시세가 나온다.** 스크립트가 `.env`를 프로세스 환경변수로 직접 주입하는 이유가 이것이다.

Railway·AWS에서는 대시보드에서 넣은 값이 진짜 환경변수라 이 문제가 없다. **로컬에서 프로덕션 모드로 돌릴 때만** 물린다.

### 6.2 네트워크를 바꾸면 토스가 죽는다

토스 허용 IP는 지금 이 회선의 공인 IP로 등록돼 있다. **행사장 와이파이에 노트북을 연결하면 IP가 바뀌어 403이 뜬다.**

대응은 둘 중 하나다.

- **권장 — 노트북을 안 가져간다.** 집·사무실 컴퓨터에서 스크립트를 돌려 두고, 발표장에서는 터널 주소만 연다. 터널 주소는 인터넷 어디서든 열리므로 그 컴퓨터가 옆에 있을 필요가 없다.
- 현장에서 `curl ifconfig.me`로 새 공인 IP를 확인해 토스 WTS에 다시 등록한다. WTS 접속이 가능해야 하고 반영까지 시간이 걸릴 수 있다.

### 6.3 서버를 재시작하면 접속자가 전원 로그아웃된다 [사실]

세션 유효성은 프로세스가 뜰 때 만드는 부팅 표식이 정한다(`app/api/supabase.ts`, 기능명세 §4.3). `next start`를 다시 하면 **보고 있던 사람 전부 로그인 화면으로 튕긴다.** 시연 중에는 재시작하지 않는다.

### 6.4 공개 주소는 매번 바뀐다

무료 quick tunnel은 실행할 때마다 새 주소를 받는다. **QR 코드는 발표 직전에 만든다.** 고정 주소가 필요하면 Cloudflare 계정과 도메인을 붙이는 named tunnel로 가야 한다(설정 단계가 늘어난다).

### 6.5 컴퓨터가 자면 시연도 죽는다

전원 설정에서 절전을 끈다. 노트북은 덮개를 닫아도 안 자게 해야 한다.

## 7. 문제 해결

| 증상 | 원인과 조치 |
|---|---|
| 빨간 `ERR ... quic ...` 줄이 뜬다 | 공유기가 UDP 7844를 막은 것이다. `SUMMARY: Environment ready with degraded transport`와 `hard_fail=false`가 있으면 **정상 동작 중**이고 http2로 돌아간 것이다. 스크립트는 기본으로 `--protocol http2`를 써서 이 줄을 아예 없앤다 |
| `포트를 PID … 가 쓰고 있다` | 이전 실행이 남았거나 다른 개발 서버가 있다. `-Stop`으로 정리하거나 `-Port`로 다른 포트를 쓴다 |
| `실시간이 아니다 — source=fixture` | 키 누락, IP 미등록, 네트워크 차단 중 하나다. `.env` 값과 현재 공인 IP를 확인한다 |
| `cloudflared 가 없다` | `winget install --id Cloudflare.cloudflared` |
| 서버가 포트를 못 연다 | 콘솔이 알려주는 `%TEMP%\six-opening-demo\server.err.log`를 본다 |
| 한글이 깨져 보인다 | 이 스크립트는 UTF-8 BOM으로 저장돼 있어야 한다. 편집 후 저장 인코딩을 확인한다 |

## 8. 이 방식의 한계

터널은 **시연용이다.** 상시 운영에는 맞지 않는다.

- 앱을 돌리는 컴퓨터가 계속 켜져 있어야 한다
- 무료 quick tunnel은 가동률 보장이 없다
- 주소가 매번 바뀐다

상시 서비스가 필요해지면 고정 IP를 주는 호스팅으로 옮기고, 그때 토스 허용 IP를 그 주소로 다시 등록한다. 선택지 비교는 이 문서 §2 표를 출발점으로 삼는다.
