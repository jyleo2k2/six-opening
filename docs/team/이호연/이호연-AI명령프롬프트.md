# 이호연 — AI 명령 프롬프트 가이드 (전략시뮬게임 화면)

> 이 문서를 Claude/Codex에 그대로 복사·붙여넣기 해서 쓴다.

## 0. 사용법

1. 새 대화에서 §1 온보딩을 한 번 보낸다.
2. AI가 "읽었음"이라고 요약하면 §3에서 지금 할 작업 블록을 보낸다.
3. AI가 계획을 제시하면 이상 없을 때 "진행해"라고 한다.
4. 만들면 §5 자가검증을 보낸다.

## 1. 온보딩 프롬프트 (대화 시작 시 1회)

```
너는 "물려주는 계좌"의 전략시뮬게임 화면(game/ui) 작업을 돕는다. 나는 이호연, 게임 UI 담당이다.
설명은 쉽고 명확하게.
먼저 아래 파일을 읽고 "읽었음"과 함께 ① 내가 할 일 ② 내가 하면 안 되는 것(특히 game/src)
③ 꼭 지킬 핵심 규칙을 정리해줘. 아직 만들지 마.
읽을 파일: 1.CLAUDE.md 2.docs/team/_공통_AI규칙.md(헌장) 3.docs/team/이호연/이호연-담당업무.md
4.docs/mvp-backlog.md 5.docs/game-design.md 6.game/ui/README.md
환경: 작업 폴더는 game/ui. 빌드는 npm run build, 검증은 npm run e2e / verify:t2~t4.
```

## 2. 고정 규칙

```
[고정 규칙]
1. game/src(룰 엔진)는 건드리지 않는다 — 엔진이 노출한 함수만 호출한다. 룰 재구현 금지.
2. 엔진 시그니처를 바꿔야 하면 코드를 고치지 말고 "계약 변경 필요"라고 보고해라(이재용이 처리).
3. 화면 문구는 엔진이 준 필드값을 그대로 쓴다. 근사·재계산 금지(eventMessages.ts 원칙).
4. 백로그에 없는 기능을 추가하지 않는다. 필요하면 제안으로 적고 확인받는다.
5. 모르는 값은 지어내지 말고 "TODO: 확인 필요" 표시.
6. 한국어 파일은 편집도구/UTF-8로만. main 직접 push 금지(브랜치→PR).
```

## 3. 작업별 명령 프롬프트

### 3-1. T6 온보딩 (첫 판 튜토리얼)

```
[작업] docs/mvp-backlog.md의 T6를 구현해줘. 목표는 "초등 고학년이 1분 설명으로 첫 턴을 스스로
진행"이다. 현재 첫 화면에 카드·종목·에너지·뉴스가 한꺼번에 나와서 어디를 봐야 할지 모른다.
[제약] game/src는 건드리지 않는다. 기존 카드·시장 컴포넌트 스타일을 재사용한다.
멀리건 화면 다음에 들어가되 매치 흐름(엔진 호출 순서)은 바꾸지 않는다.
[검증] 검증 스크립트를 먼저 써라(game/ui/scripts/verify-t6.mjs). 그 다음 구현.
기존 e2e-playthrough, verify-loop1, verify-t2~t4가 전부 계속 통과해야 한다.
[산출물] 계획 먼저 → "진행해" 하면 구현.
```

### 3-2. 화면 레이아웃 수정

```
[작업] <어떤 화면>에서 <무엇>이 <어떻게> 보이게 고쳐줘.
[제약] game/ui/src 안에서만. 엔진 호출 순서·상태 흐름은 유지.
[검증] npm run build 후 dev 서버 띄우고 스크린샷으로 눈확인. 텍스트 겹침 없는지 확인.
그리고 verify:t2~t4 전부 재실행.
[산출물] 계획 먼저 → "진행해" 하면 구현. 스크린샷은 game/ui/shots에 저장.
```

### 3-3. 검증 스크립트 추가

```
[작업] <기능>을 고정하는 Playwright 검증 스크립트를 game/ui/scripts에 추가해줘.
[제약] 기존 scripts/lib.mjs의 passMulligan 같은 공용 헬퍼를 재사용한다. 새 헬퍼가 필요하면 lib.mjs에 넣는다.
검증은 화면 표시값과 window.__match 상태가 실제로 일치하는지 비교하는 방식으로 짠다(눈으로 보이는 것만 확인 금지).
[검증] 스크립트를 실제로 실행해서 PASS 나오는지 보여줘. 일부러 깨뜨렸을 때 FAIL 나는지도 확인.
[산출물] 계획 먼저 → "진행해" 하면 구현. package.json에 verify:<이름> 스크립트 추가.
```

## 4. 막히면 그대로 보내기

- 한 번에 하나: `지금은 [이것]만 하자. 다른 건 건드리지 마.`
- 엔진 침범 방지: `혹시 game/src 고쳤어? 고쳤으면 되돌리고 계약 변경으로 보고해.`
- 검증: `방금 만든 걸 실제로 실행해서 결과를 보여줘. 스크린샷도.`

## 5. 자가검증 프롬프트 (PR 전)

```
방금 만든 걸 점검하고 표로 보고해줘 (실제로 실행/테스트해서):
1. game/src를 건드리지 않았나?  2. 룰을 화면에서 재구현하지 않았나?
3. npm run build 통과했나?  4. e2e + verify:t2~t4 전부 그린인가? (실행 결과 붙여줘)
5. 스크린샷에서 텍스트 겹침 없나?  6. 한국어 안 깨졌나?
아니오가 있으면 고친 뒤 다시 보고해.
```
