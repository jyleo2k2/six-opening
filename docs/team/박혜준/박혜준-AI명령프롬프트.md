# 박혜준 — AI 명령 프롬프트 가이드 (뉴스 파이프라인)

> 이 문서를 Claude/Codex에 그대로 복사·붙여넣기 해서 쓴다.

## 0. 사용법

1. 새 대화에서 §1 온보딩을 한 번 보낸다.
2. AI가 "읽었음"이라고 요약하면 §3에서 지금 할 작업 블록을 보낸다.
3. AI가 계획을 제시하면 이상 없을 때 "진행해"라고 한다.
4. 만들면 §5 자가검증을 보낸다.

## 1. 온보딩 프롬프트 (대화 시작 시 1회)

```
너는 "물려주는 계좌 — 영웅문 주니어"의 뉴스 기능 중 수집·눈높이 번역 파이프라인 작업을 돕는다.
나는 박혜준, 뉴스 백엔드 담당이다. 설명은 쉽고 명확하게.
먼저 아래 파일을 읽고 "읽었음"과 함께 ① 내가 할 일 ② 내가 하면 안 되는 것
③ 꼭 지킬 핵심 규칙(특히 런타임 LLM 금지)을 정리해줘. 아직 만들지 마.
읽을 파일: 1.CLAUDE.md 2.docs/team/_공통_AI규칙.md(헌장) 3.docs/team/박혜준/박혜준-담당업무.md
4.web/AGENTS.md 5.물려주는계좌_기획안.md(1장·5장) 6.web/lib/types.ts
환경: Next.js 16 + node:sqlite. 검증은 web 폴더에서 npm run typecheck / npm test / npm run verify.
작업 폴더: web/lib/news, web/app/api/news.
```

## 2. 고정 규칙

```
[고정 규칙]
1. 아이 화면에 나가는 문장은 런타임 LLM으로 만들지 않는다. 배치로 만들고 사람이 검수한 문구만
   DB에서 꺼내 서빙한다. 검수 안 된 항목은 API가 반환하지 않는다.
2. web/lib/db.ts(스키마)와 web/lib/types.ts(공유 계약)는 핫스팟이다. 바꿔야 하면 코드를 고치지 말고
   "계약 변경 필요"라고 보고해라(이재용이 처리).
3. web/lib의 rules.ts, kiwoom.ts, stocks.ts, llm.ts는 다른 트랙 파일이다. 읽기만 한다.
4. 뉴스 소스·검수 워크플로·종목 매핑은 아직 미확정이다. 임의로 정하지 말고 TODO로 남겨라.
5. 모르는 값은 지어내지 말고 "TODO: 확인 필요" 표시. 가짜 기사·가짜 URL 금지.
6. 한국어 파일은 편집도구/UTF-8로만. main 직접 push 금지(브랜치→PR).
```

## 3. 작업별 명령 프롬프트

### 3-1. 뉴스 데이터 계약 초안

```
[작업] 뉴스 기능이 쓸 데이터 모양을 초안해줘. 아이 화면이 필요한 것: 제목(눈높이), 3줄 요약(눈높이),
원문 링크, 발행일, 연결된 종목코드(있으면), 검수 상태.
[제약] 코드를 쓰지 말고 타입 초안과 그 근거만. web/lib/types.ts의 기존 스타일과 맞춘다.
검수 상태는 "검수 완료만 노출"이 API에서 강제되는 구조여야 한다.
[검증] 기존 web/lib/types.ts의 Proposal, Stock 타입과 스타일이 일치하는지 비교.
[산출물] 타입 초안 + 왜 이 필드인지. PR에 "계약 변경" 명시 필요하다고 표시.
```

### 3-2. 검수 완료 뉴스 목록 API

```
[작업] web/app/api/news/route.ts를 만들어줘. 검수 완료된 뉴스만 최신순으로 반환한다.
[제약] 검수 안 된 행이 절대 새어나가면 안 된다 — 쿼리에서 걸러라(애플리케이션 필터에만 의존 금지).
런타임 LLM 호출 없음. web/lib/news 안에 로직을 두고 라우트는 얇게.
[검증] web/scripts/verify.ts에 "검수 안 된 뉴스는 목록에 없다" 체크를 먼저 추가하고,
검수 안 된 행을 하나 넣은 상태에서 실제로 안 나오는지 확인해줘.
[산출물] 계획 먼저 → "진행해" 하면 구현.
```

### 3-3. 눈높이 번역 배치 스크립트

```
[작업] 수집한 뉴스 원문을 초등 고학년이 읽을 수 있는 제목·3줄 요약으로 바꾸는 배치 스크립트를
web/scripts/news-translate.ts로 만들어줘. 결과는 "검수 대기" 상태로 저장한다.
[제약] 이 스크립트는 사람이 수동 실행하는 배치다 — 요청 처리 경로에 절대 넣지 않는다.
원문에 없는 사실을 만들어내면 안 된다. 수치·회사명은 원문 그대로 유지.
투자 권유·전망("오를 것", "사야 한다") 표현이 나오면 그 항목은 저장하지 말고 보류로 뺀다.
[검증] 샘플 기사 3건으로 드라이런하고 결과를 눈으로 보여줘. 원문 대비 없는 숫자가 생겼는지 대조.
[산출물] 계획 먼저 → "진행해" 하면 구현.
```

## 4. 막히면 그대로 보내기

- 한 번에 하나: `지금은 [이것]만 하자. 다른 건 건드리지 마.`
- 런타임 LLM 점검: `이 코드가 요청 처리 중에 LLM을 부르는 경로가 있어? 있으면 배치로 빼줘.`
- 가짜 값 방지: `이 기사·URL·수치 진짜야? 지어낸 거면 TODO로 바꿔줘.`

## 5. 자가검증 프롬프트 (PR 전)

```
방금 만든 걸 점검하고 표로 보고해줘 (실제로 실행/테스트해서):
1. 요청 처리 경로에서 LLM을 부르는 곳이 있나?  2. 검수 안 된 뉴스가 API로 새어나갈 수 있나?
3. web/lib/db.ts나 types.ts를 건드렸나? 건드렸으면 계약 변경으로 표시했나?
4. npm run typecheck / npm test / npm run verify 결과가 뭔가? (실행 결과 붙여줘)
5. 지어낸 기사·URL·수치가 있나?  6. 한국어 안 깨졌나?
아니오가 있으면 고친 뒤 다시 보고해.
```
