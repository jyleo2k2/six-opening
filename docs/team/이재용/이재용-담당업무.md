# 이재용 — 담당업무 (통합 오너 · 전략시뮬게임 룰 엔진)

## 1. 역할

두 가지를 겸한다.

**통합 오너** — 공유 핫스팟의 단일 작성자를 지정하고, PR 머지를 승인하고, 루트 진입점 문서를 관리한다.
기능 구현보다 경계 관리가 먼저다.

**전략시뮬게임 룰 엔진** — `game/src`의 룰·밸런스·봇·시뮬레이터를 담당한다.
이 폴더가 게임 룰의 유일한 SSOT이고, `game/ui`는 여기서 import만 한다.

## 2. 작업 경로

| 경로 | 내용 |
|---|---|
| `game/src` | 룰 엔진 — 타입·카드·엔진·봇·난이도·시뮬레이터 |
| `game/tests` | 룰 정합성 유닛 테스트 |
| `AGENTS.md` · `CLAUDE.md` | 루트 진입점 (**나만 수정**) |
| `web/AGENTS.md` · `web/CLAUDE.md` · `game/AGENTS.md` · `game/CLAUDE.md` | 폴더 규칙 (**나만 수정**) |
| `물려주는계좌_기획안.md` · `docs/team/_공통_AI규칙.md` | 기획·헌장 (**나만 수정**) |
| `scripts/git_session_manager.py` | 하네스 엔진 (**나만 수정**) |
| `docs/game-design.md` · `docs/mvp-backlog.md` | 게임 설계 SSOT (핫스팟 — 이호연과 조율) |

## 3. 통합 오너로서 할 일

- **핫스팟 겹침 판정**: 두 세션이 같은 공유 파일을 claim하면 단일 작성자를 지정한다.
  목록은 `.claude/skills/git-session-manager/references/team-git-policy.md`.
- **머지 승인**: 모든 PR은 `@jyleo2k2` 승인이 필요하다(`.github/CODEOWNERS`).
- **계약 변경 순서 통제**: `web/lib/types.ts`·`game/src/types.ts`가 바뀌면
  계약 → 생산자 → 소비자 → 통합 연결 순으로 병합시킨다.
- **공용 연결 PR**: 팀원이 만든 신규 화면을 `web/app/layout.tsx`에 붙이는 일은 내가 별도 PR로 한다.
  팀원은 신규 파일만 만든다.
- **진입점 문서 갱신**: 폴더 구조·규칙이 바뀌면 `AGENTS.md`와 `CLAUDE.md`를 같은 커밋에서 함께 고친다.

## 4. 게임 엔진으로서 할 일

`docs/mvp-backlog.md`가 작업 지시서다. 현재 상태:

- T1~T4 완료 (엔진 이벤트 로그 / 판정 피드백 UI / 매치 종료 정산 / 멀리건)
- **T5 AI 난이도 3티어 — `game/src/difficulty.ts`는 이미 있는데 백로그 체크·진행 로그가 비어 있다.**
  검증(`npm run sim` 티어 매치업 단조 감소)을 돌려서 마감하거나, 미완이면 무엇이 남았는지 적는다.
- T6 온보딩 / T7 밸런스 재조정 / T8 카드 기여 지표 — 미착수

불변 조건: 룰은 `game/src`에만. 교육 메시지 3종(분산>몰빵, 정직>불법, 시그널활용>무시)이
`npm run sim`에서 역전되면 그 변경은 되돌린다.

## 5. 경계

- `web/`은 내 담당이 아니다. 읽기만 하고, 규칙 파일(`web/AGENTS.md`) 외에는 수정하지 않는다.
- `game/ui`는 이호연 경계다. 엔진 API를 바꿔 UI가 깨지면 계약 PR을 먼저 올리고 알린다.
- 일정·범위 조정은 김설빈(팀장)과 상의한다. 나는 파일 경계를, 팀장은 우선순위를 정한다.

## 6. 검증

```powershell
cd game; npm test          # 룰 정합성
cd game; npm run sim       # 밸런스 + 교육 메시지 3종
```
