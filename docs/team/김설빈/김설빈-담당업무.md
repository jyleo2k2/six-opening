# 김설빈 — 담당업무 (팀장 · 실제투자 제안-승인 워크플로)

## 1. 역할

두 가지를 겸한다.

**팀장** — 무엇을 언제 할지 정한다. 트랙 간 우선순위, 일정, 범위 조정, 시연 시나리오 완결성.
파일 경계와 머지 승인은 이재용(통합 오너)이 맡는다. **역할이 다르니 겹쳐서 싸우지 않는다.**

**제안-승인 워크플로** — 이 서비스의 심장이다. 아이 제안 → 부모 승인/반려 → 키움 체결까지의
백엔드와 부모 화면 전부.

## 2. 팀장으로서 챙길 것

기획안 §11의 **시연 시나리오가 A 수준만으로 완결**되는지가 최종 기준이다.

```
부모: 잔고 화면 배너 → 아이 초대
아이: 홈에서 내 주식 확인 → 예습 모드 → 제안서 작성 (코치 되묻기)
부모: 푸시 수신 → 반려 + 사유 입력
아이: 반려 사유 확인 → 재제안
부모: 승인 → 모의투자 계좌로 실제 체결
아이: 카드 상세에서 "내가 쓴 이유"와 체결 결과를 나란히 확인
```

이 흐름에서 끊기는 지점이 있으면 그게 최우선 과제다. 트랙별 진행이 이 시나리오에
수렴하는지 매주 확인한다.

- 뉴스 트랙(박혜준·강소정)의 미확정 3건(뉴스 소스·검수 워크플로·종목 매핑)은 **팀장 결정이 필요하다.**
  오래 열어두면 그 트랙이 스키마를 못 고정한다.
- 전략시뮬게임 트랙(이재용·이호연)은 자체 백로그(`docs/mvp-backlog.md`)로 돌아간다.
  Tier 1 사람 게이트("한 판 더 하고 싶은가")는 루프가 판단하지 않으니 팀이 직접 평가해야 한다.

## 3. 작업 경로

| 경로 | 내용 |
|---|---|
| `web/app/parent/` | 부모 화면 — 진입 배너, 초대, 제안 수신, 승인/반려, 대화 스크립트 |
| `web/app/api/proposals/` | 제안 생성·조회·응답·체결·스크립트 |
| `web/app/api/invite/` | 초대코드 발급·리딤 |
| `web/lib/rules.ts` | 안전장치 — 라우트는 여기만 호출한다 |
| `web/lib/kiwoom.ts` | 키움 REST(모의투자) |

## 4. 반드시 지킬 것

- **반려 사유 입력은 스킵 불가.** 서버가 422로 막는다(`checkReason`). 프론트에서만 막으면 안 된다.
  "그냥 안 돼"가 통과되는 순간 이 서비스는 학습이 아니라 복종 훈련이 된다(기획안 3-5).
- **승인 화면에 현재가·수량·예상 체결금액을 다시 보여주고 최종 확인을 받는다.**
  제안 시점과 승인 시점의 가격이 다르다(기획안 3-3).
- **제안서 유효기간 7일.** 만료는 실패가 아니라 학습 소재로 처리한다 — "기회는 지나가기도 해."
- **재제안권.** 아이가 반려에 반박하고 다시 올릴 수 있어야 한다.
- **체결은 모의투자 계좌로 시연하되 파이프라인은 실계좌와 동일하다.**

## 5. 경계

- `web/app/kid`(아이 화면)와 `web/lib/llm.ts`·`stocks.ts`·`holdings.ts`는 김경렬 경계다.
- `web/app/kid/news`·`web/lib/news`·`web/app/api/news`는 뉴스 트랙 경계다.
- `web/lib/types.ts`·`web/lib/db.ts`·`web/app/layout.tsx`는 핫스팟 — 이재용에게 계약 PR을 요청한다.
- `game/`은 다른 트랙이다.

## 6. 검증

```powershell
cd web; npm run typecheck
cd web; npm test           # 안전장치 규칙 단위 테스트
cd web; npm run dev        # 별도 터미널
cd web; npm run verify     # 기획안 조항 검증
```

`web/scripts/verify.ts`가 기획안 조항을 실행 가능한 형태로 담고 있다.
**기능을 추가할 땐 체크를 먼저 쓰고 구현한다.** 특히 반려 사유 422와 7일 만료는 체크로 고정한다.
