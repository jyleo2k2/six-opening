# 강소정 — AI 명령 프롬프트 가이드 (뉴스 아이 화면)

> 이 문서를 Claude/Codex에 그대로 복사·붙여넣기 해서 쓴다.

## 0. 사용법

1. 새 대화에서 §1 온보딩을 한 번 보낸다.
2. AI가 "읽었음"이라고 요약하면 §3에서 지금 할 작업 블록을 보낸다.
3. AI가 계획을 제시하면 이상 없을 때 "진행해"라고 한다.
4. 만들면 §5 자가검증을 보낸다.

## 1. 온보딩 프롬프트 (대화 시작 시 1회)

```
너는 "물려주는 계좌 — 영웅문 주니어"의 뉴스 화면(아이가 보는 쪽) 작업을 돕는다.
나는 강소정, 뉴스 프론트 담당이다. 설명은 쉽고 명확하게.
먼저 아래 파일을 읽고 "읽었음"과 함께 ① 내가 할 일 ② 내가 하면 안 되는 것
③ 꼭 지킬 핵심 규칙을 정리해줘. 아직 만들지 마.
읽을 파일: 1.CLAUDE.md 2.docs/team/_공통_AI규칙.md(헌장) 3.docs/team/강소정/강소정-담당업무.md
4.web/AGENTS.md 5.물려주는계좌_기획안.md(3-3·5장) 6.web/app/page.tsx(기존 화면 스타일)
환경: Next.js 16 + React 19, 화면은 "use client". 모션 motion, 바텀시트 vaul, 토스트 sonner.
작업 폴더: web/app/kid/news. 검증은 web 폴더에서 npm run typecheck + dev 서버 눈확인.
```

## 2. 고정 규칙

```
[고정 규칙]
1. web/app/layout.tsx는 절대 건드리지 않는다(핫스팟). 내비 연결이 필요하면 "연결 PR 필요"라고만 보고해라.
2. web/lib/news와 web/app/api/news는 박혜준 경계다. 응답이 부족해도 직접 고치지 말고 요청 내용으로 정리해라.
3. 화면에서 텍스트를 만들거나 가공하지 않는다. API가 준 검수 완료 문구를 그대로 렌더한다.
4. 아이 언어로 쓴다. 어른용 경제 기사 톤 금지. "오를 것" 같은 전망·권유 표현이 보이면 데이터 문제로 보고해라.
5. 모르는 값은 지어내지 말고 "TODO: 확인 필요" 표시. 목업 기사를 실제 데이터처럼 커밋하지 않는다.
6. 한국어 파일은 편집도구/UTF-8로만. main 직접 push 금지(브랜치→PR).
```

## 3. 작업별 명령 프롬프트

### 3-1. 뉴스 목록 화면

```
[작업] web/app/kid/news/page.tsx를 만들어줘. 검수 완료된 뉴스를 최신순 카드 목록으로 보여준다.
카드에는 눈높이 제목, 발행일, 연결된 종목이 있으면 종목 배지.
[제약] web/app/kid/news 아래에만 파일을 만든다. layout.tsx 건드리지 않는다.
430px 세로 기준. 기존 web/app/page.tsx의 카드 스타일을 재사용한다.
API가 아직 없으면 fetch 경로만 잡고 빈 상태·로딩 상태를 먼저 만든다.
[검증] npm run typecheck 통과 + dev 서버에서 스크린샷. 빈 상태·로딩 상태도 각각 확인.
[산출물] 계획 먼저 → "진행해" 하면 구현.
```

### 3-2. 뉴스 상세 + 제안서 연결

```
[작업] 뉴스 상세 화면을 만들고, 연결된 종목이 있으면 하단에 "이거 사고 싶어?" 버튼으로
제안서 작성 화면으로 넘어가게 해줘.
[제약] 제안서 화면 자체는 김경렬 경계다 — 링크만 건다. 버튼을 누르면 어떤 경로로 가는지
먼저 확인하고, 경로가 아직 없으면 TODO로 남긴다.
원문 링크는 새 탭으로 연다.
[검증] npm run typecheck + dev 서버에서 실제로 눌러보고 스크린샷.
[산출물] 계획 먼저 → "진행해" 하면 구현.
```

### 3-3. 빈 상태·에러 상태

```
[작업] 뉴스가 하나도 없을 때와 불러오기 실패했을 때 화면을 만들어줘.
[제약] 아이가 읽는 문구다. "500 Internal Server Error" 같은 기술 문구 금지.
불안하게 만들지 않는 톤으로. 재시도 버튼 하나.
[검증] API를 일부러 죽이고 실제로 그 화면이 뜨는지 확인 + 스크린샷.
[산출물] 계획 먼저 → "진행해" 하면 구현.
```

## 4. 막히면 그대로 보내기

- 한 번에 하나: `지금은 [이것]만 하자. 다른 건 건드리지 마.`
- 경계 점검: `혹시 layout.tsx나 web/lib 건드렸어? 건드렸으면 되돌려줘.`
- 눈확인: `dev 서버에 띄워서 스크린샷 보여줘. 430px 세로 기준으로.`

## 5. 자가검증 프롬프트 (PR 전)

```
방금 만든 걸 점검하고 표로 보고해줘 (실제로 실행/확인해서):
1. web/app/kid/news 밖 파일을 건드렸나? (특히 layout.tsx, web/lib)
2. 화면에서 텍스트를 생성·가공한 곳이 있나?
3. npm run typecheck 통과했나? (결과 붙여줘)
4. 스크린샷 — 430px에서 텍스트 겹침·잘림 없나? 빈 상태·에러 상태도 확인했나?
5. 어른 톤이나 투자 권유로 읽히는 문구가 있나?  6. 한국어 안 깨졌나?
아니오가 있으면 고친 뒤 다시 보고해.
```
