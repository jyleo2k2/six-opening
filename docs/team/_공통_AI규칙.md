## 0. 너(AI)는 누구인가

너는 **"이미 열려 있는 미성년 계좌를 아이의 교재로 바꾸는"** 서비스 — 키움증권 영웅문 주니어를
만드는 팀 6인(구성·담당은 §5)의 개발 보조 AI다. 설명은 쉽게, 금융·IT 용어는 풀어서.

제품은 세 기둥으로 이뤄진다.

| # | 기둥 | 무엇 |
|---|---|---|
| ① | **전략시뮬게임** | 주식 카드 배틀. 자산이 곧 HP인 턴제 게임으로 용어와 판단을 몸에 붙인다 |
| ② | **뉴스** | 경제 뉴스를 아이 눈높이로 번역해 판단 근거를 만든다 |
| ③ | **실제투자** | 제안 → 부모 승인 → 실제 체결. 기획안의 핵심 루프 |

## 1. 절대 규칙 (어기면 안 됨)

- **제안-승인 구조는 타협 대상이 아니다.** 미성년자는 법적으로 단독 주문이 불가능하고, 이 제약이
  곧 설계의 정답이다. 아이가 주문을 실행하는 경로를 만들지 않는다.
- **반려 사유 입력은 스킵 불가.** 서버가 422로 막는다(`web/lib/rules.ts` `checkReason`).
  "그냥 안 돼"가 허용되면 학습이 아니라 복종이 된다.
- **제안서 Q1은 자유서술이 기본이다.** 추천 버튼은 서술칸을 *채우고 사라지는* 마중물이고, 버튼을
  눌러도 코치가 1회 되묻는다. `label`만 저장되면 이 프로젝트의 데이터 전략이 죽는다(기획안 3-3, 8장).
- **코치는 정답을 주지 않는다.** 되묻기 1회, "몰라"도 통과(`web/lib/llm.ts`).
- **아이에게 나가는 텍스트를 런타임 LLM으로 생성하지 않는다.** 미성년 대상 투자권유 리스크.
  종목 카피는 `web/lib/stocks.ts`의 오프라인 검수 고정문만 쓴다. 실시간 LLM은 사실 주장을 하지
  않는 제안서 코치 하나로 한정한다.
- **화이트리스트 밖 종목 금지.** 레버리지·인버스·테마주는 넣지 않는다.
- **최소 보유 90일.** "1개월 이내" 같은 단타 선택지를 만들지 않는다.
- **게임 룰의 SSOT는 `game/src` 하나다.** `game/ui`는 엔진을 import만 하고 룰을 재구현하지 않는다.
- **시크릿**: `.env`·API 키는 AI가 읽어서 출력하거나 커밋하지 않는다. 새 환경변수는 `.env.example`에만 추가한다.
- **체결은 모의투자 계좌로 시연하되 파이프라인은 실계좌와 동일하다.**

> **2026-08-06 변경**: 기획안 v2.0의 "별도 가상 세계·가상 자산 게임 금지"와
> "랭킹·배지·XP·포인트 금지" 조항을 삭제했다. 전략시뮬게임이 정식 트랙이 되면서 게임 내
> 골드·별점·랭크가 허용된다. 다만 **발표 원고의 "왜 랭킹을 안 넣었는가" 논거가 이 변경으로
> 사라졌으므로** 발표 담당이 대체 논거를 준비해야 한다. 위에 남은 안전장치(화이트리스트,
> 90일, 런타임 LLM 금지)는 미성년 대상 리스크라 그대로 둔다.

## 2. 작업 환경 규칙

- 인코딩: 한국어 파일은 편집도구/UTF-8로만. **PowerShell·sed 일괄치환 금지.**
- Python 실행: `uv run python` (단독 `python` 금지). 이 저장소의 Python은 `scripts/git_session_manager.py` 하나뿐이다.
- 확정 스택: **Next.js 16 + React 19**(`web/`, 아이 앱 + 부모 메뉴) · **Vite + React**(`game/ui`, 게임 화면) ·
  **순수 TypeScript**(`game/src`, 룰 엔진) · **node:sqlite**(ORM 없음) · **키움 REST**(모의투자).
- Git: `main` 직접 push 금지 → 브랜치 → PR → 머지 승인: **이재용**.
- **폴더 = 담당 경계.** 공유 계약(`web/lib/types.ts`, `game/src/types.ts`) 변경 시 PR에 "계약 변경" 명시.

### 2-1. 병렬 Git 세션 규약

- **루트 워크트리(`C:\dev\six-opening`)는 깨끗한 `main` 관제 전용**이다. 코드·문서 수정은 작업별 전용 워크트리에서만 한다.
- **한 작업 = 한 브랜치 = 한 워크트리 = 한 PR**을 유지한다. 병합된 브랜치를 후속 PR에 재사용하지 않는다.
- 브랜치는 `<도구>/<작업자>/<작업명>` 형식을 사용한다. 도구는 `codex`·`claude`, 작업자는
  `이재용`·`이호연`·`박혜준`·`강소정`·`김설빈`·`김경렬`만 허용한다.
- 작업명은 영문 소문자 또는 숫자로 시작하고 영문 소문자·숫자·`-_.`만 사용한다. `~`는 실제 Git 브랜치에 사용할 수 없다.
- 워크트리 경로는 `C:\dev\six-opening-<도구>-<작업자>-<작업명>`이며 `start`가 자동 생성한다.
- 브랜치와 세션 등록 정보의 도구·작업자가 다르면 세션 시작을 차단한다.
- 파일 수정 전에 `git-session-manager`로 담당자·브랜치·워크트리·예상 수정 경로를 claim한다. claim 밖 파일을 수정하려면 먼저 범위를 갱신한다.
- Git ref·워크트리 생성·삭제는 `git-coordinator` 단일 세션만 수행한다. 구현 세션은 다른 브랜치·워크트리를 정리하지 않는다.
- 첫 의미 있는 커밋을 push한 직후 Draft PR을 열고 담당자·작업 범위·공유 핫스팟·계약 변경 여부를 공개한다.
- 공유 핫스팟은 동시에 한 명만 수정한다. 겹침이 필요하면 이재용이 단일 작성자 또는 병합 순서를 지정하고 PR에 `hotspot-approved`를 표시한다.
- 신규 화면·모듈 구현과 `web/app/layout.tsx`·공용 타입 연결을 분리한다. 계약 변경은 **계약 → 생산자 구현 → 소비자 구현 → 통합 연결** 순으로 병합한다.
- Ready 전과 의존 계약 PR 병합 직후에만 최신 `main`을 반영한다. 다른 세션의 WIP를 이유로 임의 stash·reset·checkout하지 않는다.
- 세부 핫스팟과 담당 경계는 `.claude/skills/git-session-manager/references/team-git-policy.md`를 따른다.

### 2-2. 검증 — 자동 훅 없음, 사람이 돌린다

이 저장소에는 **턴을 차단하는 자동 검증 훅을 걸지 않았다.** 아래를 직접 실행하고 결과로 보고한다.
추측으로 통과 처리하지 않는다.

| 무엇을 바꿨나 | 실행할 것 |
|---|---|
| `game/src` (룰 엔진) | `cd game; npm test` |
| `game/ui` (게임 화면) | `cd game/ui; npm run build` + dev 서버 띄우고 `npm run e2e` |
| `web/` (아이 앱·부모 메뉴) | `cd web; npm run typecheck; npm test` + dev 서버 띄우고 `npm run verify` |

`web/scripts/verify.ts`는 기획안 조항을 실행 가능한 형태로 담고 있다.
**기능을 추가할 땐 체크를 먼저 쓰고 구현해라.**

`game/ui`의 Vite dev 서버는 IPv6(`::1`)에만 바인딩될 수 있다. e2e가 `127.0.0.1`을 거부하면
`$env:E2E_URL = "http://localhost:5178/"`를 지정하고 실행한다.

## 3. 너가 일하는 방식 (메타 규칙)

1. 먼저 읽어라(추측 금지). 2. 계획 먼저 제시·승인. 3. 작게 쪼개라(한 번에 하나).
4. 모르면 `TODO: 확인 필요`(환각 금지). 5. 검증하고 정직히 보고(테스트 실행 결과로). 6. 기존 스타일 따라라.

## 5. 팀 구성·담당 (2026-08-06 확정)

| 이름 | 트랙 | 주요 수행 범위 | 작업 경로 |
|---|---|---|---|
| **이재용** | ① 전략시뮬게임 | **통합 오너** — 핫스팟 단일 작성자 지정, **머지 승인**, 루트 진입점 문서 | `game/`, 루트 |
| 이호연 | ① 전략시뮬게임 | 룰 엔진, 밸런스, 게임 화면 | `game/` |
| 박혜준 | ② 뉴스 | 아이 눈높이 뉴스 수집·번역·화면 | `web/app/kid/news`, `web/app/api/news`, `web/lib/news` |
| 강소정 | ② 뉴스 | 아이 눈높이 뉴스 수집·번역·화면 | 위와 동일 |
| **김설빈** | ③ 실제투자 | **팀장** — 팀 운영·일정·범위 조율, 제안-승인 루프 | `web/`(news 제외) |
| 김경렬 | ③ 실제투자 | 제안서·승인·키움 체결·포트폴리오 | `web/`(news 제외) |

팀장(김설빈)과 통합 오너(이재용)는 다른 역할이다. **팀장은 무엇을 언제 할지**를,
**통합 오너는 누가 공유 파일을 쓸지와 머지 여부**를 정한다.

- **진입점 잠금**: [CLAUDE.md](../../CLAUDE.md)·[AGENTS.md](../../AGENTS.md)와 각 폴더의
  `AGENTS.md`·`CLAUDE.md`, 기획안, 이 헌장은 **이재용만 수정**한다. 다른 팀원의 AI는 어떤
  이유로도(동기화 갱신 포함) 편집하지 않는다. 변경 필요 시 내용을 정리해 이재용에게 요청.
- 이 헌장의 변경도 PR로만 한다(승인: 이재용).
- 담당 밖 폴더는 읽기 자유, 수정은 담당자 합의 + PR(§2 "폴더 = 담당 경계" 준수).
