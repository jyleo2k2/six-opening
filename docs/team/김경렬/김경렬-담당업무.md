# 김경렬 — 담당업무 (실제투자 · 아이 화면과 제안서)

## 1. 역할

아이가 보는 화면 전부와, 그 화면이 쓰는 종목·코치 API를 담당한다.
기획안 §11의 아이 앱 화면 8개(A 수준)가 내 몫이다.

| # | 화면 | 상태 |
|---|---|---|
| 1 | 홈 — 내 자산 (아이 언어 번역, 종목 카드 3줄) | A |
| 2 | 제안서 작성 Step 1~3 (자유서술 + 마중물 버튼 + 코치) | A |
| 3 | 제안 완료 · 부모 답변 대기 · 7일 만료 | A |
| 4 | 부모 답변 수신 (승인 / 반려 + 사유) | A |
| 5 | 카드 앨범 (전체 · 승인 · 반려) | A |
| 6 | 카드 상세 — 판단 타임라인 (내가 쓴 이유 + 지금) | A |
| 7 | 재제안 | A |
| 8 | 예습 모드 — 1화면. 종목 선택 → "3개월 전에 샀다면 지금" → `제안서 쓸래?` | A |

## 2. 반드시 지킬 것 — 이 프로젝트에서 가장 중요한 설계

**제안서 Q1은 자유서술이 기본이다.** 3문항을 객관식으로 받으면 저장되는 것이 아이의 판단이 아니라
우리가 만든 선택지가 된다. 프로젝트의 데이터 전략 절반이 여기서 죽는다(기획안 3-3, 8장).

```
[상단]  자유서술 칸          ← 항상 열려 있는 기본 입력
[하단]  "막히면 이렇게 써도 돼 👇"
        추천 2개 (종목별로 다름)  ← 누르면 서술칸을 채우고 사라진다
          ↓
[코치]  되묻기 1회
          ↓
[저장]  label(구조화) + text(아이 원문) + coach_answer(근거)
```

| 원칙 | 이유 |
|---|---|
| 버튼은 **채우고 사라진다** | 선택으로 끝나면 라벨만 남는다. 채우면 원문이 남는다 |
| 되묻기는 **1회만** | 두 번 이상 캐물으면 아이가 이탈한다 |
| **"몰라"도 통과** | 강제하면 서비스를 안 쓴다 |

추천 2개는 고정 3지선다가 아니라 **종목별로 다르게** 제시한다.
프로토타입: `prototype/step1-input.html`

그 밖에:

- **코치는 정답을 주지 않는다.** 되묻기 1회만. 이 서비스의 유일한 실시간 LLM이고
  **사실 주장을 하지 않는다**(`web/lib/llm.ts`).
- **종목 카피는 `web/lib/stocks.ts`의 오프라인 검수 고정문만 쓴다.** 런타임 LLM으로 만들지 않는다.
- **화이트리스트 밖 종목 금지.** 레버리지·인버스·테마주는 넣지 않는다.
- **최소 보유 90일.** "1개월 이내" 같은 선택지를 만들지 않는다.
- **아이 화면의 1순위 CTA는 "내가 쓴 이유 다시 보기"다.** 수익률은 2순위.
- **손실도 그대로 보여준다.** 왜 떨어졌는지 카드로 설명한다.

## 3. 작업 경로

| 경로 | 내용 |
|---|---|
| `web/app/kid/` (news 제외) | 아이 화면 전부 |
| `web/app/api/coach/` | 제안서 코치 (되묻기 1회) |
| `web/app/api/classify/` | 이유 유형 분류 |
| `web/app/api/stocks/` | 화이트리스트 종목 |
| `web/app/api/portfolio/` | 보유 조회 |
| `web/app/api/preview/` | 예습 모드 |
| `web/lib/llm.ts` · `web/lib/stocks.ts` · `web/lib/holdings.ts` | 위 API의 로직 |

## 4. 경계

- `web/app/parent`·`web/app/api/proposals`·`web/app/api/invite`·`web/lib/rules.ts`·`kiwoom.ts`는 김설빈 경계다.
  제안 제출·응답 API가 부족하면 직접 고치지 말고 요청한다.
- `web/app/kid/news`는 강소정 경계다. 아이 홈에서 뉴스로 가는 링크만 건다.
- `web/lib/types.ts`·`db.ts`·`web/app/layout.tsx`는 핫스팟 — 이재용에게 계약 PR을 요청한다.
- `game/`은 다른 트랙이다. 예습 모드와 전략시뮬게임은 별개다 — 예습 모드는 1화면이다.

## 5. 검증

```powershell
cd web; npm run typecheck
cd web; npm test
cd web; npm run dev        # 별도 터미널
cd web; npm run verify     # 기획안 조항 검증
```

화면 작업은 타입체크로 다 못 잡는다. dev 서버에 띄워 430px 세로 기준으로 눌러보고 확인한다.
**제안서 입력 흐름은 특히 verify에 체크를 먼저 쓰고 구현한다** —
"버튼을 눌러도 text 원문이 저장된다", "되묻기는 1회를 넘지 않는다", "'몰라'도 저장된다".
