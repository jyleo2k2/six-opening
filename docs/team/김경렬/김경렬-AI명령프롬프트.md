# 김경렬 — AI 명령 프롬프트 가이드 (아이 화면 · 제안서)

> 이 문서를 Claude/Codex에 그대로 복사·붙여넣기 해서 쓴다.

## 0. 사용법

1. 새 대화에서 §1 온보딩을 한 번 보낸다.
2. AI가 "읽었음"이라고 요약하면 §3에서 지금 할 작업 블록을 보낸다.
3. AI가 계획을 제시하면 이상 없을 때 "진행해"라고 한다.
4. 만들면 §5 자가검증을 보낸다.

## 1. 온보딩 프롬프트 (대화 시작 시 1회)

```
너는 "물려주는 계좌 — 영웅문 주니어"의 아이 화면과 제안서 작성 흐름 작업을 돕는다.
나는 김경렬, 실제투자 트랙의 아이 쪽 담당이다. 설명은 쉽고 명확하게.
먼저 아래 파일을 읽고 "읽었음"과 함께 ① 내가 할 일 ② 내가 하면 안 되는 것
③ 꼭 지킬 핵심 규칙(특히 제안서 Q1 자유서술)을 정리해줘. 아직 만들지 마.
읽을 파일: 1.CLAUDE.md 2.docs/team/_공통_AI규칙.md(헌장) 3.docs/team/김경렬/김경렬-담당업무.md
4.web/AGENTS.md 5.물려주는계좌_기획안.md(3-3·11장) 6.web/lib/llm.ts 7.prototype/step1-input.html
환경: Next.js 16 + React 19, 화면은 "use client". 검증은 web 폴더에서
npm run typecheck / npm test / npm run verify. 작업 폴더: web/app/kid(news 제외),
web/app/api/{coach,classify,stocks,portfolio,preview}, web/lib/{llm,stocks,holdings}.ts.
```

## 2. 고정 규칙

```
[고정 규칙]
1. 제안서 Q1은 자유서술이 기본이다. 추천 버튼은 서술칸을 채우고 사라지는 마중물이다.
   label만 저장되고 아이 원문(text)이 안 남으면 그 구현은 틀린 것이다.
2. 코치는 정답을 주지 않고 되묻기 1회만 한다. "몰라"도 통과시킨다. 사실 주장을 하지 않는다.
3. 종목 카피는 web/lib/stocks.ts의 검수 고정문만 쓴다. 런타임 LLM으로 아이 화면 텍스트를 만들지 않는다.
   (예외: 코치 되묻기 하나뿐)
4. 화이트리스트 밖 종목, "1개월 이내" 같은 단타 선택지를 만들지 않는다.
5. web/app/parent, web/app/api/proposals, web/lib/rules.ts, kiwoom.ts는 김설빈 경계다. 건드리지 않는다.
   web/lib/types.ts, db.ts, web/app/layout.tsx는 핫스팟이다 — "계약 변경 필요"라고 보고만 해라.
6. 모르는 값은 지어내지 말고 "TODO: 확인 필요" 표시.
7. 한국어 파일은 편집도구/UTF-8로만. main 직접 push 금지(브랜치→PR).
```

## 3. 작업별 명령 프롬프트

### 3-1. 제안서 Step 1 (자유서술 + 마중물)

```
[작업] 제안서 작성 Step 1 화면을 만들어줘. 상단에 자유서술 칸이 항상 열려 있고,
하단에 "막히면 이렇게 써도 돼 👇" + 종목별 추천 2개. 버튼을 누르면 서술칸을 채우고 그 버튼은 사라진다.
[제약] 추천 문구는 고정 3지선다가 아니라 종목별로 다르게 나와야 한다(web/lib/stocks.ts에서 파생).
prototype/step1-input.html의 A/B 결과를 먼저 확인하고 그 결론을 따른다.
저장은 label + text(원문) + coach_answer 세 개 전부.
[검증] web/scripts/verify.ts에 "버튼을 눌러도 text 원문이 저장된다" 체크를 먼저 쓰고 구현.
dev 서버에서 실제로 눌러보고 스크린샷.
[산출물] 계획 먼저 → "진행해" 하면 구현.
```

### 3-2. 코치 되묻기

```
[작업] 아이가 쓴 이유에 코치가 1회 되묻는 흐름을 붙여줘.
[제약] 되묻기는 정확히 1회. 두 번째 되묻기 경로가 존재하면 안 된다.
"몰라"라고 답해도 그대로 저장되고 다음 단계로 넘어간다.
코치는 사실 주장("이 회사는 성장할 거야")을 하지 않는다 — 되묻기만 한다.
[검증] verify에 "되묻기는 1회를 넘지 않는다"와 "'몰라'도 저장된다" 체크를 먼저 추가.
실제로 "몰라"를 넣어서 통과하는지 확인해줘.
[산출물] 계획 먼저 → "진행해" 하면 구현.
```

### 3-3. 카드 상세 — 판단 타임라인

```
[작업] 카드 상세 화면을 만들어줘. "내가 쓴 이유"와 "지금"을 나란히 붙인 타임라인이다.
[제약] 1순위 CTA는 "내가 쓴 이유 다시 보기". 수익률은 2순위로 작게.
떨어져도 그대로 보여준다 — 손실을 숨기거나 완곡하게 바꾸지 않는다.
랭킹·순위·비교는 넣지 않는다(아이가 지면 상처받는다 — 기획안 5장).
[검증] npm run typecheck + dev 서버에서 손실 상태 데이터로도 스크린샷 확인.
[산출물] 계획 먼저 → "진행해" 하면 구현.
```

## 4. 막히면 그대로 보내기

- 한 번에 하나: `지금은 [이것]만 하자. 다른 건 건드리지 마.`
- 자유서술 점검: `버튼만 누르고 넘어가면 아이 원문이 저장돼? 안 되면 고쳐줘.`
- 경계 점검: `혹시 web/app/parent나 rules.ts 건드렸어? 건드렸으면 되돌려줘.`
- 눈확인: `dev 서버에 띄워서 스크린샷 보여줘. 430px 세로 기준으로.`

## 5. 자가검증 프롬프트 (PR 전)

```
방금 만든 걸 점검하고 표로 보고해줘 (실제로 실행/테스트해서):
1. 추천 버튼만 눌러도 아이 원문(text)이 저장되나? (실제 저장된 값 붙여줘)
2. 코치 되묻기가 2회 이상 가능한 경로가 있나? "몰라"도 통과되나?
3. 아이 화면 텍스트를 런타임 LLM으로 만든 곳이 있나? (코치 제외)
4. 김설빈 경계(parent, proposals, rules, kiwoom)나 핫스팟을 건드렸나?
5. npm run typecheck / npm test / npm run verify 결과가 뭔가? (실행 결과 붙여줘)
6. 스크린샷 — 430px에서 텍스트 겹침·잘림 없나?  7. 한국어 안 깨졌나?
아니오가 있으면 고친 뒤 다시 보고해.
```
