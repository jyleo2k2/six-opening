# 키웅이 선제 도움 — 타이밍·수용성 리서치

> 최종 검토: 2026-08-12  
> 목적: 키웅이가 필요한 순간 먼저 돕되 자녀에게 귀찮음·감시감·과잉 도움을 만들지 않기 위한 근거와 검증 기준 정리  
> 문서 경계: 제품 결정은 `docs/영웅키움_기획_통합문서_v2.md`, 구현값은 `web/features/f10-chatbot/SPEC.md`가 단일 원본이다. 이 문서는 연구 근거와 PoC 검증안만 소유하며 현재 확정된 선제 신호 3종을 변경하지 않는다.

표기: **[사실]** 출처가 직접 뒷받침 / **[추론]** 연구를 영웅 키움에 적용한 해석 / **[가정]** 자녀 테스트 전 초기안.

## 1. 결론

**[추론] 선제 도움은 `도움 필요성`과 `현재 수용 가능성`이 동시에 확인될 때만 노출한다.**

```text
선제 발화 = 도움 필요 신호가 충분함
          AND 지금 도움을 받아들일 수 있음
          AND 최근 거절·발화 제한에 걸리지 않음
```

- **[추론]** 능동성을 발화 횟수로 강화하지 않는다. 신호는 소수로 유지하고 수락 뒤의 설명·화면 연결 품질을 높인다.
- **[추론]** 첫 발화는 정답이나 긴 설명이 아니라 짧은 도움 제안이어야 한다. 사용자가 수락한 뒤 `힌트 → 쉬운 설명 → 관련 화면` 순으로 깊어진다.
- **[추론]** 오탐을 완전히 제거하기 어렵기 때문에 거절·뮤트뿐 아니라 개입 이유 확인과 오탐 정정 경로가 필요하다.
- **[사실]** 자녀용 모의투자 선제 챗봇을 직접 검증한 연구는 이번 조사에서 확인하지 못했다. 아래 근거는 건강 JITAI, 교육용 튜터, 성인 대화 에이전트, 아동 HCI와 아동 설계 지침을 결합한 인접 근거다.

## 2. 연구 근거

| 연구축 | 확인된 결과 [사실] | 영웅 키움 적용 [추론] | 한계 |
|---|---|---|---|
| JITAI 적시 개입 | JITAI는 개인의 변하는 상태에 맞춰 **적절한 종류·양의 지원을 적절한 시점**에 제공하는 설계다. | 행동 신호만으로 즉시 발화하지 않고 수용 가능 상태를 함께 확인한다. | 건강 행동 분야 중심이며 자녀·투자 맥락이 아니다. |
| Micro-randomized trial | 개입 가능한 각 시점에 발화 여부를 무작위화하면 개입 직후의 인과 효과와 적절한 타이밍을 신호별로 추정할 수 있다. | 30세션 PoC에서 같은 조건의 `발화`와 `미발화`를 비교한다. | 30세션은 통계적 결론보다 방향 확인에 적합하다. |
| Assistance Dilemma | 교육용 튜터에서는 정보를 너무 많이 주면 스스로 구성할 기회를 줄이고, 너무 적게 주면 좌절·시간 낭비를 만들 수 있다. | 완성 답변을 먼저 주지 않고 도움의 깊이를 단계화한다. | 인지 튜터 연구이며 금융 챗봇 실험이 아니다. |
| 능동형 AI의 오탐과 복구 | 성인 175명 실험에서 false positive 개입은 false negative 조건보다 에이전트 수용성과 토론 경험이 낮았다. 사용자가 판정을 반박하고 에이전트가 정정하는 복구 전략은 false positive 조건의 경험을 개선했다. | 높은 재현율보다 오탐이 적은 보수적 신호를 우선하고, 아이가 AI 판단을 정정할 수 있게 한다. | 성인 그룹 채팅 참여 독려 상황이다. |
| 아동 맥락 기반 도움 | 2026년 아동 그림 탐색 연구에서 시선 맥락 기반 도움은 무작위 도움보다 현재 관심 대상에 주의를 더 오래 유지시키고 관련 영역 탐색을 더 잘 유도했다. 아이·부모·참여 교사도 더 긍정적으로 평가했다. | 고정 주기나 무작위 발화보다 현재 화면·행동과 직접 연결된 도움만 제공한다. | 2026-07 사전논문이며 그림 탐색 과제다. 금융 서비스 효과를 입증하지 않는다. |
| 아동 넛지 지침 | ICO는 아이에게 개인정보 보호를 약화시키는 조작적 넛지를 금하고, 연령이 높아질수록 명확한 설명과 의식적 판단을 돕는 중립 개입을 권고한다. 휴식·일시정지 같은 웰빙 도구도 제시한다. | 수락과 거절을 동등하게 제시하고 감정·손실을 이용해 대화를 강요하지 않는다. | 영국 규제기관의 설계 지침이며 한국법이나 효과 실험이 아니다. |
| Push–pull 혼합 | 성인 도박 문제 JITAI 연구에서 참여자의 77%가 능동 알림과 자발적 접근을 섞은 방식을 선호했고, 52%는 평가 질문 빈도를 줄이길 원했다. | 키웅이는 짧게 제안만 하고 실제 도움은 아이가 선택해 여는 `push → pull` 구조가 적합하다. | 성인 임상 맥락의 간접 근거다. 자녀 투자 UX 수치로 전용하지 않는다. |

## 3. 제품 적용 원칙

### 3.1 2단계 발화 게이트

#### 1단계 — 도움 필요성

현재 확정된 `switch`, `dwell`, `lossRevisit`만 평가한다. 팀 재결정 없이 신호를 추가하지 않는다.

#### 2단계 — 수용 가능성

**[가정]** 다음 조건을 PoC 후보로 검증한다.

- 앱이 포그라운드이며 최근 터치·스크롤 같은 활동이 있다.
- 주문 입력, 확인 모달, 로딩, 튜토리얼 진행 중이 아니다.
- 아이가 직접 문제를 해결하며 화면 단계가 계속 진행되는 중이 아니다.
- 발화 쿨다운·세션 상한·신호 뮤트에 걸리지 않는다.
- 직전 개입을 거절했거나 빠르게 닫았다면 이후 발화 빈도를 높이지 않는다.

### 3.2 도움의 깊이

```text
상황을 중립적으로 언급
→ 도움이 필요한지 질문
→ 수락 시 한 단계 힌트
→ 추가 요청 시 쉬운 설명
→ 사용자가 눌러 관련 화면으로 이동
```

- **[추론]** 아이 대신 주문·매매 판단을 수행하지 않는다.
- **[추론]** “불안해 보여”, “충동적이야”처럼 감정을 진단하거나 성향을 낙인찍지 않는다.
- **[추론]** 관련 화면 이동도 버튼으로 제안하고 사용자가 눌렀을 때만 실행한다.
- **[추론]** 앱 밖 푸시보다 행동이 발생한 화면 안의 짧은 제안을 우선한다.

### 3.3 통제권과 오탐 복구

현재 F10 명세의 `직접 질문 / 괜찮아`, 신호별 뮤트, 쿨다운, 세션 상한은 유지한다.

아래는 **[가정] 연구 검증 후보**이며 도입 결정이 아니다. 채택하려면 통합문서와 F10 `SPEC.md`를 함께 갱신해야 한다.

- `왜 나타났어?`: 감지한 행동을 쉬운 말로 설명한다.
- `잘못 짚었어`: 아이가 오탐을 표시하면 “내가 잘못 짚었네”라고 인정하고 해당 신호를 세션 뮤트한다.
- `오늘 그만`: 모든 선제 발화를 남은 세션 동안 끈다.
- 선택지는 시각적 무게와 조작 단계를 비슷하게 두며 거절을 숨기지 않는다.

## 4. 현재 선제 신호 3종의 연구 관점 점검

| 신호 | 해석 [추론] | 주요 오탐 위험 | PoC 검증 우선순위 |
|---|---|---|---|
| `switch` | 확인창에서 상반된 행동을 반복하므로 사용법 혼란과 가장 가까운 신호다. | 아이가 기능을 일부러 비교하는 정상 탐색 | 현 기준을 우선 검증한다. |
| `dwell` | 시간만으로는 도움 필요성과 수용 가능성을 구분하기 어렵다. | 읽기, 보호자와 대화, 앱을 켜둔 채 이탈 | 현 5분 기준을 베이스라인으로 두고 `활동 있음 + 단계 진전 없음` 조건을 실험한다. |
| `lossRevisit` | 최근 사건과 현재 화면의 관련성이 높아 맥락 도움에는 적합할 수 있다. | 단순 가격 확인을 불안으로 오인하거나 감시감을 줄 수 있음 | 중립 문구·개입 이유 설명·즉시 뮤트를 함께 검증한다. |

`dwell`의 활동·진전 조건과 `lossRevisit`의 대안 문구는 **[가정] 실험안**이다. 현재 구현 기준은 F10 `SPEC.md` §7을 따른다.

## 5. 30세션 PoC 검증안

### 5.1 방법

**[가정]** 각 신호가 발화 가능 상태가 된 시점마다 `발화`와 `미발화`를 1:1로 배정한다. 같은 아이에게도 시점별로 다시 배정하는 micro-randomized 방식으로 신호별 직후 효과를 비교한다.

- 30세션 결과는 유의성 확정이 아니라 임계값 조정과 제거 후보 선별에 사용한다.
- 신호별 표본이 지나치게 적으면 수치를 확정하지 않고 추가 관찰로 남긴다.
- 테스트 참여자와 보호자에게 행동 이벤트 수집 범위, 목적, 보존 기간을 먼저 설명한다.
- 챗봇 대화 원문과 선제개입 실험 로그는 부모 리포트나 F9 성향 점수에 사용하지 않는다.

### 5.2 최소 이벤트

```text
proactive_eligible   신호가 발화 가능한 상태가 됨
proactive_assigned   show 또는 holdout 배정
proactive_shown      실제 노출
proactive_response   ask / dismiss / mute / why / wrong
proactive_progress   노출 또는 holdout 뒤 120초 안 화면 단계 진전
proactive_repeat     10분 안 같은 막힘 행동 반복
```

이벤트에는 원문 대화나 자유 입력 내용을 넣지 않고 신호 코드, 시각, 화면, 배정, 반응만 기록한다. `why`·`wrong`은 해당 후보 UI를 켠 실험군에서만 수집한다.

### 5.3 지표

| 축 | 지표 | 해석 |
|---|---|---|
| 도움 효과 | 수락률 | 노출 후 `직접 질문`을 선택한 비율 |
| 도움 효과 | 120초 과업 회복률 | 발화군이 미발화군보다 다음 단계로 더 진행했는지 |
| 도움 효과 | 10분 내 같은 행동 재발률 | 도움 뒤 같은 막힘이 감소했는지 |
| 귀찮음 | 3초 내 닫기·`괜찮아` 비율 | 메시지가 즉시 방해로 인식됐을 가능성 |
| 귀찮음 | 뮤트·오탐 표시율 | 반복 노출 거부와 잘못된 추론 정도 |
| 안전 | 주문 시도·거래 빈도 변화 | 챗봇이 거래를 재촉하지 않았는지 |
| 정성 | 도움 필요 순간 일치율 | 관찰자 검토에서 실제 도움 필요 순간과 맞았는지 |

### 5.4 판단 기준

- **유지:** 도움 필요 순간 일치율이 통합문서 기준인 70% 이상이고, 미발화군보다 과업 회복이 좋아지며 귀찮음·거래 빈도가 악화되지 않는다.
- **임계값 조정:** 도움 가능성은 있으나 오탐·즉시 닫기가 높다.
- **제거:** 반복 오탐 또는 감시감이 확인되거나 거래 행동을 늘린다.
- **보류:** 표본이 부족해 방향을 판단할 수 없다.

수락률 하나만으로 성공을 판단하지 않는다. 호기심으로 눌렀더라도 과업 회복이 없거나 이후 뮤트가 늘 수 있기 때문이다.

## 7. 조사 한계

- 검색 범위 안에서 **한국 자녀 + 모의투자 + 선제형 AI 챗봇**을 직접 검증한 연구는 확인하지 못했다. “연구가 없다”는 부재 증명이 아니라 이번 조사에서의 미발견이다.
- 건강·도박 연구의 빈도 수치를 자녀 서비스에 그대로 적용하지 않는다.
- 2026년 아동 연구는 사전논문이며 금융 의사결정 과제가 아니다.
- ICO 문서는 제품 설계 참고자료이며 한국 법률 검토를 대체하지 않는다.
- 따라서 현재 임계값은 계속 **[가정]**으로 두고 자녀 테스트 결과로 조정한다.
