# game — 룰 엔진 · 데이터 · 멀티 서버 · 시뮬 세션 하네스

> 적용 범위: `game/` 하위 전체.
> 규칙 본문은 이 파일에만 쓴다. 같은 폴더 `CLAUDE.md`는 `@AGENTS.md` 한 줄이다 (루트 `AGENTS.md` §동기화).
> 최종 갱신: 2026-08-07 (히스토리 투자 시뮬로 전면 교체 — 카드게임 규칙은 전부 무효)

## 담당 오너

**이재용·이호연** (트랙 ①). 룰 판정과 밸런스 수치의 변경은 오너 합의 후 진행한다.
다른 트랙은 버그 수정·리팩터링이라도 **판정 결과나 시뮬 수치가 바뀌면** 합의 없이 머지하지 않는다.
`data/`의 뉴스·사건 문구는 트랙 ③(김경렬·강소정)이 공급하되, 머지는 트랙 ① 승인으로 한다.

## 세션 시작 규칙

1. 루트 `AGENTS.md` → `docs/기획서.md`(룰 근거) → 이 파일 순서로 읽는다.
2. 루트 `C:\dev\six-opening`에서 고치지 않는다. `git_session_manager.py start`로 워크트리를 받아 거기서 작업한다.
3. claim 범위 밖(`web/` · `content/` · `pipelines/`)은 수정하지 않는다. 범위가 늘면 claim을 먼저 갱신한다.

## 소유 경계

| 경로 | 내용 |
|---|---|
| `src/` | 룰 엔진 — **룰의 SSOT**. 순수 함수만 |
| `data/` | 연대 데이터 팩 (종목 16·이벤트 13·뉴스 풀) — 밸런스 시뮬 대상 |
| `server/` | Colyseus 룸 — 2~8인 방·서버 권위 판정·페이즈 타이머·채팅 릴레이 |
| `sim/` | 봇 셀프플레이 밸런스 시뮬레이터 |
| `tests/` | vitest |

`web/app/(child)/game`도 트랙 ① 소유지만 프론트 규약은 `web/AGENTS.md`를 따른다.

## 불변식

- **`src/`는 순수하다.** I/O·네트워크·DOM·`Date.now()` 의존 금지. 서버와 UI 없이 시뮬이 돌아야 한다.
- **`Math.random()` 직접 호출 금지.** 난수는 `src/rng.ts`(mulberry32, 시드는 상태에 보관)만 쓴다.
  같은 시드 = 같은 판(이벤트 추첨·뉴스 배정·정보 판정·등락폭 전부) = 재현 가능한 시뮬.
- **`src/index.ts` 공개 API가 룰의 유일한 진입점이다.** web·server·sim이 전부 여기만 import한다.
  판정을 클라이언트나 서버에 복제하지 않는다.
- **정보 비대칭 무결성 (기획서 §9).** 이벤트 큐·타인의 뉴스·타인의 정보소 구매 내용을 클라이언트로
  내보내지 않는다. 타인의 현금·보유 내역도 비공개(공개는 총자산뿐). 서버가 상태를 내보낼 때는
  **반드시 `viewFor(state, playerId)`를 거친다** — `broadcast('state', game)` 금지.
- **이벤트 등락의 방향(부호)은 실제 역사를 따른다.** `data/events.ts`의 부호를 바꾸는 PR은 사료
  근거(어떤 사건에 어떤 업종이 실제로 어느 방향으로 움직였나)를 본문에 첨부한다. 폭 수치는 게임
  밸런스 영역이라 시뮬로 조정한다.
- **실존 기업 금지.** 종목은 전부 익명 가상 회사다. 실존 기업명·티커·상표 연상 네이밍을 `data/`에
  넣지 않는다 (확정, 2026-08-07).
- 효과는 **섹터 단위**로 정의한다 (종목 고유 지정 금지). 종목별 차이는 엔진이 범위 내 개별 추첨으로 만든다.
- 가격은 정수 원, 바닥 100원. 채팅·이모티콘은 자산에 영향을 주지 않는다 — 룰 엔진 밖(서버 릴레이)이다.

## 밸런스 수치 변경 규칙

`data/`의 이벤트 폭·종목 시작가나 `src/rules.ts` 상수(정보소 가격·적중률 포함)를 바꾸면 **감이 아니라 수치로 증명한다.**

1. `npm run test -w game` 통과
2. `npm run sim -w game -- 3000`을 변경 전후로 돌려 **전략별 승률·최종자산 p10/p50/p90 ·
   정보 구매 기대이익 · 이벤트 등장 빈도를 전후 표로 PR에 붙인다**
3. 기획서 §7 수치와 어긋나면 기획서 갱신을 이재용에게 요청한다 (기획서는 이재용만 수정)

## 검증 명령

**PowerShell에서 실행한다** — Bash 툴 셸에는 node가 PATH에 없어 `vitest`가 뜨지 않는다.

```powershell
npm run test -w game         # vitest
npm run typecheck -w game    # tsc --noEmit
npm run sim -w game          # 밸런스 시뮬 (기본 1000판)
npm run sim -w game -- 3000  # 수치 변경 시
```
