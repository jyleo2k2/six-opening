# 영웅 키움 — 키움 가족 모의투자 리그

> 부모와 자녀가 **각자 모의투자**를 하고, 수익률이 아니라 **행동 기반 투자성향**을 비교하며 대화 거리를 만드는 가족 리그 데모 웹앱입니다. 자녀 곁에는 AI 챗봇 **"키웅이"** 가 함께합니다.

- 개발 기간: 2026.08.06 ~ (진행 중)
- 실행 앱: `web/` (Next.js) · 데모 시연: 로컬 서버 + Cloudflare 터널
- 영웅문·실계좌·실주문과 연결되지 않은 **모의투자 데모**입니다.

## 왜 만들었나

아이의 첫 투자 교육은 "얼마 벌었니"가 아니라 **"왜 샀니"** 에서 시작해야 한다고 봤습니다. 그래서 이 앱은:

- 매수·매도 때마다 **이유와 계획을 기록**하게 하고,
- 그 행동 데이터를 모아 **투자성향 리포트**(근거력·직관력 등)로 돌려주며,
- 가족끼리 성향과 기록을 비교하는 **리그**로 대화를 유도합니다.

## 주요 기능

| ID | 기능 | 설명 |
|---|---|---|
| F0 | 홈·가족 리그 | 계정(아빠·엄마·자녀)별 홈, 내 자산, 가족 랭킹 |
| F2 | 모의투자 | 51개 종목 탐색(게임형 수집 카드), 종목 상세·뉴스·차트, 매수·매도 3단계 주문, 실시간 시세 |
| F3 | 매매 이유 기록 | 주문 과정에서 "왜 사는지 / 언제까지 들고 갈지"를 함께 기록 |
| F9 | 성장 아카이브 | 행동 데이터 기반 투자성향 리포트, 시즌 카드, 가족 성향 비교 |
| F10 | 키웅이 챗봇 | 자녀용 AI 챗봇. 투자 기초·화면 사용법·종목 공개 정보를 쉬운 말로 설명 |
| F11 | 가족 기록 | 가족의 매매 기록 피드와 댓글·응원 |

### 어린이 안전 원칙 (F10 키웅이)

챗봇은 재미보다 **안전을 우선**하도록 설계했습니다.

- **종목 추천, 매매 시점, 목표가, 수익률 전망, 훈계를 하지 않습니다.** 범위 밖 질문은 정중히 거절합니다.
- 허용 범위: 51개 종목의 공개 정보, 현재 화면 사용법, 금융 기초 개념.
- 모든 LLM 출력은 서버의 필터(`web/shared/llm`)를 거친 뒤에만 화면에 나갑니다. 수치는 LLM이 아니라 서버 도구 값만 사용합니다.
- 어린이 뉴스는 수집 → 선별 → 어린이용 편집 → **독립 검수**의 다단계 역할 파이프라인으로 만듭니다.

## 기술 스택

| 영역 | 사용 기술 |
|---|---|
| 프론트엔드 | Next.js 16 (App Router), React 19, Tailwind CSS 4, Zustand |
| 백엔드 | Next.js Route Handlers (서버 전용), Supabase (PostgreSQL) |
| LLM | OpenAI Responses API — `gpt-5.6-luna` (서버 전용, 필터 경유) |
| 시세 | 토스증권 · 키움 REST Open API (제공자 폴백 사다리 + 캐시) |
| 시연 인프라 | 로컬 프로덕션 서버 + Cloudflare Tunnel (`scripts/local-demo.ps1`) |
| 협업 | 6인 병렬 AI 세션 하네스 (`scripts/git-session-manager.mjs`) |

### 구조 한눈에

```text
web/
├─ app/                  # 캐치올 라우트([[...screen]])·로그인·API (시세/주문/챗봇/피드 …)
├─ features/
│  ├─ f0-home/           # 사용자 화면 전부 (홈·탐색·상세·차트·주문·아카이브·랭킹)
│  ├─ f2-trade/          # 시세·차트·주문 계약과 규칙
│  ├─ f9-archive/        # 성향 리포트 명세
│  ├─ f10-chatbot/       # 키웅이 챗봇 (오버레이·오케스트레이터·안전 게이트)
│  └─ f11-feed/          # 가족 기록 명세
└─ shared/               # engine(수치 계산)·llm(모델·필터)·types·data·ui
supabase/migrations/      # 스키마·시드 (가족 계정·보유·주문 생애주기·뉴스 저장)
scripts/                  # 병렬 세션 하네스 · 시연 스크립트
docs/                     # 기획·기능·디자인·기술 기준 문서
```

- 주소가 곧 화면입니다. 아는 주소만 렌더링하고 모르는 주소는 404입니다.
- 시세는 서버 프록시(`/api/quote`)만 거칩니다. 제공자 장애 시 토스 → 키움 → 보관 캔들 → 픽스처 순으로 내려갑니다.
- 클라우드 대신 **로컬 서버 + Cloudflare 터널**로 시연하는 이유: 시세 API 두 곳이 IP를 검증하기 때문입니다(토스: 사전 등록 IP만 허용, 키움: 토큰 발급 IP와 호출 IP 일치 요구). 자세한 내용은 [docs/로컬시연_터널_가이드.md](docs/로컬시연_터널_가이드.md).

## 실행 방법

```bash
# 1) 의존성 설치
cd web
npm ci

# 2) 환경변수 — 저장소 루트에 .env 생성 (.env.example 참고)
#    SUPABASE_URL / SUPABASE_SECRET_KEY / OPENAI_API_KEY / 시세 제공자 키

# 3) 개발 서버
npm run dev

# 4) 테스트 / 빌드
npm test
npm run build
```

발표·시연(실기기 접속)은 PowerShell에서 한 줄로 실행합니다:

```powershell
.\scripts\local-demo.ps1   # 빌드 → 서버 → 시세 점검 → 터널 개통까지 자동
```

- 키가 없으면 앱은 픽스처 시세로 동작합니다(화면은 전부 열립니다).
- 데모 계정(자녀 `cksdud` · 엄마 `mom` · 아빠 `dad`)의 비밀번호는 저장소에 두지 않고 별도로 전달합니다.

### AI 병렬 협업 방식

6명이 Claude·Codex 세션을 병렬로 돌리면서도 충돌 없이 작업하도록 자체 하네스를 만들어 썼습니다 — 작업마다 전용 브랜치·worktree·파일 claim·Draft PR을 강제하고, 공유 파일은 한 번에 한 세션만 수정합니다. 규칙은 [CLAUDE.md](CLAUDE.md), 구현은 [scripts/git-session-manager.mjs](scripts/git-session-manager.mjs)에 있습니다.
