# 키웅이 선제 도움 — 타이밍·수용성 리서치

> 실행 가능한 페르소나 경계 평가는 [README.md](./README.md)를 따른다.

> 최종 검토: 2026-08-12  
> 목적: 키웅이가 필요한 순간 먼저 돕되 자녀에게 귀찮음·감시감·과잉 도움을 만들지 않기 위한 근거와 검증 기준 정리  
> 문서 경계: 제품 결정은 `docs/영웅키움_기획_통합문서_v2.md`, 구현값은 `web/features/f10-chatbot/SPEC.md`가 단일 원본이다. 이 문서는 연구 근거와 PoC 검증안만 소유하며 현재 확정된 선제 신호 2종을 변경하지 않는다.

표기: **[사실]** 출처가 직접 뒷받침 / **[추론]** 연구를 영웅 키움에 적용한 해석 / **[가정]** 자녀 테스트 전 초기안.

## 1. 결론

**[추론] 선제 도움은 `도움 필요성`과 `현재 수용 가능성`이 동시에 확인될 때만 노출한다.**

```text
선제 발화 = 도움 필요 신호가 충분함
          AND 지금 도움을 받아들일 수 있음
          AND 최근 거절·발화 제한에 걸리지 않음
```

- **[추론]** 능동성을 발화 횟수로 강화하지 않는다. 신호는 소수로 유지하고 수락 뒤의 설명·화면 연결 품질을 높인다.
- **[추론]** 첫 발화는 정답이나 긴 설명이 아니라 짧은 도움 제안이어야 한다. 사용자가 수락한 뒤 `힌트 → 쉬운 설명 → 관련 화면` 순으로 깊어진다.
- **[추론]** 오탐을 완전히 제거하기 어렵기 때문에 거절·뮤트뿐 아니라 개입 이유 확인과 오탐 정정 경로가 필요하다.
- **[사실]** 자녀용 모의투자 선제 챗봇을 직접 검증한 연구는 이번 조사에서 확인하지 못했다. 아래 근거는 건강 JITAI, 교육용 튜터, 성인 대화 에이전트, 아동 HCI와 아동 설계 지침을 결합한 인접 근거다.

## 2. 연구 근거

| 연구축 | 확인된 결과 [사실] | 영웅 키움 적용 [추론] | 한계 |
|---|---|---|---|
| JITAI 적시 개입 | JITAI는 개인의 변하는 상태에 맞춰 **적절한 종류·양의 지원을 적절한 시점**에 제공하는 설계다. | 행동 신호만으로 즉시 발화하지 않고 수용 가능 상태를 함께 확인한다. | 건강 행동 분야 중심이며 자녀·투자 맥락이 아니다. |
| Micro-randomized trial | 개입 가능한 각 시점에 발화 여부를 무작위화하면 개입 직후의 인과 효과와 적절한 타이밍을 신호별로 추정할 수 있다. | 20세션 PoC에서 같은 조건의 `발화`와 `미발화`를 비교한다. | 20세션은 통계적 결론보다 방향 확인에 적합하다. |

| Push–pull 혼합 | 성인 도박 문제 JITAI 연구에서 참여자의 77%가 능동 알림과 자발적 접근을 섞은 방식을 선호했고, 52%는 평가 질문 빈도를 줄이길 원했다. | 키웅이는 짧게 제안만 하고 실제 도움은 아이가 선택해 여는 `push → pull` 구조가 적합하다. | 성인 임상 맥락의 간접 근거다. 자녀 투자 UX 수치로 전용하지 않는다. |

## 3. 제품 적용 원칙

### 3.1 2단계 발화 게이트

#### 1단계 — 도움 필요성

현재 확정된 `switch`, `dwell`만 평가한다. 팀 재결정 없이 신호를 추가하지 않는다.

#### 2단계 — 수용 가능성

**[가정]** 다음 조건을 PoC 후보로 검증한다.

- 앱이 포그라운드이며 최근 터치·스크롤 같은 활동이 있다.
- 주문 입력, 확인 모달, 로딩, 튜토리얼 진행 중이 아니다.
- 아이가 직접 문제를 해결하며 화면 단계가 계속 진행되는 중이 아니다.
- 발화 쿨다운·세션 상한·신호 뮤트에 걸리지 않는다.
- 직전 개입을 거절했거나 빠르게 닫았다면 이후 발화 빈도를 높이지 않는다.

### 3.2 도움의 깊이

```text
상황을 중립적으로 언급
→ 도움이 필요한지 질문
→ 수락 시 한 단계 힌트
→ 추가 요청 시 쉬운 설명
→ 사용자가 눌러 관련 화면으로 이동
```

- **[추론]** 아이 대신 주문·매매 판단을 수행하지 않는다.
- **[추론]** “불안해 보여”, “충동적이야”처럼 감정을 진단하거나 성향을 낙인찍지 않는다.
- **[추론]** 관련 화면 이동도 버튼으로 제안하고 사용자가 눌렀을 때만 실행한다.
- **[추론]** 앱 밖 푸시보다 행동이 발생한 화면 안의 짧은 제안을 우선한다.

### 3.3 통제권과 오탐 복구

현재 F10 명세의 `직접 질문 / 괜찮아`, 신호별 뮤트, 쿨다운, 세션 상한은 유지한다.

아래는 **[가정] 연구 검증 후보**이며 도입 결정이 아니다. 채택하려면 통합문서와 F10 `SPEC.md`를 함께 갱신해야 한다.

- `왜 나타났어?`: 감지한 행동을 쉬운 말로 설명한다.
- `잘못 짚었어`: 아이가 오탐을 표시하면 “내가 잘못 짚었네”라고 인정하고 해당 신호를 세션 뮤트한다.
- `오늘 그만`: 모든 선제 발화를 남은 세션 동안 끈다.
- 선택지는 시각적 무게와 조작 단계를 비슷하게 두며 거절을 숨기지 않는다.

## 4. 현재 선제 신호 2종의 연구 관점 점검

| 신호 | 해석 [추론] | 주요 오탐 위험 | PoC 검증 우선순위 |
|---|---|---|---|
| `switch` | 확인창에서 상반된 행동을 반복하므로 사용법 혼란과 가장 가까운 신호다. | 아이가 기능을 일부러 비교하는 정상 탐색 | 현 기준을 우선 검증한다. |
| `dwell` | 시간만으로는 도움 필요성과 수용 가능성을 구분하기 어렵다. | 읽기, 보호자와 대화, 앱을 켜둔 채 이탈 | 현 5분 기준을 베이스라인으로 두고 `활동 있음 + 단계 진전 없음` 조건을 실험한다. |

`dwell`의 활동·진전 조건은 **[가정] 실험안**이다. 현재 구현 기준은 F10 `SPEC.md` §7을 따른다.

## 5. 20세션 PoC 검증안

### 5.1 방법

**[가정]** 각 신호가 발화 가능 상태가 된 시점마다 `발화`와 `미발화`를 1:1로 배정한다. 같은 아이에게도 시점별로 다시 배정하는 micro-randomized 방식으로 신호별 직후 효과를 비교한다.

- **[가정]** PoC의 분석 단위는 배정된 신호가 실제로 발화 가능한 상태가 된 1회의 `opportunity_id`다.
- **[가정]** 20세션은 아래 사전 배정표를 끝까지 수행한 유효 세션 20개를 뜻하며, 로그 유실이나 화면 렌더링 실패가 난 세션은 같은 신호·같은 배정으로 다시 수행하고 유효 세션 수에 넣지 않는다.
- **[가정]** 각 세션은 사전 준비한 모의 상태와 행동 시나리오로 배정 신호 1종의 유효 기회를 1회만 만들며, 나머지 신호의 조건은 해당 세션에서 만들지 않는다.

- 20세션 결과는 유의성 확정이 아니라 임계값 조정과 제거 후보 선별에 사용한다.
- 신호별 표본이 지나치게 적으면 수치를 확정하지 않고 추가 관찰로 남긴다.
- 테스트 참여자와 보호자에게 행동 이벤트 수집 범위, 목적, 보존 기간을 먼저 설명한다.
- 챗봇 대화 원문과 선제개입 실험 로그는 부모 리포트나 F9 성향 점수에 사용하지 않는다.

### 5.2 20세션 균형 무작위 배정표

**[가정]** 세션 ID는 실제 수행 순서이며, 신호별 10세션 블록에서 고정 시드 `poc30-v1`로 5개 ID를 복원 없이 무작위 추출해 `show`로 두고 나머지 5개를 `holdout`으로 둔다.

**[가정]** 아래 `show`·`holdout` 배정표는 실험 시작 전에 잠그고 중간 결과를 보고 바꾸지 않는다.

| 블록 | 확정 신호와 조건 | `show` 발화 세션 | `holdout` 미발화 세션 | 완료 수 |
|---|---|---|---|---:|
| 1 | **[사실]** `switch`: 매수·매도 확인창 취소가 번갈아 3회 연속 | **[가정]** S02, S05, S06, S09, S10 | **[가정]** S01, S03, S04, S07, S08 | **[가정]** 10세션(5:5) |
| 2 | **[사실]** `dwell`: 주문 또는 종목 상세 화면 5분 초과 체류 | **[가정]** S12, S13, S15, S17, S19 | **[가정]** S11, S14, S16, S18, S20 | **[가정]** 10세션(5:5) |
| 합계 | **[사실]** 확정 신호 2종을 그대로 사용 | **[가정]** 10세션 | **[가정]** 10세션 | **[가정]** 20세션(10:10) |

- **[가정]** `show`는 F10 `SPEC.md` §7의 해당 고정 발화와 `직접 질문 / 괜찮아` 카드가 실제 렌더링된 경우에만 완료로 센다.
- **[가정]** `holdout`은 같은 유효 시점에 발화·카드를 노출하지 않고 배정과 이후 120초 행동만 기록한다.
- **[사실]** 두 신호의 코드·조건·고정 발화와 발화 간 3분, 동일 신호 10분, 세션 최대 2회 제한은 F10 `SPEC.md` §7을 따르며 이 PoC가 신호 2종 자체를 변경하지 않는다.

### 5.3 최소 이벤트

```text
proactive_eligible   신호가 발화 가능한 상태가 됨
proactive_assigned   show 또는 holdout 배정
proactive_shown      실제 노출
proactive_response   ask / dismiss / mute / why / wrong
proactive_progress   노출 또는 holdout 뒤 120초 안 화면 단계 진전
proactive_repeat     10분 안 같은 막힘 행동 반복
```

이벤트에는 원문 대화나 자유 입력 내용을 넣지 않고 신호 코드, 시각, 화면, 배정, 반응만 기록한다. `why`·`wrong`은 해당 후보 UI를 켠 실험군에서만 수집한다.

**[가정]** 모든 이벤트는 `experiment_id`, `assignment_version`, `session_id`, 가명화한 `participant_id`, `opportunity_id`, `signal_code`, `arm`, `occurred_at`, `screen`, `spec_version`을 공통 키로 기록하고 `opportunity_id`로 결합한다.

| 추가 이벤트 | 기록 시점과 필드 |
|---|---|
| `proactive_mute_set` | **[가정]** 뮤트 적용 직후 `scope=signal/session`, `reason=dismiss/wrong/all_stop`, `muted_signal`, `muted_at`을 기록한다. |
| `proactive_followup` | **[가정]** 배정 후 120초 안에 도움 질문 제출, 승인된 관련 화면 열기, 화면 단계 진전이 생기면 `action_type=question_submitted/approved_screen_opened/step_progressed`, `elapsed_ms`를 기록한다. |
| `proactive_delivery_failed` | **[가정]** `show` 배정 뒤 고정 발화나 카드가 렌더링되지 않으면 `failure_stage`, `error_code`를 기록한다. |

### 5.4 측정 지표 정의표

| 지표 | 분자 | 분모 | 필요한 이벤트 로그 | 산출 규칙 |
|---|---|---|---|---|

| 거절률 | **[가정]** `proactive_response.response=dismiss`인 `opportunity_id` 수 | **[가정]** `proactive_shown`이 기록된 `show` 기회 수 | **[가정]** `proactive_shown`, `proactive_response` | **[가정]** `괜찮아` 선택만 명시적 거절로 세고 무응답·기술 실패를 거절로 바꾸지 않는다. |
| 뮤트율 | **[가정]** `proactive_mute_set`이 1회 이상 기록된 고유 `opportunity_id` 수 | **[가정]** `proactive_shown`이 기록된 `show` 기회 수 | **[가정]** `proactive_shown`, `proactive_response`, `proactive_mute_set` | **[가정]** 한 기회에서 뮤트 이벤트가 중복돼도 1건으로 세고 `signal`·`session` 범위를 별도 표기한다. |
| 후속행동률 | **[가정]** 배정 후 120초 안에 `proactive_followup`이 1회 이상 기록된 고유 `opportunity_id` 수 | **[가정]** 해당 신호·배정군의 유효 `proactive_assigned` 기회 수 | **[가정]** `proactive_assigned`, `proactive_shown`, `proactive_followup` | **[가정]** 신호별 `show` 5건과 `holdout` 5건을 따로 계산하며 한 기회의 후속행동이 여러 개여도 1건으로 센다. |

- **[사실]** 현재 F10 기본 UI에서 `괜찮아`는 해당 신호의 세션 뮤트로 이어지므로 기본 경로에서는 거절 건과 신호 뮤트 건이 겹칠 수 있다.
- **[가정]** 수락률·거절률·뮤트율은 서로 배타적인 합계 지표가 아니며 각 지표를 독립적으로 해석한다.
- **[가정]** `proactive_delivery_failed` 또는 필수 공통 키 유실이 있는 기회는 성과를 0으로 바꾸지 않고 기술 무효로 분리해 같은 배정으로 다시 수행한다.

#### 5.4.1 보조 관찰 지표

| 축 | 지표 | 해석 |
|---|---|---|
| 도움 효과 | 수락률 | 노출 후 `직접 질문`을 선택한 비율 |
| 도움 효과 | 120초 과업 회복률 | 발화군이 미발화군보다 다음 단계로 더 진행했는지 |
| 도움 효과 | 10분 내 같은 행동 재발률 | 도움 뒤 같은 막힘이 감소했는지 |
| 귀찮음 | 3초 내 닫기·`괜찮아` 비율 | 메시지가 즉시 방해로 인식됐을 가능성 |
| 귀찮음 | 뮤트·오탐 표시율 | 반복 노출 거부와 잘못된 추론 정도 |
| 안전 | 주문 시도·거래 빈도 변화 | 챗봇이 거래를 재촉하지 않았는지 |
| 정성 | 도움 필요 순간 일치율 | 관찰자 검토에서 실제 도움 필요 순간과 맞았는지 |

### 5.5 판정 기준

- **유지:** 도움 필요 순간 일치율이 통합문서 기준인 70% 이상이고, 미발화군보다 과업 회복이 좋아지며 귀찮음·거래 빈도가 악화되지 않는다.
- **임계값 조정:** 도움 가능성은 있으나 오탐·즉시 닫기가 높다.
- **[가정]** **즉시 중단:** 반복 오탐 또는 감시감이 확인되면 해당 신호의 남은 PoC 노출을 멈춘다.
- **보류:** 표본이 부족해 방향을 판단할 수 없다.

수락률 하나만으로 성공을 판단하지 않는다. 호기심으로 눌렀더라도 과업 회복이 없거나 이후 뮤트가 늘 수 있기 때문이다.

**[가정]** 아래 운영 판정은 각 신호의 유효 `show` 5건과 `holdout` 5건이 채워진 뒤 적용하며, `즉시 중단 → 신호 수정 → 신호 유지` 순서로 우선 판정한다.

| 판정 | 신호별 수치 기준 | 후속 조치 |
|---|---|---|
| 신호 유지 | **[가정]** 수락 `3/5` 이상, 거절 `2/5` 이하, 뮤트 `1/5` 이하, `show` 후속행동이 `holdout`보다 1건 이상 많고 즉시 중단 조건이 0건일 때다. | **[가정]** 현재 신호 코드·조건·고정 발화를 유지하고 더 큰 표본의 후속 검증으로 넘긴다. |
| 신호 수정 | **[가정]** 즉시 중단 조건이 없으면서 수락 `2/5` 이하, 거절 `3/5` 이상, 뮤트 `2/5~3/5`, 또는 `show` 후속행동이 `holdout` 이하 중 하나라도 해당할 때다. | **[가정]** 신호 종류는 유지하고 임계값·수용성 게이트·고정 문구·노출 시점 중 원인에 해당하는 한 요소만 바꾼 뒤 새 버전으로 재검증한다. |
| 즉시 중단 | **[가정]** 아동 불편·개인정보·안전 관련 중대 사건 `1건` 이상, 전체 선제 도움 중단 요청 `1건` 이상, 뮤트 `4/5` 이상, 또는 `wrong` 오탐 표시 `3/5` 이상 중 하나라도 해당할 때다. | **[가정]** 중대 사건이나 전체 중단 요청이면 두 신호의 남은 `show`를 모두 멈추고, 비율·오탐 기준이면 해당 신호의 남은 `show`만 멈추며 `holdout`으로 바꿔 채우지 않는다. |
| 보류 | **[가정]** 기술 무효를 제외한 유효 `show` 5건과 `holdout` 5건을 채우지 못했을 때다. | **[가정]** 비율을 확정값으로 보고하지 않고 같은 사전 배정 규칙으로 부족한 셀만 추가 관찰한다. |

- **[가정]** `3/5(60%)`처럼 분자·분모와 비율을 함께 보고하고 퍼센트만으로 판정하지 않는다.
- **[가정]** 20세션 결과는 통계적 유의성, 일반화 가능성, 최종 제품 효과를 결론 내리는 자료가 아니라 다음 실험 방향을 고르는 PoC 신호로만 사용한다.
- **[사실]** F10 `SPEC.md` §7의 확정 선제 신호는 `switch`, `dwell` 2종이며 위의 수정·중단 판정도 신호 2종 자체를 추가·교체·삭제하는 제품 결정을 뜻하지 않는다.

### 5.6 오탐 정정 경로

**[가정]** 아래 경로는 20세션 PoC에서 오탐 복구 수용성을 확인하기 위한 연구 검증안이며, 제품 채택 전에는 통합문서와 F10 `SPEC.md`를 함께 갱신한다.

| 사용자 상태·입력 | 시스템의 즉시 반응 | 사용자에게 보이는 확인 | 로그와 상태 변경 | 이후 동작 |
|---|---|---|---|---|
| `괜찮아` 선택 | **[사실]** 해당 신호를 현재 세션 동안 뮤트한다. | **[가정]** “알겠어. 이번에는 먼저 말하지 않을게.”를 고정 문구로 보여주고 카드를 닫는다. | **[가정]** `proactive_response(response=dismiss)`와 `proactive_mute_set(scope=signal, reason=dismiss)`을 같은 `opportunity_id`로 기록한다. | **[가정]** 같은 신호의 대기 중 발화를 취소하고 사용자가 직접 키웅이를 여는 경로는 유지한다. |
| `잘못 짚었어` 선택 | **[가정]** 오탐을 인정하고 해당 신호를 현재 세션 동안 뮤트한다. | **[가정]** “내가 잘못 짚었네. 이 도움은 이번 세션에서 그만할게.”를 고정 문구로 보여준다. | **[가정]** `proactive_response(response=wrong)`과 `proactive_mute_set(scope=signal, reason=wrong)`을 기록한다. | **[가정]** 해당 건을 오탐 1건으로 판정 집계하고 같은 신호를 재노출하지 않는다. |
| `오늘 그만` 선택 | **[가정]** 현재 세션의 두 신호를 모두 뮤트한다. | **[가정]** “알겠어. 이번 세션에는 내가 먼저 말하지 않을게.”를 고정 문구로 보여준다. | **[가정]** `proactive_mute_set(scope=session, reason=all_stop)`을 신호별 상태와 함께 기록한다. | **[가정]** 남은 세션 동안 선제 발화만 중단하고 사용자가 직접 키웅이를 여는 경로는 유지한다. |
| 뮤트 직후 대기 중 발화가 발견됨 | **[가정]** 화면 표시 전에 발화를 폐기한다. | **[가정]** 추가 확인이나 재질문을 보여주지 않는다. | **[가정]** 폐기한 `opportunity_id`와 적용된 뮤트 범위를 진단 로그에 기록한다. | **[가정]** 배정을 다른 신호나 다른 세션으로 넘기지 않는다. |
| 뮤트 상태 기록 실패 | **[가정]** 안전 우선으로 현재 세션의 모든 선제 발화를 메모리 상태에서 중단한다. | **[가정]** “지금은 먼저 도움을 띄우지 않을게.”를 고정 문구로 한 번만 보여준다. | **[가정]** 오류 코드와 세션 ID만 기록하고 대화 원문은 기록하지 않는다. | **[가정]** 원인 확인 전 해당 세션의 선제 발화를 재시도하지 않는다. |

- **[사실]** F10 `SPEC.md` §7에 따라 30분 무활동 뒤에는 새 세션으로 보며 기존 신호 뮤트가 초기화된다.
- **[가정]** 정정 경로에서는 “정말 도움이 필요 없니?” 같은 재확인 질문을 하지 않고 거절을 한 번의 선택으로 완료한다.
- **[가정]** 오탐 표시와 뮤트 로그는 부모 리포트나 F9 성향 점수로 전달하지 않는다.

## 7. 조사 한계

- 검색 범위 안에서 **한국 자녀 + 모의투자 + 선제형 AI 챗봇**을 직접 검증한 연구는 확인하지 못했다. “연구가 없다”는 부재 증명이 아니라 이번 조사에서의 미발견이다.

- 2026년 아동 연구는 사전논문이며 금융 의사결정 과제가 아니다.
- ICO 문서는 제품 설계 참고자료이며 한국 법률 검토를 대체하지 않는다.
- 따라서 현재 임계값은 계속 **[가정]**으로 두고 자녀 테스트 결과로 조정한다.
