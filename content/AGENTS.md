# content — 편집 콘텐츠 세션 하네스

> 적용 범위: `content/` 하위 전체 (`dex/` 도감 MDX · `news/` 아이 눈높이 뉴스 MDX).
> 규칙 본문은 이 파일에만 쓴다. 같은 폴더 `CLAUDE.md`는 `@AGENTS.md` 한 줄이다 (루트 `AGENTS.md` §동기화).
> 최종 갱신: 2026-08-06

## 담당 오너

**김경렬·강소정** (트랙 ③). 렌더링 화면은 `web/app/(child)/{news,dex}`이고 그 규약은 `web/AGENTS.md`를 따른다.

## 세션 시작 규칙

1. 루트 `AGENTS.md` → `content/README.md`(디렉터리 정의) → 이 파일 순서로 읽는다.
2. 루트 `C:\dev\six-opening`에서 고치지 않는다. `git_session_manager.py start`로 워크트리를 받아 거기서 작업한다.
3. 생성 경로는 `pipelines/news_digest`가 소유한다. 파이프라인 코드를 같은 세션에서 고치지 않는다 — claim을 나눈다.

## 불변식

- **자동 발행 금지.** 아이에게 보이는 텍스트는 예외 없이 사람 검수를 거쳐 커밋된다. AI가 쓴 초안을 검수 없이 `content/`에 넣지 않는다. 검수를 건너뛸 수 있는 경로 자체를 만들지 않는다.
- **뉴스 원문을 크롤링·전재하지 않는다.** 이슈를 재작성한 결과물만 둔다. 원문 링크와 출처는 남긴다.
- **앱이 종목을 추천하지 않는다.** 도감·뉴스 문구가 특정 종목 매수를 권하는 형태가 되면 안 된다 (투자권유 규제).
- 금지 표현: **수익 보장 · 확정 수익 · 원금 보장 · 무조건 오른다 · 매수 권유**. 불확실성은 불확실하게 쓴다.
- 10~16세 눈높이. 용어를 쓰면 그 자리에서 한 줄로 푼다.
- **게임 데이터를 여기 두지 않는다.** 종목·이벤트·게임 뉴스 풀은 `game/data/`다 — 룰 엔진이 읽고 밸런스 시뮬 대상이기 때문이다. 트랙 ③이 게임 뉴스·사건 문구를 공급할 때는 `game/data`를 **별도 세션으로 claim**하고 트랙 ① 승인으로 머지한다 (`game/AGENTS.md`).
- CMS를 도입하지 않는다. Git이 버전관리·리뷰·롤백이다 (`content/README.md`).

## 검증 명령

아직 MDX가 없다. 첫 문서를 추가하는 세션이 렌더 확인 경로를 이 절에 채운다.

```powershell
npm run build -w web   # MDX가 붙은 뒤: 발행 문서가 빌드에서 깨지지 않는지
rg -n "수익.*보장|원금.*보장|확정 수익|무조건|매수하세요" .
```
